## 관찰 (탐색 수준)

1. **GPT-4o 회계 공식이 실측과 정확히 맞았다.** 144회 모두에서 "실측 prompt tokens − 타일 공식 예측(85+170N)"이
   질문마다 하나의 상수였다. A·B의 치수 6종(2048×1536, 1536×1152, 1024×768 등)과 E의 crop 치수 전부에서 이미지 토큰이 공식과 같다는 뜻이다.
   저장소 회계 문서(`docs/research/image-token-cost-models.md`)의 산술 예제를 처음으로 실제 청구 토큰으로 확인했다.
2. **긴 변 1536 downscale과 1024 stress는 GPT-4o 토큰을 전혀 줄이지 않았다.** 2048×1536, 1536×1152, 1024×768 모두 provider가
   짧은 변 768로 맞춘 뒤 4 tile(765 토큰)이 된다. A와 B의 토큰이 모든 조건에서 같다. 파일 bytes는 B가 A보다 17–33% 작았지만(clean, JPEG-only, downscale-only)
   토큰은 0% 줄었다. combined에서는 q75 재인코딩 때문에 B가 A보다 bytes가 오히려 14% 컸다.
3. **토큰을 줄인 것은 crop(E)뿐이다.** oracle crop은 이미지 토큰을 56–65% 줄였다(765 → 340 또는 269). 다만 oracle이라
   근거 영역을 미리 아는 상한값이다. 실제 selector(C·D)가 이만큼 줄이면서 근거를 놓치지 않는지는 측정하지 않았다.
4. **틀린 내용 6건은 모두 작은 글자 질문이고, 6건 모두 1024로 줄인 조건(downscale-only, combined)에서 나왔다.**
   빌드 번호(16px), 메모 각주 코드(17px), 알림 배지 숫자(16px)다. 같은 해상도의 variant에서 crop한 E도 복구하지
   못했다. provider가 확대하지 않으므로 이미 잃은 pixel은 crop으로 되돌아오지 않는다. downscale-only의 메모 각주는
   A가 맞히고 E(310×57 crop)가 틀렸다. 아주 작은 crop이 전체 이미지보다 불리할 수 있다는 신호지만 1건이다. 일반 글자 질문은 모든 셀에서 내용 100%였다.
5. **clean과 JPEG-only(q50, 원래 해상도)에서는 모든 arm이 내용 100%였다.** 이 합성 세트는 원래 해상도에서 너무 쉽다.
   arm 간 차이를 보려면 작은 글자와 밀집 레이아웃 stratum을 늘려야 한다.
6. **형식 위반 4건.** 모델이 지시와 달리 앞에 라벨을 붙였다. 엄격 채점은 형식 준수까지 함께 재므로, 본 실험의 채점 규칙에
   이 경우를 어떻게 다룰지 미리 정해야 한다.

## 연구 방향에 주는 함의 (제안)

- GPT-4o high에서 2048 이하 4:3 이미지의 client-side resize·JPEG는 청구 토큰에 영향이 없다. 이 공급자에서 비용 절감은
  영역 선택(crop)에서만 나온다. 논문의 기여는 "질의 인식 영역 선택 + 작은 글자 guard"에 집중하는 편이 맞다.
- 공급자마다 회계식이 다르므로(저장소 문서: Anthropic은 pixel 비례 patch 회계), 같은 변환이 공급자별로 다른 절감을 낸다.
  "공급자별 이미지 토큰 회계 × 정확도"를 실측으로 비교하는 것이 논문의 측정 기여가 될 수 있다. 다음 파일럿에 두 번째
  공급자를 추가할지는 사용자 결정이다.
- 작은 글자가 손상되는 지점(1024 stress)이 guard가 지켜야 할 대상임을 처음으로 실제 오답으로 확인했다.
