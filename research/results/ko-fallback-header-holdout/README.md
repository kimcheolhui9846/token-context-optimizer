# 질문한 열의 머리글을 원본에서 보완한 결과

새 한국어 합성 표 18개 중 기존 표시가 행 이름과 두 값은 온전히 남기면서 두 열 제목을 모두 잘라낸 표는 3개였다. 세 표 모두 원본의 머리글 띠를 붙여 두 제목을 원래 열 위에 복원했다. 세 질문 모두 시각을 물었다. 인원·분량 표에서 같은 상황은 관측되지 않았다.

**사전등록 판정은 미확정이다.** 다른 기록의 값에 새로 보인 글자 픽셀은 18표 전체에서 0개였다. 다른 기록을 두 제목 사이에 넣은 6표에서는 표시 규칙이 한 번도 작동하지 않았다. 따라서 규칙이 실제로 작동하는 상황에서 다른 기록을 가릴 수 있는지는 알 수 없다. 이 실험은 사람이 열을 올바르게 읽는지 측정하지 않았다.

| 질문 종류 | 새 표 | 복원 기회 | 두 제목 복원 | 별관 기록이 있는 표 | 별관 있는 표에 띠 적용 |
|---|---:|---:|---:|---:|---:|
| 시각 | 6 | 3 | 3 | 2 | 0 |
| 인원 | 6 | 0 | 0 | 2 | 0 |
| 분량 | 6 | 0 | 0 | 2 | 0 |
| 전체 | 18 | 3 | 3 | 6 | 0 |

## 원본과 표시 비교

- **1번, 장구 가죽 손질의 접수 시각.** 기존 화면에는 두 시각이 있지만 어느 쪽이 접수 시각인지 표시되지 않았다. 새 화면은 행 이름과 시각 두 개를 그대로 두고 두 열 이름을 복원했다. [원본](set/render/images/q4e547a01.png) · [기존 W5](build/w5/q4e547a01.png) · [보완 W6](w6/q4e547a01.png)
- **3번, 다육 화분 점적의 시작 시각.** 기존 화면에 두 제목은 있지만 질문한 행의 이름과 두 값은 없다. 별관 값이 제목 사이에 있고 자격을 충족하는 OCR 머리글은 없었다. 규칙은 기존 화면을 유지했고 이 표는 복원 기회에서 제외됐다. [원본](set/render/images/qbf6987c5.png) · [기존 W5](build/w5/qbf6987c5.png) · [보완 W6](w6/qbf6987c5.png)

복원된 나머지 표는 2번 유약 시험편 소성의 [점화 시각](w6/q2acfaa75.png)과 4번 유성우 개수 기록의 [개시 시각](w6/q083bb210.png)이다. 세 표에 각각 높이 36픽셀의 원본 띠와 8픽셀의 구분선이 더해졌다. 원본 페이지 면적 대비 표시 면적 증가는 적용 표 평균 **4.58%p**, 전체 평균 **0.76%p**였다.

## 적용되지 않은 15표

| 이유 | 표 수 | 관측 내용 |
|---|---:|---|
| 기존 표시가 단일 W1 조각으로 돌아간 경우가 아님 | 6 | 인원 3표와 분량 3표는 기존 두 조각을 보존했다. |
| 자격을 충족하는 유일한 OCR 머리글 없음 | 6 | 별관 기록이 있는 6표 모두에 해당한다. 원본 숫자의 잉크는 6표 모두 W1의 수평 범위에 있었다. |
| 질문에 적힌 열 이름이 좌우 제목 중 정확히 하나와 일치하지 않음 | 3 | 열을 임의로 선택하지 않고 기존 화면을 유지했다. |

정상 제목은 12표, 질문한 제목이 중복되거나 누락된 음성 대조는 각각 3표였다. 음성 대조에 띠를 적용한 건수와 기존에 완전히 표시되던 단서를 잃은 건수는 모두 0이었다. 18표 모두 비교 이미지가 있으며, 미적용 15표의 W5·W6 PNG는 바이트 단위로 같다. 다른 행 양쪽의 값과 별관 값을 전부 확인했으며, 원래 일부 보이던 값이 더 드러난 경우도 새 노출에 포함했다.

## 실제로 시험된 안전 조건

별관 6표 중 5표에서는 기존 화면부터 별관 숫자 전체가 보였다. 5번만 기존 화면에서 별관 숫자가 가려져 있었고, 이 표에서는 머리글 행이 OCR 자격을 얻지 못했다. 3번의 상위 단계는 질문한 행 대신 별관 쪽을 선택했다. 음성 대조 중 기존 W1에 양쪽 제목의 글자가 모두 없던 경우는 5번과 6번이며, 이 중 질문 필드 비교에 도달한 것은 6번뿐이었다. 복원된 3표는 모두 동일한 세로 위치의 띠를 사용했다.

별관 이름 셀은 6표 모두 가로 구분선과 겹쳤다. 독립 검토에서 셀의 잉크 중 구분선 170픽셀을 제외한 수가 렌더러의 글자 상자 계수와 같았다. 이 겹침은 이번 숫자 노출 지표에 영향을 주지 않았다. 독립 검토자는 글자 상자 대신 셀과 구분선을 사용해서도 각 단서의 잉크 수를 확인했다.

## 자료와 재현

규칙 작성자와 합성 문구 작성자를 나눴다. 실험 코드·자료·판정 기준은 첫 렌더링 전에 `59b3c6b18459f220cb2ab479358eb0416ae12348`에서 고정했다. 최초 실행은 Windows 경로 처리 문제로 OCR을 시작하기 전에 중단됐다. 첫 렌더 결과는 측정에 쓰지 않고 새 디렉터리에서 다시 시작했다. 실행기 경로 표기와 잠금 검사를 수정한 `0fc0cb55b94e10feb67a0f2d6e4d129275888e57`로 다시 실행했고 그 사이 코퍼스·선택·채점 규칙은 그대로였다. 두 번의 독립 실행에서 공개한 JSON·JSONL·PNG 106개가 바이트 단위로 일치했다. [사전등록](../../plans/2026-11-26-ko-fallback-header-holdout.md) · [18표 개별 측정값](measures.json) · [OCR 네트워크 차단 기록](ocr/guard-summary.json)

저장소 루트에서 Python과 Pillow로 공개 결과를 다시 계산할 수 있다. 검산기는 표시 이미지를 원본과 좌표에서 재조립하고, 주 채점기와 별개로 단서와 다른 기록의 픽셀을 센다. 두 채점기는 렌더러에서 얻은 같은 글자 위치를 쓴다. 질문 유형·행·좌우 배치는 고정되어 있으며 동일한 양식군을 사용했다. 따라서 세 복원 사례로 다른 양식·질문 유형의 복원율을 추정할 수 없다.

```sh
python -B research/tools/ko-fallback-header/recount.py research/results/ko-fallback-header-holdout
python -B -m unittest discover -s research/experiments/ko-fallback-header-holdout -p "test_*.py"
```

OCR까지 재실행하려면 등록한 Node 연구 의존성, 한글 글꼴, 로컬 언어 파일, Git 원본 커밋을 준비한다. 아래 명령의 출력 경로는 존재하지 않는 새 디렉터리여야 한다. [입력 파일 및 버전 목록](../../tools/ko-blind-reader/registered.json)

