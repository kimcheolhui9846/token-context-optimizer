## 8. 해석 (프로토콜 5.1 기준)

- **L = 6/48 > 0.** 이 자료에서 W2는 "기존 성공을 잃지 않는다"는 조건을 충족하지 못했다. 6쪽 모두 정답 값이 W2 밖으로 나갔고(값만 6, 표지만 0, 둘 다 0) 모두 `vert below` 배치다. 원본은 `venue-table-c1`, `proof-cards-c1`, `workshop-table-c0` 3개이고 각 원본의 narrow·wide 두 쪽이다. `vert same` 24쪽의 L은 0/24다.
- 손실 쪽의 기하: K1 적중 단어는 표지 줄에 있고 W2 아래 끝은 `ceil(적중 아래 + 적중 높이 중앙값)`이다. 6쪽 모두 값 잉크가 W2와 일부만 겹친다(부분 노출). 값 잉크 아래 끝은 W2 아래 끝보다 17px 아래에 있다. 표지 잉크는 6쪽 모두 W2 안에 완전히 들어 있다. 등록 때 위험으로 적어 둔 "아래 배치에서 값이 잘릴 수 있음"이 실제로 일어났다. 이 결과는 규칙·여백을 바꾸지 않고 그대로 보고한다. 좌표는 y픽셀, 아래 끝은 배타적이다(`predictions.jsonl`의 `w2`, `gold.json`의 상자).

- **J = 21/27, 원본 11개.** W1과 W2 모두 엄격 성공을 유지한 쪽에서, W1에서 완전히 보이던 다른 기록 값 중 하나 이상이 W2에서 전혀 보이지 않게 된 관찰이 21쪽 있다. 21쪽 모두 `vert same`이다. `vert below`에서는 0/5이고 기회 5쪽이 모두 손실 쪽이다. 프로토콜대로 두 현상을 함께 적는다. 판정은 L = 6/48 손실이 우선한다. J는 손실과 함께 있던 관찰로만 적는다.

## 9. 독립 검산의 범위와 작성자

- `tools/ko-row-height/recount.py`(Python 표준 라이브러리만)가 원시 OCR·렌더·질문에서 다음을 다시 계산해 기록과 대조한다: K0·K1, W1, W2, 판정, 노출, 집계, 짝, 공개 표 칸.
- 같은 저자(Claude Code 세션)가 JS 구현과 같은 작업 중에 썼다. PNG 해독, K0/K1, W1 부분은 #150 검산기를 옮긴 것이다. W2, 노출, 채점, 집계, 짝, 표 부분은 이번에 새로 썼다. 따라서 명세 해석의 공통 오류까지 막지는 못한다. 독립성은 "다른 언어·다른 코드 경로"까지다.
- 변조 시험(`recount/mutation.json`)은 다음 변조를 넣어 모두 거부되는지 확인한다: 주변합을 보존하는 t12·절감 픽셀 교환, 일부↔전혀 교환, 노출 분류 변경, 예측 W2 1px 이동, ID 중복·누락, 정답 상자 1px 이동, K1 적중 변조, 공개 표 칸 변조.
