# 두 제목 창이 머리글 옆 숫자를 가리는가

표시 위치를 고정하면 효과가 있었다. 숫자를 제목과 같은 높이에 놓은 **6개 변형 모두**에서 전체 폭 띠는 별관 숫자를 온전히 보여줬고, 두 제목 창은 숫자 잉크를 모두 가리면서 열 제목·행 이름·두 값을 보존했다. 그러나 새 원본마다 OCR을 다시 실행하면 이 6개에서는 어느 쪽도 띠를 붙이지 않았다. 실제 선택기가 작동하는 유효 위험 사례는 0개였다. **두 분석 모두 사전등록 판정은 미확정이다.**

독립 원본은 #158에서 복원이 관측된 시각 질문 3개다. 각 원본에 무변경 대조 1장과 별관 숫자 위치를 바꾼 변형 4장을 만들었다. 원본 3개, 대조 포함 총 15장으로, 아래 표의 두 분석은 같은 자료를 사용한다.

| 조건 | 장수 | 실제 OCR 띠 적용 | 실제 전체 폭 → 두 창에서 새로 보인 별관 잉크 | 위치 고정 전체 폭 → 두 창 |
|---|---:|---:|---|---|
| 무변경 대조 | 3 | 3 | 별관 기록 없음 | 세 대조 모두 #158의 W5·전체 띠 픽셀 재현 |
| 제목과 같은 높이 | 6 | 0 | 기존 화면 유지, 새 잉크 0 | 6장 모두 숫자 전체 → 0픽셀 |
| 아래로 18px | 6 | 2 | 두 장 각각 143 → 0픽셀 | 6장 모두 일부 → 0픽셀 |

마지막 6장에서는 새 숫자의 일부가 기존 가로 구분선과 겹쳤다. 원본별로 겹친 글자 픽셀은 26·34·36개였다. 실제 OCR이 띠를 적용한 두 장은 모두 같은 원본(유약 시험편 소성)의 배치다. 숫자 전체 잉크 277픽셀 중 보인 143픽셀을 두 창이 모두 가렸지만, 동결한 규칙에 따라 이 두 장도 유효 위험 사례에서 제외했다. 모든 변형을 분모와 공개 자료에 보존했다.

| 독립 원본 | 같은 높이에 놓은 별관 값 | 실제 OCR 적용 변형 / 4 | 같은 높이 두 위치의 고정 전체 폭 → 두 창 |
|---|---:|---:|---|
| 장구 가죽 손질 | 87 | 0/4 | 각각 226 → 0픽셀 |
| 유약 시험편 소성 | 89 | 2/4 | 각각 277 → 0픽셀 |
| 유성우 개수 기록 | 91 | 0/4 | 각각 207 → 0픽셀 |

예를 들어 새 숫자 89가 ‘개방 시각’과 ‘점화 시각’ 사이에 있다. 같은 좌표에서 두 제목을 따로 복사하면 숫자가 사라지고 두 제목은 원래 열 위에 남는다. 실제 OCR에서는 이 표의 머리글 행이 자격 조건을 충족하지 못했다. [원본](set/render/images/q5fb8ec7e.png) · [기존 W5](displays/natural/q5fb8ec7e/w5.png) · [위치 고정 전체 폭](displays/fixed/q5fb8ec7e/full.png) · [위치 고정 두 창](displays/fixed/q5fb8ec7e/two.png)

전체 15장에서 두 창 방식 때문에 완전하던 대상 단서를 잃거나 다른 행·별관의 수치가 추가로 드러난 경우는 관측되지 않았다. 두 창은 제목의 가로 위치와 읽을 본문을 그대로 유지한다. 실제 OCR의 판독 능력, 사람의 정확도, 다양한 양식에서의 안전성은 이 측정으로 일반화할 수 없다. [15장 개별 측정](results.json) · [사전등록](../../plans/2026-11-26-ko-header-window-safety.md)

## 재현과 검산

두 번의 별도 로컬 CPU 실행에서 공개 데이터 148개(1,499,519바이트)가 바이트 단위로 같았다. 실험 코드·기준은 `f33521251185e6ddc6d5c919e869e8cd6ceb8cac`에서 원격에 먼저 고정했다. 첫 실행은 기존 입력기의 ‘18개 필수’ 검사에서 OCR 전에 중단됐다. `b18b337`에 고정한 실행 어댑터는 원본 JS 해시를 확인한 뒤 이 길이 검사 한 곳만 15로 바꾼다. 처음 출판한 실험 코드·좌표·판정 기준을 그대로 사용했다.

저장소 루트에서 Python과 Pillow로 모든 원본·좌표와 30세트의 W5/전체 폭/두 창 이미지를 재검산한다. 아래 두 번째 명령은 합성 구현 시험 32개를 실행한다.

```sh
python -B research/tools/ko-header-window/verify_result.py research/results/ko-header-window-safety
python -B -m unittest discover -s research/experiments/ko-header-window-safety -p "test_*.py"
```

전체 OCR 재실행에는 [고정 입력 목록](../../tools/ko-blind-reader/registered.json)의 글꼴, 언어 파일, 기존 커밋과 연구 의존성이 필요하다. 원본·변형은 모두 공개 합성 자료다. 출력은 새 디렉터리에 만든다.

```sh
git fetch origin pull/147/head pull/150/head pull/151/head pull/152/head pull/153/head pull/154/head
npm --prefix research ci --ignore-scripts
python -B research/tools/ko-header-window/replay.py --lock f33521251185e6ddc6d5c919e869e8cd6ceb8cac --font "C:/Windows/Fonts/NotoSansKR-VF.ttf" --out .artifacts/header-window-fresh
```
