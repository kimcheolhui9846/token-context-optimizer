이 실행 뒤 하네스 설계를 동결하고 held-out을 사전 등록한다. 조건당 문항 48개다.

- 실행 중 OpenAI 크레딧 소진과 조직 월 한도로 두 번 멈췄다. 같은 설정으로 이어 실행했다. 끊긴 시도의 호출은 시도 ID로 집계에서 뺐다(`resumes.jsonl`).
- 비용(S2·S3 새 호출) 약 $2.00. 채점은 2026-10-15 수정 규칙이다(on/off·yes/no 문장 답 허용).

## s3-cal-001 대비 변화 (S2, 같은 채점 규칙)

- 정확도 79% → 85%, 늦은 회상 67% → 89%. "가장 높은 막대" 같은 전체 이미지 질문의 조용한 오답이 사라졌다(썸네일 효과).
- 입력 토큰은 19,492 → 22,618로 늘었다. 썸네일과 일괄 비우기 사이에 쌓이는 이미지 때문이다. 정가 기준 절감은 −43% → −33%다.
- 캐시 기준 절감은 −15% → −12%로 거의 같았다. 일괄 비우기로 캐시 토큰은 3,840 → 8,469로 늘었지만, 쌓인 이미지가 그만큼을 상쇄했다.

## 동결 시점의 남은 약점 (held-out에서 그대로 보고)

1. **13px 작은 글자 오독.** 청구서 번호의 숫자를 바꿔 읽는 경우(INV-55785 → 65785)는 S0에서도 나온다. 메모 각주 코드는 crop·원본 모두 판독 불가였다.
2. **세는 질문(요지).** "로그에서 legend가 나오는 줄 수" 같은 문항은 텍스트 발췌 도구가 일부 줄만 돌려주므로 플러그인 조건이 틀린다(67%). 전체를 봐야 답할 수 있는 질문은 발췌 방식의 구조적 한계다.
3. **캐시를 고려한 절감은 작다.** 정가 기준 −33~38%가 캐시 기준으로는 −8~12%다. 도구 왕복으로 호출 수가 2배가 되는 것도 원인이다.

## 동결한 설계

| 항목 | 값 |
|---|---|
| 모델 | `gpt-4o-2024-11-20`, detail high, temperature 0, max_tokens 60 |
| compact | S1·S3, 턴 3·6 뒤 고정 일정. 임계값 4,000 초과 턴 수는 보조 지표 |
| 플러그인 도구 | `query_text_artifact`(실제 플러그인 MCP `query_artifact`), `query_image_artifact`(C1 창 selector + 썸네일), `get_original_image` |
| 플러그인 규칙 | 턴당 도구 왕복 3회, UNREADABLE이면 원본 자동 재요청, 도구 결과 이미지는 턴 3·6 뒤 일괄 비우기 |
| 채점 | 내용 일치. yes/no·on/off는 해당 단어가 있고 반대 단어가 없으면 맞음. 숫자 단독 일치, 월 약어 허용 |

이 설계는 `research/src/session-harness.mjs`와 `session-summarize.mjs`의 현재 상태다. held-out 실행 전에 커밋하고 그 커밋을 사전 등록 문서에 적는다.
