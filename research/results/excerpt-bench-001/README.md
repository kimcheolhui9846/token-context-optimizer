# 텍스트 발췌 재현 벤치 (excerpt-bench-001)

- 실행: 2026-10-16, Claude Code. 명령은 `node src/excerpt-bench.mjs`. 모델 호출 없음, 비용 0
- 대상
  - 실험 3 세션의 로그 문항 중 근거 줄이 하나로 정해진 것. gist 문항은 제외했다.
  - 세션마다 3문항: 즉시 로그, 교차, 늦은 로그
  - 분할: held-out 24세션(72문항), calibration 6세션(18문항), 개발 3세션(9문항)
- 도구: 실제 플러그인 번들의 `query_artifact`(MCP stdio). maxTokens 400, contextLines 1이고, 실험 3 하네스와 같다.
- 질의 규칙(모델이 아니라 고정 규칙으로 만든다)

| 규칙 | 내용 |
|---|---|
| `full` | 질문 문장 전체 |
| `keywords` | 질문에서 짧은 영어 불용어를 뺀 단어들 |
| `entity` | 질문에서 숫자가 든 단어만(송장 번호, 노드 이름, 오류 코드 등). 숫자 단어가 없는 문항은 해당 없음 |

- 판정
  - 발췌 구간이 근거 줄을 덮고, 정답 문자열이 발췌 안에 있으면 성공이다.
  - 교차 문항은 정답을 이미지에서 읽으므로 근거 줄을 덮기만 하면 성공이다.
- 동점 진단
  - 플러그인 점수 방식(질의 단어 포함 수)을 복제해, 최고점 줄이 몇 개인지 셌다.
  - 복제본의 첫 최고점 줄은 모든 경우 플러그인이 돌려준 구간 안에 있었다(불일치 0).
- 원자료: `rows.jsonl`(질의별), `summary.json`, `table.md`(분할 × 규칙 × 문항 유형)

## 결과

| 분할 | full | keywords | entity |
|---|---|---|---|
| held-out | 72/72 | 72/72 | **20/24**(동점 8, 동점 때문에 근거 줄 놓침 4) |
| calibration | 18/18 | 18/18 | 5/6(동점 2, 놓침 1) |
| 개발 | 9/9 | 9/9 | 2/3(동점 1, 놓침 1) |

- 응답의 발췌 수는 모든 경우 1개였다.
- 질문 문장이나 키워드로 질의하면 근거 줄이 항상 유일한 최고점이었다. 놓친 경우가 없다.
- **실패는 entity 질의에서만 생긴다.**
  - 문서 검토 세션의 "posted invoice" 문항에서, 송장 번호가 FLAG 줄과 posted 줄 두 곳에 있다.
  - 송장 번호만으로 질의하면 두 줄이 동점이 된다. 플러그인은 앞쪽 줄 하나만 돌려준다.
  - FLAG 줄이 앞에 있는 세션에서는 근거 줄을 놓친다.
  - held-out에서 놓친 세션: document-review-1, 2, 4, 8-v2

## held-out 실제 오답과 대조

| 공급자·조건 | 로그 즉시 문항 오답 | 벤치가 놓친 세션 4개 안에 있는가 |
|---|---|---|
| GPT-4o S2 | 2건(document-review-1, 4) | 2/2 |
| GPT-4o S3 | 4건(document-review-1, 2, 4, 8-v2) | 4/4 |
| Haiku S2 | 2건(document-review-4, 8-v2) | 2/2 |
| Haiku S3 | 2건(document-review-4, 8-v2) | 2/2 |

- **플러그인 조건의 로그 즉시 문항 오답 10건이 모두 이 벤치가 짚은 세션 4개 안에 있다. 그 밖의 세션에서는 오답이 없다.**
- 모델이 실제로 보낸 질의는 기록되지 않았다. 입증된 것은 **세션 단위의 일치**다. 오답 10건이 모두 entity 질의가 실패하는 4세션에 속한다. 동점 발췌가 오답의 원인이라는 것은 이 일치와 맞는 설명(가설)이지 확정이 아니다(PR #35 검토 M-1).
- 반대로, 모델이 같은 세션에서도 맞힌 경우가 있다. 모델이 질문 문장에 가까운 질의를 보낸 경우로 보인다(추정).
