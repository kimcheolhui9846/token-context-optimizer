## 4. 해석

- 이 자료에서 관측한 2px 손실은 대칭 여백 4px로 복구되었고, 매치 행의 평균 전달 면적은 페이지의 0.85퍼센트포인트 늘었다. 8px·16px도 포함 결과는 같았고 면적만 더 늘었다
- 이것은 이미 알려진 한 사례의 재생이다. 다른 문서·다른 선택기·다른 글꼴에서 같은 여백이 충분하거나 필요하다는 근거가 아니다. 판독성·정답률은 재지 않았다
- 제품 기본 여백은 정하지 않는다. 기본값 논의에는 새 자료의 사전 등록 평가가 필요하다

## 6. 실행 코드 상태 증거 (PM 검토 Major 1)

- 원래 A·B의 `run-meta.json`(`runnerCommit 613e20c`)에 있는 `runnerTreeClean: true`는 **실행 당시 코드 상태의 증거가 아니다.** 실행기가 `research/src`에서 `git status --porcelain -- src`를 실행해 존재하지 않는 `research/src/src`를 검사했다. 실제 임시 Git 저장소에서 추적 파일을 바꿔도 이 명령은 빈 문자열을 돌려줌을 테스트로 재현했다(`d1a4cb8`). 또 측정이 끝난 뒤 검사했다. 원래 기록은 그대로 보존한다
- 수정(`960b451`): 실행기는 입력을 읽거나 서버를 띄우기 전에, 자신이 실제로 불러오는 모듈 5개(`research/src/{crop-padding-replay-run,crop-padding-replay-lib,crop-padding-replay-client,mcp-view-comparison-lib,mcp-view-comparison-client}.mjs`)마다 HEAD blob·작업 사본 blob(`git hash-object`)·`git status --porcelain`을 기록하고, 하나라도 추적되지 않았거나 다르면 측정을 시작하지 않는다. 검사 범위는 이 5개뿐이다(번들·동결 라이브러리 blob은 따로 확인한다. 오프라인 가드 스크립트·`node_modules`는 대상이 아니고, 모듈을 불러온 직후에 검사한다). 줄바꿈만 다시 쓴 파일은 `status`가 수정으로 보고해 측정을 거부한다(보수적 동작). `run-meta.json`의 `runCodeCheckedBeforeMeasurement`에 있다. 수정 전 코드로 바뀐 작업 사본에서 실행하면 실제로 거부됨을 확인했다
- 수정 코드 재실행(`rerun-pmfix/`, 코드 `960b451`, 두 실행 모두 `clean: true`): 새로 만든 준비 리포트, A·B의 결정적 출력 3개, 증거(evidence.json), 채점 2개, 검산 결과가 원래 커밋된 파일과 모두 바이트 동일했다(`rerun-pmfix/comparison.json`). 가드 5, 차단 0
- 따라서 원래 측정값은 **수정된 코드로 같은 바이트가 재현된다**는 근거가 있다. 원래 실행 시점에 코드가 바뀌지 않았다는 직접 증거는 원래 플래그로는 없다. 원래 사전등록(`c636f69`)과 실측 날짜(2026-11-24, `5f40f1a`)는 바꾸지 않는다
