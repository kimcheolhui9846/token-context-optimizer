RQ1(공급자별 청구 토큰)을 위해 [pilot-003](../pilot-003/README.md)과 같은 dev3 slot을 Anthropic 모델로 실행한 결과다.
개발용 탐색 실행이며 calibration·held-out이 아니다.

- 모델 `claude-haiku-4-5-20251001`(고정 snapshot, 공식 SDK `@anthropic-ai/sdk` 0.131.0), temperature 0, max_tokens 40.
  이미지 블록을 텍스트 앞에 둔다. 지시문은 pilot-003과 같다.
- arm A, C1, E 각 144회, 합계 432회, 실패 0회. 비용 $0.3164(usage × 정가 $1/$5 per MTok).
- C2(OpenAI detail low 위치 찾기)는 OpenAI 전용이라 실행하지 않았다. C1R은 pilot-003과 같은 규칙으로 파생했다(C1이 UNREADABLE이면 같은 slot의 A 응답 사용).

## 회계식 일치

질문 36개 모두에서 "실측 input tokens − 예측 이미지 토큰"이 질문마다 하나의 상수였다(55–67, 질문 텍스트 몫). 예측은 저장소 회계 문서의 Haiku 4.5 식이다: ceil(w/28)×ceil(h/28), 긴 변 1568·1568 patch 상한. 상한 쪽은 선형 탐색으로 근사했다. 따라서 Haiku 이미지 토큰도 공개 회계식과 432회 모두 일치했다. GPT-4o(pilot-001~003)에 이어 두 번째 공급자다.

## 관찰 (탐색 수준)

1. **같은 변환이 공급자마다 정반대로 작동했다.** 긴 변 1024 축소는 GPT-4o 토큰을 줄이지 않았다(825 → 825). Haiku 토큰은 33% 줄였다(1,625 → 1,097). 대신 Haiku 정확도는 94%에서 69%로 크게 떨어졌다. GPT-4o는 원래 내부에서 768 짧은 변으로 줄여 처리하므로 1024 축소의 추가 손실이 작았다(89% → 86%).
2. **crop의 절감은 Haiku에서 더 컸다.** Haiku는 pixel 면적에 비례해 과금하므로, 같은 crop이 더 많이 줄인다. clean 기준 C1R은 GPT-4o −25%, Haiku −56%였다. oracle crop은 GPT-4o −49%, Haiku −89%였다.
3. **정확도 대가는 공급자에 따라 다르다.** clean에서 C1R은 GPT-4o에서 A와 같은 정확도였지만(89% 대 89%), Haiku에서는 5%p 낮았다(89% 대 94%). Haiku 원본이 더 정확했기 때문이다. Haiku는 2048×1536을 1568 상한까지만 줄인다. 차이는 1–2문항 수준이라 우열은 말할 수 없다.
4. **토큰 수와 비용은 다르다.** Haiku는 같은 이미지에 GPT-4o보다 토큰을 약 2배 쓰지만 단가가 2.5배 낮다. 그래서 clean A의 이미지 비용은 Haiku 약 $0.0016, GPT-4o 약 $0.0021이다(정가 기준). 공급자 비교는 토큰 수가 아니라 비용으로 해야 한다.

## 논문에 주는 함의

RQ1의 핵심 결과가 된다. "클라이언트 쪽 resize의 절감 효과는 공급자의 회계 방식에 달려 있다. GPT-4o 타일 회계에서는 0%, Haiku patch 회계에서는 33%이며, Haiku에서는 큰 정확도 손실이 따른다. 반면 질의 인식 crop은 두 공급자 모두에서 절감을 낸다." 실무 도구들의 "픽셀을 줄이면 비용이 준다"는 주장은 공급자에 따라 성립하기도 하고 안 하기도 한다.
