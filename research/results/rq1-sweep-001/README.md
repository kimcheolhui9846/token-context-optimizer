## 1. 회계식 일치

| 공급자·설정 | 일치 | 비고 |
|---|---|---|
| GPT-4o detail high | **66/66 정확히 일치** | 타일 규칙: 2048 맞춤 → 짧은 변 768 → 512 타일, 85 + 170×타일 |
| GPT-4o detail low | **66/66**(모두 85) | 크기와 무관 |
| Haiku 4.5 | **66/66이 예측 + 3** | 이미지 한 장마다 고정 3토큰이 붙는다. 패치 수 식 자체는 66장 모두 맞았다 |
| Haiku count_tokens 대 실제 청구 | 66/66 같음 | count_tokens(무료)로 청구 토큰을 미리 알 수 있다 |
| PNG 대 JPEG q75 | 7/7 같음(두 공급자) | 형식은 청구 토큰에 영향이 없다 |

- **Haiku 고정 3토큰.** pilot-003-haiku에서는 질문마다 "실측 − 예측"이 하나의 상수(55–67)였는데, 그 안에 이 3토큰이 섞여 있었다. 이번 기준선 분리로 처음 드러났다. 회계식 해석을 바꾸지는 않는다.
- **상한 근처에서도 일치한다.** `run.mjs`의 Haiku 상한 처리는 공식 이진 탐색을 선형 탐색으로 근사한 것이다. 상한에 걸리는 크기와 7개 종횡비 모두에서 결과가 같았다. 이번 표본 범위의 결과다.

## 2. 축소가 토큰을 줄이는 구간 (긴 변 2048 대비 절감률, PNG)

| 종횡비 | 1536 | 1024 | 768 | 512 | 256 |
|---|---|---|---|---|---|
| 1:1 | GPT 0% / Haiku 0% | 0% / 10% | 0% / 48% | 67% / 76% | 67% / 93% |
| 4:3, 3:4 | 0% / 0% | 0% / 34% | 0% / 62% | 67% / 83% | 67% / 95% |
| 16:9, 9:16 | 0% / 0% | 31% / 50% | 62% / 71% | 77% / 86% | 77% / 96% |
| 3:1, 1:3 | **59% / 2%** | 71% / 55% | 71% / 73% | 82% / 87% | 82% / 96% |

**관찰**

- **GPT-4o는 계단식이다.**
  - 1:1·4:3에서는 긴 변 3072부터 768까지 줄여도 765토큰으로 같다(0%). 512 이하로 가야 255토큰(−67%)이 된다.
  - 경계 사례: 512×512는 255인데 513×513은 765다. 1픽셀 차이로 3배가 된다.
  - 종횡비에 따라 계단 위치가 다르다. 3:1에서는 2048 → 1536만 줄여도 −59%다(1,445 → 595).
- **Haiku는 상한 아래에서 넓이에 거의 비례한다.**
  - 시각 토큰 1,568 상한에 걸리는 크기(4:3에서 긴 변 약 1,536 이상)에서는 줄여도 0%다. held-out S4 결과와 같은 원인이다.
  - 그 아래에서는 줄일수록 고르게 준다(4:3: 1024 −34%, 768 −62%).
- **같은 축소라도 공급자에 따라 정반대가 된다.**
  - 4:3 1024: GPT 0%, Haiku −34%
  - 3:1 1536: GPT −59%, Haiku −2%
  - "픽셀을 줄이면 비용이 준다"는 통념은 공급자·종횡비·목표 크기에 따라 맞기도, 틀리기도 한다.

## 3. 해석과 쓰임

- **기여 C1의 근거가 넓어졌다.** 파일럿(4:3·3:4, 2048 이하)에서 종횡비 7종, 긴 변 256–3072로 넓혔다. 두 공급자의 공개 회계식이 모두 청구 토큰과 일치했다. Haiku는 이미지당 고정 3토큰을 더해야 한다.
- **제품 쪽 시사점(후속 resize 구현, X8):** 축소 목표 크기를 공급자별 계단·상한에 맞춰야 절감이 생긴다.
  - GPT-4o: 짧은 변 768 계단과 512 타일 경계
  - Haiku: 1,568 토큰 상한 아래
  - 이 경계를 1픽셀 넘으면 절감이 사라질 수 있다.
  - 정확도 영향은 이 측정의 범위가 아니다. 작은 글자 정확도 손실은 pilot-001·003-haiku를 본다.
