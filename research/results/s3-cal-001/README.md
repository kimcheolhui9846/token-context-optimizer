## 관찰

1. **compact는 세부를 크게 잃었다(H2).** 고정 일정에서 S1의 늦은 회상은 17%, 교차·요지는 0%였다. UNREADABLE 답이 27건이었다.
2. **플러그인은 compact 뒤에도 회상을 되찾았다(H3).** 같은 시점에 compact해도 S3의 늦은 회상은 72%로, S1(17%)보다 55%p 높다. 아티팩트가 컨텍스트 밖에 남아 다시 꺼낼 수 있기 때문이다. 이번 결과에서 가장 분명한 차이다.
3. **플러그인 단독(S2)은 토큰을 줄였지만 정확도를 일부 잃었다(H1 부분).** 정확도는 88%에서 79%, 늦은 회상은 94%에서 67%로 떨어졌다. 오답의 원인은 두 가지다.
   - 이미지 전체를 봐야 하는 질문("가장 높은 막대")에서 selector가 제목 줄을 잘라 왔다. 모델은 판독 불가 표시 없이 틀렸다(조용한 오답).
   - 13px 작은 글자(메모 각주, 사이드바 저장 용량)는 crop으로 못 읽은 뒤 원본을 자동으로 다시 받아도 판독 불가였다. 공급자가 원본을 줄여 처리하기 때문이다.
4. **플러그인 조건은 임계값에 한 번도 닿지 않았다.** S0과 S4는 28턴이 4,000토큰을 넘었고, S2와 S3는 0턴이다. 임계값 방식의 제품이라면 플러그인은 compact 자체를 미루거나 피한다. 손실 요약을 겪지 않는다는 뜻이다.
5. **캐싱을 고려하면 절감이 크게 줄었다(H4).** 정가 기준 −43%(S2)가 캐시 기준으로는 −15%가 됐다. S0의 반복 전송은 자동 캐시로 이미 싸다. 반면 플러그인은 도구 결과를 비우면서 기록 앞부분을 바꿔 캐시를 깬다. 도구 왕복으로 호출 수도 2배다(16.5 대 8.0).
6. **1536 축소(S4)는 토큰을 줄이지 않았다.** RQ1 결과(pilot-001)와 같다.

## held-out 전에 정할 것 (제안)

calibration은 설정을 고치는 데 써도 되는 분할이다. 아래 두 가지는 위 원인에 직접 대응하는 변경이다. 바꾼다면 calibration을 한 번 더 돌린 뒤 동결한다.

- **전체 맥락 썸네일:** `query_image_artifact`가 crop과 함께 저해상도 전체 이미지(OpenAI detail low, 85토큰)를 돌려준다. 전체를 봐야 하는 질문의 조용한 오답을 줄이려는 것이다.
- **캐시 친화적 비우기:** 도구 결과 이미지를 매 턴 비우지 않고, compact 시점이나 일정 턴마다 한꺼번에 비운다. 비우는 사이에는 캐시 접두부가 유지된다.
- 또는 지금 설계를 그대로 동결하고 held-out을 실행한다. 이 경우 위 약점을 결과로 그대로 보고한다.
