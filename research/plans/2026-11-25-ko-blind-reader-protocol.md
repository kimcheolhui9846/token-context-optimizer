## 1. 목적과 해석 한계

사용자 한 명이 처음 보는 한국어 합성 표 18개를 직접 판독한다. 질문한 기록의 두 수치 열 가운데 질문 필드의 열(왼쪽/오른쪽)과 그 값을 모두 맞힌 문항 수를 W1, W4, W5 표시 방식마다 센다(방식당 6문항).

- 독자는 앞선 방법(#153 W4, #154 W5)을 아는 프로젝트 운영자다. 방법 이름만 가린 **단일 독자 파일럿**이며, 독자는 화면 모양으로 방식을 짐작할 수 있다. 문항 난이도 차이도 결과에 섞인다. 이 셋을 결과 보고에 그대로 남긴다.
- 효과 크기, 일반 독자 성능, 유의성, W5 채택 여부를 판정하지 않는다. 결과는 건수로만 보고한다.
- 진짜 응답 전에는 점수를 내지 않는다. 사용자가 실제로 답할 때까지 연구 결과는 **미측정**이다.

## 4. 새 자료 생성 (시드 하나에서 결정)

### 4.1 구성과 배정

- 18개 서로 다른 신규 원본. 유형(시각 time / 인원 count / 분량 pages) × 정답 열 방향(L/R) 6개 층, 층마다 3개 원본.
- 층마다 세 원본을 W1·W4·W5에 하나씩 배정(층별 무작위 순열) → 방식마다 6문항, 유형 2개씩, L 3·R 3.
- 방식마다 **정답 값이 경쟁 값보다 큰 문항 3, 작은 문항 3**. 좌우 방향별로는 3이 홀수라 완전 균형이 불가능하므로 L·R 각각의 "큰" 수가 {1, 2}이고 합이 3이 되게 한다(어느 쪽이 2인지 무작위). 전체는 9/9.
- 같은 방식으로 **질문 필드가 자연 순서상 앞 이름인 문항**(예: 출발/도착의 출발)도 방식마다 3/3, 좌우 {1, 2}로 균형화한다. 질문 레코드의 위치(위/가운데/아래)는 방식마다 2/2/2.
- 원본마다 문서 종류(6종) 하나. 종류 순열은 각 3개.
- **순서:** 하나의 시드에서 18문항 전체 순서를 제약 무작위화한다(거부 표집, 최대 200,000회). 6문항씩 3블록, 블록마다 방식 2개씩, 유형 2개씩, L 3·R 3. 같은 방식이 3번 연속하지 않는다.
- 독자는 원본마다 한 방식만 본다. 실제 결과에 따라 배정이나 데이터를 다시 뽑지 않는다.

### 4.2 시드와 난수

- DRBG: HMAC-SHA256 카운터 모드(`registered.json`의 `drbg`). 스트림 이름별(`assign`, `order`, `kind`, `content:<원본>:<시도>`, `ids`, `packet`) 독립 바이트열. `randbelow`는 거부 표집, `shuffle`은 Fisher–Yates.
- **공개 모의 시드**(`mockSeedHex`)는 등록값이다. 공개 구현·시험·재현은 이 시드와 시험용 시드만 쓴다. 모의 결과는 "mock"으로 표기한다.
- **실제 시드:** 관문 통과 뒤 `secrets.token_bytes(32)`로 한 번 만들고 관리자 폴더에만 둔다. 출력·커밋하지 않는다. 풀·코드는 공개지만 시드 없이는 배정·문항 조합을 역산할 수 없다.
- 실제 시드와 배정을 **선택기(OCR) 실행 전에** 고정한다: 시드·배정 파일의 약속값(8.3절)을 커밋·push한 뒤 OCR을 돌린다.

### 4.3 문항 내용과 생성 절차

- 페이지 문법은 #153과 같다(1280 × 960, 기록명 열 `[40,320)`, 값 열 L `[360,580)`·R `[620,840)`, 머리글 없는 비고 열 `[1060,1250)`, 레코드 3개 × 두 줄, 세로 괘선 없음). 머리글은 정상(두 필드명이 다름), 질문 값은 표지와 같은 줄 A(#153 `<side>-normal-same` 셀). 두 값 열은 같은 유형·같은 서식이다.
- 질문 문법은 #153 그대로: `<기록명>의 <필드명>은 몇 시/명/쪽인가요?`. 필드명은 `<한글 2음절> 시각|인원|분량`. 
- 값: 시각 `HH:MM`(10–20시, 10분 단위), 인원 `N명`(10–95), 분량은 원본마다 자릿수를 먼저 뽑는다(두 자리 12–99 또는 세 자리 100–240). 한 원본의 값 6개(질문 열 3, 경쟁 열 3)는 서로 다르고 정규화 값도 다르다. 질문 행의 두 값 순서가 "큰/작은" 배정과 다르면 그 두 값만 맞바꾼다.
- **후보 풀(`registered.json` `pools`, 첫 커밋 고정):** 문서 종류 6개(제목, 기록명 열 머리글, 기록명 후보 각 20개), 유형별 필드 쌍 16개, 보조 문구 18개, 비고 12개. 모두 새로 만든 문자열이다.
- **풀 필터(시드 무관, 결정적):** 근접 재사용 규칙(4.4절)에 걸리는 기록명, 한글 bigram 4개 미만 기록명, 칸을 넘는 문자열, 이전 자료에 있는 필드명, 첫 단어가 정확히 한글 2음절이 아닌 필드 쌍을 뽑기 전에 뺀다. 2음절 규칙은 질문 필드 머리글이 질문과 bigram을 정확히 2개 공유하게 해 #153 규칙(≤ 2)을 지키게 한다.
- **모의 제외:** 실제 생성은 먼저 공개 모의 시드로 생성을 실행해 모의 세트가 쓴 기록명·필드 쌍을 실제 후보에서 뺀다(공개된 모의 문항과 실제 문항이 겹치지 않게).
- **원본별 생성:** 스트림 `content:<원본>:<시도>`에서 필드 쌍(그 유형의 미사용 쌍 균등), 기록명 3개(그 종류의 미사용 후보), 자릿수(분량만), 값 6개, 보조 문구 6개, 비고 3개를 뽑는다. 쪽 규칙(아래)에 하나라도 걸리면 시도 번호를 1 늘려 그 원본 내용을 통째로 다시 뽑는다(최대 1,000회, 넘으면 생성 실패). 이것이 길이·유일성 충돌의 등록된 결정 규칙이다.
- **쪽 규칙(#153 3.3절 규칙 계승):** 질문에 목표 표지가 정확히 1회·`의 `가 정확히 1회이고 #153 파서로 (목표 표지, 필드, 유형)이 나온다. 목표 표지와 bigram을 공유하는 다른 항목 없음. 머리글·제목 외 항목은 질문과 bigram 공유 없음, 머리글·제목 ≤ 2, 기록명 열 머리글 0. 값 외 항목은 값 문법에 맞지 않고 ASCII 영숫자가 없다. `시각`·`인원`·`분량`은 두 필드 머리글에만. 등록 폭(기록명 268px, 머리글·보조 208px, 비고 178px)을 넘지 않는다.
- **공개 사전 확인(등록 전, 시험용 시드만):** 풀 필터 뒤 종류마다 기록명 20개, 유형마다 필드 쌍 16개가 남았다. 시험용 시드 200개로 생성하면 200/200 성공, 순서 거부 표집 최대 42,724회, 원본 내용 재시도 최대 3회였다. 이 수치는 실제 시드와 무관하다.

### 4.4 이전 자료와의 중복·근접 재사용 (첫 커밋 고정)

- 비교 대상: `registered.json` `priorCorpus.files`의 16개 Git blob(r09 heldout·dev, FCP, #148, #150, #151, #152, #153의 질문·설계 파일)에 있는 한글 포함 문자열 전체와 그 질문들. 이미지: 같은 목록의 PNG tree 8개.
- **기록명(단일 규칙):** NFC 후 한글 음절 연속 구간 안의 인접 음절쌍(bigram) 집합 B. 새 기록명 x를 거부: `squash(x)`가 어떤 대상 문자열의 `squash` 부분 문자열이거나, 어떤 대상 문자열 s에 대해 `|B(x) ∩ B(s)| / |B(x)| ≥ 0.5`.
- **필드명:** `squash(필드명)`이 어떤 대상 문자열의 부분 문자열이면 거부.
- **질문:** 정규화 질문(NFC, 공백 연속 → 한 칸, 양끝 제거)이 이전 질문과 같으면 거부. 새 세트 안에서도 질문 18개는 서로 다르다.
- 고정 질문 문법 자체(`의`, `은`, `몇`, 단위, `인가요`)는 따로 비교하지 않는다. PNG SHA-256 겹침은 0이어야 한다.

### 4.5 렌더·OCR·세 방식 출력

1. `generate.py`가 `design.json`(렌더 입력), `plan.json`(배정·순서·내용·정답, 실제는 관리자 전용), `selector/questions.json`(이미지 ID·파일·질문)을 쓴다.
2. 고정 렌더러로 PNG·`gold.json`·`render.json`·`render-check.json`(실패 0이어야 함).
3. OCR: 위 핀 그대로 18쪽을 한 번씩. 입력은 **질문과 PNG뿐**(허용 목록 리더). 설계·정답·배정·렌더 기록은 선택기에 전달하지 않는다. 시간 초과·예외는 재시도하지 않고 그 쪽의 기술 오류로 남긴다.
4. 예측: 고정 #153 `buildPrediction`으로 W1, W4(W4 미적용이면 W1과 같음).
5. 표시: 고정 #154 `project/plan/compose/crop`으로 W1·W4·W5 PNG를 **세 방식 모두** 만든다. W5는 W4 적용 시 원본 머리글 띠와 본문 띠를 같은 x로 조립하고, 미적용·머리글 폭 밖·머리글 아래이면 W1을 유지한다. W4·W5 모두 한 열만 잘라내는 방식이 아니다.
6. 결과에 따른 수정 없음: W4 미적용으로 W1과 같아진 문항, 고정 선택기 실패, 선택 창이 단서를 가린 문항도 그대로 분모 6에 남긴다. 상위 오류·미매치로 방식 출력이 없으면 **미표시**(5.3절)다.
7. 계약 손상·해시 오류·실행 환경 오류는 **발행 전 실패**로 기록하고 판독지를 만들지 않는다. 기술 결함은 같은 시드·배정을 유지한 채 고치고 재검사하며, 노출 전/후를 인계서에 기록한다. 다른 시드를 찾아 결과를 고르지 않는다.
8. 실제로 W4·W5가 W1과 다른 문항 수, 방식 적용 수, 조건별 가시성은 독자가 응답을 닫은 뒤에만 따로 보고한다.

## 5. 판독지 (독자 폴더의 단일 HTML)

### 5.1 전달과 격리

- 독자 폴더 `D:/orca/participant-packets/ko-blind-reader-pilot/`에는 `start.html` 하나만 둔다. 다른 방식 이미지·원본·채점기·키는 넣지 않는다. 관리자 폴더 `D:/orca/local-research-admin/ko-blind-reader-pilot/`에 사전 고정 기록, 원본, 세 방식 QA, 로컬 채점 진입점을 둔다. 기존 파일이 있으면 덮어쓰지 않고 보고한다.
- 판독지는 설치·계정·네트워크 없이 열리는 한국어 단일 파일이다. 이미지는 data URI PNG로 들어 있다. 화면·DOM·스크립트·대체 텍스트·PNG 부가정보·파일 이름·폴더에 열 정답, 조건명, 방식별 경로, 원본 ID, 정답표가 없다. 문항은 표시 순서 번호(1–18)로만 식별한다.
- 독자 링크는 `start.html`만 가리킨다. 실제 자료·키·응답·점수의 원격 게시나 제3자 전달은 이 과제 밖의 별도 결정이다.

### 5.2 화면 흐름

1. **시작:** 과제 설명(시간 제한 없음, 앞으로만 이동, 건너뛰기·중단 가능, 마지막에 응답 파일 저장), 자기 표시 "이 판독지를 열기 전에 정답·배정·원본 표 등 관리자 자료를 본 적이 있습니까?"(예/아니오, 필수). "예"면 그 세션은 눈가림 분석에서 무효로 분류된다. "중간 저장 불러오기"도 여기 있다.
2. **좌우 기준 안내(비채점 예시):** 연습 예시 표(등록 내용, 공개) 이미지와 함께 "첫 열은 기록 이름 열이다. 그 오른쪽의 두 수치 열 중 가까운 쪽이 왼쪽 수치 열, 먼 쪽이 오른쪽 수치 열이다. 맨 오른쪽 비고 열은 수치 열이 아니다."를 보여 준다.
3. **연습 한 문제(비채점):** 본 문항과 같은 입력. 답한 뒤 정답(왼쪽 수치 열, 11:40)과 이유를 보여 준다. 연습은 응답 파일에 넣지 않는다.
4. **본 문항 18개:** 질문, 이미지, 진행 표시(`n / 18`), 열 선택(왼쪽 수치 열 / 오른쪽 수치 열 / 판단 불가), 값 입력(자유 입력 + "값 판단 불가"), 유형별 단위 안내(시각 "24시간 형식 시:분 (예: 7:05)", 인원 "숫자만 또는 숫자+명 (예: 7)", 분량 "숫자만 또는 숫자+쪽 (예: 5)"; 예시는 생성 범위 밖이라 정답과 같을 수 없다). 입력 형식이 정규화 규칙에 맞지 않으면 "형식이 안내와 다릅니다(그대로 제출 가능)"만 표시한다(정오 단서 없음).
5. **이미지 보기:** 화면 맞춤(기본, 균일 확대·축소) / 원본 크기 / 2배. 원본 크기 이상에서는 가로 스크롤로 전체 너비를 본다. 열 위치나 이름을 알 수 없으면 판단 불가를 고른다.
6. **이동 규칙:** "다음 문항"은 열과 값(또는 값 판단 불가)이 모두 있을 때만. 답하지 않고 넘기려면 "이 문항 건너뛰기" → "건너뛰기 확정"(의도한 건너뜀). 지난 문항으로 돌아가지 않는다. 현재 문항의 답은 넘어가기 전까지 고칠 수 있다(제출 전 수정 정책).
7. **중단:** "중단하기" → "중단 확정". 상태 `aborted`로 최종 파일을 만든다. 현재 문항(확정하지 않은 답은 버린다)과 그 이후 문항은 `notReached`다.
8. **완료:** 마지막 문항 뒤 확인 화면(답한 수·건너뛴 수만, 정오 없음) → "완료 확정". 최종 응답 JSON을 한 번 만들어 다운로드하고, 복사 가능한 읽기 전용 답지(같은 JSON)를 보여 준다. 그 뒤 화면은 잠기며 다시 확정할 수 없다(같은 파일 재다운로드만 가능).
- **마감:** 독자가 처음으로 "완료 확정" 또는 "중단 확정"을 누른 시점. 시간 제한은 없다.

### 5.3 미표시

- 기술적으로 유효한 미표시(상위 OCR 오류·K1 미매치로 방식 출력이 없음)는 이미지 대신 "이 문항은 표시할 이미지가 없습니다."의 같은 중립 화면을 보이고, 열과 값을 모두 판단 불가로 고정한다(입력 비활성). 채점에서 분모 6에 남겨 0점이며 미표시 수를 따로 센다.

### 5.4 저장과 중간 저장

- 응답을 localStorage·sessionStorage·IndexedDB·쿠키에 두지 않는다. 상태는 페이지 메모리에만 있다. 외부 요청은 없다.
- **수동 중간 저장/재개(지원 범위):** "중간 저장 파일 받기"는 `kind: "interim"` 파일(지금까지 답, 다음 위치)을 내려받는다. 시작 화면 "중간 저장 불러오기"는 같은 `packetId`·`packetHash`·유효 digest인 파일만 받아 저장된 다음 위치부터 이어 간다(앞 문항은 고정). 같은 판독지 안에서만, 앞으로만 재개한다. 중간 저장 파일은 최종 응답이 아니며 채점기가 거부한다.

### 5.5 응답 파일

- `kbr-response-1`: `format`, `kind`(final), `packetId`, `packetHash`, `status`(completed/aborted), `adminMaterialSeen`(yes/no), `position`, `items`(18개: `pos`, `displayed`, `reached`, `skipped`, `column`, `value`, `valueUnknown`), `digest`(digest 필드를 뺀 정규 JSON — 키 정렬, 공백 없음 — 의 SHA-256).
- 이름·연락처·시각 기록·원시 이벤트·기기 정보를 담지 않는다.

## 6. 정규화와 채점 (첫 커밋 고정)

### 6.1 값 정규화

- 공통: NFKC 뒤 모든 Unicode White_Space를 지운다. 비면 값 없음.
- 시각: `^(\d{1,2}):(\d{2})$`, `^(\d{1,2})시(\d{1,2})분$`, `^(\d{1,2})시$`(분 00)만. 시 0–23, 분 0–59. 정규형 `H:MM`(시 앞 0 없음). 오전/오후, 반, 점, 다른 단위는 해석하지 않는다.
- 인원: `^(\d{1,4})명?$`. 분량: `^(\d{1,4})쪽?$`. 정규형은 앞 0 없는 십진수, 1 이상.
- 정답 값은 렌더한 질문 열 값의 정규형이다.
- 경곗값 음성 시험(첫 커밋 시험에 포함): `14:3`, `14:300`, `24:00`, `14.30`, `오후 2시`, `2시 반`, `30명명`, `3O명`, `-5명`, 인원에 `50쪽`, 분량에 `50명`, `명`, `0`, `00:60`, `1,200쪽`은 해석 불가. `１４：３０`(전각, NFKC로 허용), `50 명`, `09:30`(→ `9:30`), `14시30분`, `14시`(→ `14:00`)은 허용.

### 6.2 채점

- 열 정답: `column`이 키의 방향(L/R)과 같음. `unknown`·없음은 오답.
- 값 정답: `valueUnknown`이 거짓이고 정규화 값 = 정답 정규형.
- **주지표:** 방식마다 두 항목 모두 정답인 수 / 배정 6.
- **보조 지표:** 열만 정답, 값만 정답, 둘 다 오답, 판단 불가(열 또는 값), 미표시, 건너뜀, 미도달(중단 뒤). 완료/중단을 구분한다. 중단 파일은 배정 분모 6 옆에 응답 분모와 미응답 수를 함께 쓴다.
- 자기 표시 "예"이면 세션을 **눈가림 무효**로 표시한다(수치는 계산하되 무효 표시).
- 최종화 전에는 점수가 없다. 빈 설문·중간 저장·부분 파일은 최종 응답으로 세지 않는다.

### 6.3 채점기와 제출 고정

- 별도 로컬 채점기는 관리자 폴더에 있다(Node 내장 모듈만, 추가 설치 없음; `채점.cmd`로 실행). 독자 폴더에는 없다.
- 순서: 형식·버전 → `kind == final` → `packetId` → `packetHash` → digest → `pos` 1–18 각 1회(중복·누락 거부) → 필드 값 유효성 → 제출 고정 → 채점.
- **제출 고정:** 처음 통과한 최종 응답을 관리자 폴더 `responses/locked.json`으로 복사하고 SHA-256을 기록한다. 같은 바이트를 다시 채점하면 같은 결과(멱등). 다른 응답은 덮어쓰지 않고 거부한다.
- 점수표는 관리자 폴더 `score/`의 파일로만 쓴다. 채점기 표준 출력은 경로·개수·SHA-256·통과 여부만이다. 이름·원시 응답·점수를 모델이나 원격으로 보내지 않는다. 사용자가 원할 때만 결과를 대화·원고에 반영한다.
- 별도 재계산: Python `recount.py`가 같은 응답·키에서 점수표를 독립 계산해 JS 결과와 칸별로 대조한다.

## 8. 비밀 유지와 공개 증거

### 8.1 출력 제한

- 실제 데이터 명령의 출력은 경로·개수·범위·통과 여부·SHA-256만이다. 텍스트·값·배정·순서·방향·가시성·점수를 출력하지 않는다. 모든 명령은 허용 키·허용 값 형식만 통과시키는 출력 함수를 쓰고, 모의 자료의 비밀 문자열(정답, 기록명, 질문, 배정, 시드)이 오류 경로를 포함한 표준 출력·오류에 재귀적으로 나타나지 않는지 시험한다.
- 실제 방식 적용 수, 실제 배정, 조건별 가시성, 실제 이미지, 답, 질문 텍스트, 키, 시드, 점수를 도구 화면·모델 채팅·인계서·PR에 노출하지 않는다.

### 8.2 저장 위치

- 공개(Git): 이 문서, 등록값, 코드, 시험, 관문 결과, 모의 결과, 실제 자료의 약속값과 통과 여부.
- 관리자 폴더만: 실제 시드, salt, 배정·순서, 원본·렌더, OCR·예측, 세 방식 출력, QA·가시성, 키, 채점기, 고정 응답, 점수표.
- 독자 폴더만: `start.html`.

### 8.3 약속값 (commitment)

- `commit = SHA-256(salt ‖ UTF-8(label) ‖ 0x00 ‖ bytes)`, salt는 OS CSPRNG 32바이트(256비트), 약속마다 따로. 라벨: `kbr-seed`(시드 파일), `kbr-assignment`(배정·순서 `plan.json`), `kbr-packet`(`start.html`), `kbr-key`(정답 키).
- 시드·배정 약속값은 OCR 전에, 판독지·키 약속값은 판독지 전달 전에 커밋·push한다. Draft PR에는 이 약속값만 기록한다. 공개 모의 시드 결과는 따로 `mock`으로 표기한다.
