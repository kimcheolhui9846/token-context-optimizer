- 목적: A안 핵심 주장("원본 보존 발췌가 compact 손실을 되찾는다")과 기여 C2·C3가 선행 연구와 겹치는지 확인한다. 논문 §2(관련 연구)와 기여 문장의 수정안을 낸다.

  - 2026-10-15 웹 검색 2회(아래 §4)
- 한계

## 1. 결론 요약

| 우리 요소 | 선행 연구에 이미 있는가 | 판단 |
|---|---|---|
| 원본을 외부에 보존하고, 문맥에는 짧은 참조만 두고, 필요할 때 되살림 | **있다.** DTOC [A1], ACM [A2]. 텍스트 에이전트 | 새 원리로 주장하면 안 된다 |
| compact 요약 + 원본 보존 + 질의로 재조회(우리 S3 구조) | **있다.** ACM [A2]. 요약, 원본 파일 저장, `query_memory` | 구조의 새로움은 주장하지 않는다 |
| 오래된 도구 결과를 기록에서 지움(우리 이미지 일괄 비우기) | **있다.** observation masking [A3]. 화면 이미지 버리기 [B1] | 기존 방법의 변형으로 쓴다 |
| 질문 인식 텍스트 압축·발췌 | **있다.** LongLLMLingua [C2], RECOMP 추출형 [C5] | 텍스트 발췌 자체는 새롭지 않다 |
| 이미지의 질문 인식 crop + 저해상도 전체 썸네일 + 판독 불가 시 원본 자동 재요청을 API 앞단(black-box)에서 수행 | 찾지 못했다. GUI 에이전트 연구는 모델 내부 토큰 pruning [B2] 또는 이미지 버리기 [B1]다 | **차별점 1** |
| 공급자 청구 토큰으로, 정가와 프롬프트 캐시 반영을 나눠 두 공급자에서 측정 | 찾지 못했다. 선행 연구는 USD 비용 [A3], 입력·캐시 읽기 토큰 보고 [A1], peak 토큰 [A2, A4] | **차별점 2** |
| compact가 잃는 세부를 직접 재는 늦은 회상 문항 + 사전 등록 held-out + 짝지은 신뢰구간 | 찾지 못했다. 선행 연구는 과제 성공률(SWE-bench, AppWorld)이다. DTOC는 6과제·단일 시행 [A1], Focus는 5건이다 [A5] | **차별점 3** |
| LLM 없이 결정적으로 발췌(어휘 일치 + 줄 번호·해시 출처) | ACM은 querier LLM이 원본을 읽고 답을 만든다 [A2]. DTOC는 출력 전체를 되살린다 [A1] | 차별점 4(작음) |
| 부정 결과: 비열등 미입증, 공급자에 따라 비용 역전 | 해당 없음 | C4로 보고 |

**판단:** A안 핵심 주장의 방향은 선행 연구와 **일치**한다. 이것은 약점이 아니라 근거가 된다.
- DTOC: 되살리기를 뺀 "끄기만" 변형은 성능이 떨어졌고, 되살리기를 포함한 전체 DTOC는 정확도를 되찾았다 [A1 §ablation]. 우리 S1(compact만) 대 S3(플러그인 + compact)와 같은 방향이다.
- observation masking: LLM 요약이 단순 지우기보다 낫지 않았다 [A3].

따라서 우리 기여는 "새 구조"가 아니라 다음으로 잡아야 한다. **선행 연구가 텍스트 에이전트에서 보인 원본 보존·재조회 구조를 (1) 이미지 입력으로 확장하고, (2) 공급자 청구 토큰과 캐시로 실측하고, (3) 사전 등록 held-out으로 검증했다.**

## 2. 논문별 대조

### A. 에이전트 컨텍스트 관리 (`paper/09-agent-context`)

**[A1] DTOC.** Chaturvedi et al., *Dynamic Tool Output Compression for Adaptive Context Management in AI Agents*, arXiv 2609.26121(2026-08)
- 한 일
  - 도구 출력을 외부 메모리에 두고, 문맥에는 placeholder(도구 키, 시각, 토큰 추정)만 둔다.
  - 에이전트가 `manage_context(enable, disable)`로 출력 전체를 숨기거나 되살린다(§3.2).
  - DeepSWE 6과제, 모델별 단일 시행. 반응이 좋은 모델에서 입력 토큰 −10.3%(Sonnet 4.6), −12.7%(GPT-5.4)였고, 해결률이 올랐다.
  - 다른 모델에서는 효과가 없거나 비용이 늘었다(초록).
  - 끄기만 하는 변형은 성능이 떨어졌다(초록, ablation).
- 겹침: 원본 보존과 되살리기 원칙, 모델에 따라 효과가 다르다는 관찰
- 차이
  - 텍스트만 다룬다.
  - 출력 전체를 되살린다. 질문에 맞춘 부분 발췌가 아니다.
  - 요약과 직접 비교하지 않았다(§6 한계에 명시).
  - 캐시 읽기 토큰은 보고했지만, 정가 대 캐시 기준 절감 비교는 없다.
- 인용 문장 후보: "원본을 외부에 보존하고 문맥에는 참조만 두는 가역적 관리는 텍스트 에이전트에서 제안되었다 [A1, A2]."

**[A2] ACM.** Li, Ming, et al., *ACM: Agentic Context Management for Long Horizon Tasks*, arXiv 2607.23809(2026-07)
- 한 일
  - `manage_context`가 이전 턴을 요약하고 원본 메시지를 파일로 내보낸다.
  - `query_memory`가 식별자로 원본을 조회한다. querier LLM이 원본을 읽고 관련 정보를 돌려준다(§3).
  - 사후 학습 파이프라인을 포함한다. agentic search와 coding으로 평가했다.
- 겹침: **우리 S3와 같은 구조**다(요약 + 원본 보존 + 질의 조회).
- 차이
  - 텍스트만 다룬다.
  - 조회 결과를 LLM이 만든다. 추가 호출이 들고 손실이 생길 수 있다. 우리는 결정적 발췌와 출처를 쓴다.
  - 비용을 peak 토큰으로 잰다. 청구 토큰과 캐시는 없다.
  - 압축 시점을 에이전트가 정한다. 우리는 compact 일정을 고정하고, 조회만 모델이 정한다.
- 참고 관찰
  - ACM은 API 모델(GPT-5.5)에도 적용했다.
  - 다만 GPT-5.5는 학습 없이는 관리 도구를 거의 부르지 않았다(BrowseComp-Plus 도구 호출 분석). 저자들은 이것을 사후 학습의 동기로 든다.
  - 모델에 따라 도구 사용 행동이 달라진다는 점에서, 우리 Haiku의 도구 왕복 소진 문제와 함께 논의할 수 있다.

**[A3] The Complexity Trap.** Lindenbauer et al., *Simple Observation Masking Is as Efficient as LLM Summarization for Agent Context Management*, NeurIPS 2025 Workshop DL4Code(PDF 표기), arXiv 2508.21433
- 한 일
  - SWE-agent, SWE-bench Verified, 모델 구성 5개
  - 최근 M턴 밖의 관측을 placeholder로 바꾸는 masking과 LLM 요약을 비교했다.
  - masking이 Raw 대비 비용을 절반으로 줄이면서 LLM 요약과 같거나 약간 높은 해결률을 냈다(초록).
  - 요약 호출은 매번 다른 턴 묶음을 처리해 캐시 재사용이 시스템 프롬프트로 제한된다고 지적했다(§5.2).
- 겹침
  - 우리 이미지 일괄 비우기는 masking의 변형이다.
  - "요약이 늘 낫지 않다"는 결론이 우리 S1 결과와 같은 방향이다.
- 차이
  - masking은 지운 원본을 되살리지 않는다.
  - 텍스트(SE 관측)만 다룬다.
  - 비용은 USD로 쟀지만, 캐시 반영 여부를 나눠 보지 않았다.
- 우리 쪽 보강 근거: 기록 편집이 캐시를 깬다는 우리 관찰(s3-dev-002)과 같은 문제의식이다.

**[A4] ACON.** Kang et al., *Optimizing Context Compression for Long-horizon LLM Agents*, ICML 2026(PDF 표기: PMLR 306), arXiv 2510.00615
- 한 일: 실패 분석으로 압축 지침을 자연어로 최적화하고, 작은 모델로 증류한다. peak 토큰 26–54%를 줄였다(초록).
- 차이: 손실 압축이다(원본을 보존하지 않는다). 텍스트만 다룬다. peak 토큰으로 잰다.
- 참고: `paper/README.md`에는 "ICLR 2026(검색 결과)"로 적혀 있다. PDF 표기(ICML 2026)로 고친다.

**[A5] Focus(Active Context Compression).** Verma, arXiv 2601.07190
- 한 일: 에이전트가 스스로 학습 내용을 지식 블록에 모으고 원 기록을 지운다. Claude Haiku 4.5, SWE-bench Lite 5건, 토큰 −22.7%, 정확도 동일(3/5)이다.
- 차이: 손실 압축이고 표본이 매우 작다. 인용하더라도 보조 근거로만 쓴다.

### B. 멀티모달 에이전트 (2026-10-15 검색)

**[B1] Screenshots or Tools?** Fan et al., *Eliciting Tool Use and Managing Multimodal Context in Hybrid GUI-MCP Computer-Use Agents*, arXiv 2608.03327(2026-08)
- arXiv 초록 페이지 기준. 본문은 읽지 않았다.
- 한 일
  - 도구 호출이 성공하면 다음 스크린샷을 빼고, 이미지 기록을 절반으로 줄였다. 입력 토큰이 약 1/3 줄고 정확도가 소폭 떨어졌다.
  - 같은 관측 규칙으로 재학습하자 손실이 사라졌다.
- 겹침: 이미지 기록을 줄여 입력 비용을 낮춘다는 점. **멀티모달 쪽에서 가장 가까운 선행 연구다.**
- 차이
  - 이미지를 버린다. 보존과 재조회가 없다.
  - crop·썸네일·판독 불가 재요청이 없다.
  - 재학습 정책이다.
  - 청구 토큰과 캐시 측정 여부는 초록에 없다.
- 할 일: 인용 전에 본문을 읽고 비용 측정 방식을 확인한다.

**[B2] GUI 에이전트의 과거 스크린샷 토큰 pruning.** Li et al., *Where and How to Prune*, arXiv 2603.26041. 같은 계열로 2602.23235(시공간 pruning), 2605.19260(AQuaUI), 2610.20390(STP-GUI)이 있다.
- 모두 모델 내부(ViT 임베딩, LLM 시각 토큰)에서 줄인다. API 앞단에 쓸 수 없다.
- 논문 초안 §2에 이미 있는 "내부 토큰 압축과 외부 이미지 변환을 같은 개입으로 순위화하지 않는다"는 문장이 이들에게도 그대로 적용된다.

### C. 텍스트 프롬프트·검색 압축 (`paper/07`, `paper/08`)

- **[C1] LLMLingua**(arXiv 2310.05736), **[C3] LLMLingua-2**(arXiv 2403.12968), **[C4] Selective Context**(arXiv 2310.06201)
  - 작은 LM으로 덜 중요한 토큰을 지운다. API 앞단에서 쓸 수 있다.
  - 손실·단방향 변환이다. DTOC도 식별자·숫자 같은 "예측 가능해 보이지만 중요한" 토큰을 지울 위험을 지적했다 [A1 §2].
  - 우리 발췌는 원문 줄을 그대로 돌려주므로 이 위험이 없다. 대신 줄을 못 고를 위험이 있다. held-out의 `query_artifact` 단일 구간 문제가 그 예다.
- **[C2] LongLLMLingua**(arXiv 2310.06839): 질문 인식 장문 압축이다. 우리 이미지 질문 인식 crop의 텍스트 쪽 대응물이다.
- **[C5] RECOMP**(arXiv 2310.04408): 검색 문서의 추출형·생성형 압축이다. 추출형(문장 선택)이 우리 텍스트 발췌와 가깝다. 단, 압축기를 학습한다.
- soft prompt 계열(Gist, AutoCompressors, ICAE, 500xCompressor, xRAG)은 모델 수정이나 모듈이 필요하다. API 사용 환경과 대비하는 데에만 쓴다.
- 학회명은 `paper/README.md`의 확인값을 따르고, 인용 전에 다시 확인한다.

## 3. 논문 수정안 (Task 35·38 입력)

### 3.1 기여 문장

- **C2(시스템)**
  - 현재: "텍스트와 이미지를 같은 인터페이스(원본 색인 → 질의 발췌 → 출처·해시)로 다루는 MCP 플러그인"
  - 수정안: "텍스트 에이전트에서 제안된 원본 보존·재조회 구조 [A1, A2]를 이미지 입력으로 확장한 MCP 플러그인. 이미지는 질문 인식 crop, 저해상도 전체 썸네일, 판독 불가 시 원본 재요청으로 다루고, 텍스트는 LLM 없이 출처를 붙여 발췌한다."
- **C3(세션 평가)**
  - 현재: "… 멀티모달 에이전트 컨텍스트를 청구 토큰으로 잰 첫 평가가 목표다."
  - 수정안: "다중 턴 세션에서 전체 유지, compact 모사, 원본 보존 발췌, 그 조합을 사전 등록 held-out으로 비교한다. 비용은 두 공급자의 청구 토큰으로 정가와 캐시 반영을 나눠 잰다."
  - "첫 평가"는 "우리가 찾은 범위에서"로 한정하거나 빼는 것을 권장한다. [B1]처럼 가까운 연구가 계속 나오고 있다.
- **C4** 추가 후보: "선행 연구와 달리 프롬프트 캐시를 반영하면 절감이 크게 줄고, 공급자에 따라 역전된다."
  - 선행 연구는 캐시를 반영한 절감을 따로 보고하지 않았다 [A1, A3].

### 3.2 핵심 주장 문장(A안)에 붙일 위치 문장

> 원본을 보존하고 필요할 때 다시 꺼내는 컨텍스트 관리는 텍스트 에이전트에서 제안되었다 [A1, A2]. 본 연구는 이를 이미지 입력과 공급자 청구 토큰으로 확장해, compact와의 관계를 사전 등록 실험으로 측정한다.

### 3.3 §2 관련 연구 구성안

1. 문서·화면 질의 벤치마크(현행 [1]–[4] 유지)
2. 모델 내부 시각 토큰 축소(현행 [5]·[6]에 [B2] 추가). 외부 변환과 같은 개입으로 순위화하지 않는다.
3. 텍스트 프롬프트·검색 압축([C1]–[C5]). 손실 압축 대 원문 발췌
4. **에이전트 컨텍스트 관리([A1]–[A5], [B1]). 새 절이다.** 요약, masking, 가역적 보존, 멀티모달 기록 축소. 우리 S0–S4와의 대응을 표로 둔다.
5. 클라이언트 전처리와 청구 토큰. 학술 연구를 찾지 못했다(`paper/README.md` 2026-10-14 기록, 이번 검색에서도 업체 블로그만 나왔다).
