## 1. 왜 고치는가

처음 목표는 이랬다. compact와 superpowers 워크플로를 보완해 에이전트 작업의 토큰을 줄이는 플러그인을 만들고, 그것을 뒷받침하는 논문을 쓴다.
플러그인 문서는 이 목표를 그대로 담고 있다(README "Superpowers Use", `skills/optimize-context/SKILL.md`, `docs/design.md`의 Superpowers Integration).

현재 논문 초안(`docs/research/image-first-paper-draft.ko.md`)은 "이미지 한 장 + 질문 하나를 API로 보내는 상황"만 다룬다.
에이전트 세션, compact, superpowers와의 관계는 본문에 없다. 그 결과 두 가지가 빠졌다.

1. 에이전트 세션에서는 한 번 들어간 이미지와 로그가 compact 전까지 **매 요청마다 다시 전송되고 다시 청구된다**.
   단일 질의 실험은 이 누적 효과를 재지 못한다.
2. compact는 대화를 손실 요약한다. 그래서 앞 턴의 정확한 세부(작은 글자, 오류 줄)를 잃을 수 있다.
   플러그인의 원본 보존 설계가 바로 이 문제를 겨냥하는데, 논문은 이를 시험하지 않는다.

모은 자료(62편)로 보면 이 빈자리는 실제로 비어 있다.

- 에이전트 컨텍스트 연구(ACON 2510.00615, DTOC 2609.26121, Complexity Trap 2508.21433, ACM 2607.23809)는 모두 텍스트만 다룬다.
- 이미지 crop 연구(2502.17422, 2506.01663 등)는 단일 질의이고 대부분 모델 내부에 접근한다.
- 공급자 청구 토큰을 실측한 학술 연구는 찾지 못했다.

## 2. 새 틀

### 2.1 제목 후보

1. 에이전트 작업 흐름을 위한 원본 보존형 멀티모달 컨텍스트 최적화: 공급자 청구 토큰과 정확도의 실측
2. 컨텍스트 압축을 보완하는 질의 인식 발췌: 에이전트 세션의 텍스트·이미지 토큰 절감과 정확도
3. API 사용자를 위한 black-box 멀티모달 컨텍스트 절감: 원본 보존 발췌와 판독 불가 기반 재요청

리뷰어 의견: 1번. 범위(에이전트, 텍스트·이미지), 원칙(원본 보존), 기여의 성격(실측)이 모두 드러난다.

### 2.2 핵심 주장 (한 문장)

에이전트가 공급자 API로 작업할 때, 텍스트와 이미지 원본을 컨텍스트 밖에 보관하고 질문에 필요한 부분만 출처와 함께 발췌하며, 모델이 판독 불가로 답하면 원본을 다시 주는 방식은, compact의 손실 요약이 잃는 세부를 지키면서 누적 청구 토큰을 줄일 수 있다.
이 주장이 성립하는 범위와 성립하지 않는 범위(공급자, 해상도, 조용한 오답)를 실측으로 보인다.

### 2.3 연구 질문

| RQ | 질문 | 실험 | 현재 근거 |
|---|---|---|---|
| RQ1 | 클라이언트 쪽 변환(resize, JPEG, crop)이 공급자별 청구 이미지 토큰을 얼마나 바꾸는가 | 실험 1: 회계 실측 | pilot-001~003(GPT-4o). Anthropic은 결제 후 |
| RQ2 | 단일 질의에서 질의 인식 발췌 + 판독 불가 기반 원본 재요청이 정확도를 유지하며 토큰을 줄이는가 | 실험 2: 단일 질의 5-arm(기존 프로토콜, Task 34 개정 반영) | pilot-003: clean 89%=89%, 토큰 −25% |
| RQ3 | 다중 턴 에이전트 세션에서 원본 보존 발췌(텍스트·이미지)가 compact 단독·전체 유지와 비교해 누적 청구 토큰과 과제 정확도를 어떻게 바꾸는가 | 실험 3: 세션 실험(새 계획) | 없음. 새로 실행 |

### 2.4 기여

- **C1 측정:** 공급자 2곳(GPT-4o, Claude Haiku 4.5)의 이미지 청구 토큰을 클라이언트 변환별로 실측하고 공개 회계식과 대조한다.
  "픽셀을 줄이면 비용이 준다"는 실무 통념이 성립하지 않는 범위를 보인다(pilot-001: GPT-4o에서 1536/1024 resize 0%).
- **C2 시스템:** 텍스트와 이미지를 같은 인터페이스(원본 색인 → 질의 발췌 → 출처·해시)로 다루는 MCP 플러그인.
  compact를 대체하지 않고 보완하며, superpowers 워크플로에 들어가는 규칙을 갖는다.
- **C3 세션 평가:** 다중 턴 에이전트 세션에서 전체 유지, compact, 플러그인, 플러그인+compact의 누적 청구 토큰과 늦은 턴의 정확한 회상을 비교한다.
  멀티모달 에이전트 컨텍스트를 청구 토큰으로 잰 첫 평가가 목표다.
- **C4 경계와 부정적 결과:** 원본 fallback이 작은 글자에서 안전하지 않다는 점(공급자 내부 축소), 이미 해상도를 잃은 입력에서 발췌가 소용없다는 점,
  조용한 오답의 비율을 그대로 보고한다.

### 2.5 하지 않는 주장

- 새 crop·pruning 알고리즘의 우월성. crop의 정확도 효과는 선행 연구에 있다(2502.17422 등). 우리는 black-box 조건과 청구 토큰을 다룬다.
- 제품 compact(Claude Code, Codex)의 성능 평가. 실험 3의 compact는 공개 규칙으로 재현한 모사이며, 제품 내부 동작과 같다고 주장하지 않는다.
- 영상. 같은 원칙(질의 인식 keyframe 발췌)의 후속 연구로 남긴다(`paper/11-video/`).

## 4. 반드시 다룰 사실 — 프롬프트 캐싱

에이전트 세션의 반복 전송은 공급자의 프롬프트 캐싱으로 할인될 수 있다. 그래서 "매 턴 재청구"를 정가로만 계산하면 절감을 과장하게 된다.
실험 3은 캐시 적용 여부를 고정하고, 캐시된 입력 토큰과 캐시되지 않은 입력 토큰을 따로 기록한다.

- [검증 필요] OpenAI: 1,024토큰 이상 접두부의 자동 캐싱과 캐시 입력 할인. 이미지 포함 여부와 gpt-4o 할인율은 공식 문서로 확인한다.
- [검증 필요] Anthropic: `cache_control` 명시 캐싱. 읽기는 기본 입력가의 일부, 쓰기는 할증. 정확한 배율과 TTL은 공식 문서로 확인한다.
- 보고: 정가 기준, 캐시 적용 기준, 두 값을 모두 보고한다. 캐싱이 있으면 발췌의 이점이 줄어드는지가 RQ3의 하위 질문이 된다.

## 5. 플러그인 개발에 주는 영향

- **이미지 발췌 도구.** 텍스트의 `query_artifact`에 대응하는 이미지 도구(가칭 `query_image_artifact`)를 둔다.
  입력은 아티팩트 ID와 질문이고, 출력은 출처(원본 해시, crop 좌표, 변환 이력)가 붙은 발췌 이미지다. 원본 재요청 경로도 같은 도구로 연다.
  실험 3의 모사 도구가 이 인터페이스의 시안이다.
- **superpowers 연동 규칙.** `skills/optimize-context/SKILL.md`의 Superpowers Integration에 이미지 규칙을 더한다.
  예를 들어 systematic-debugging에서 스크린샷은 원본을 색인하고 발췌로 본다. 작은 글자를 판독할 수 없으면 원본을 다시 요청한다.
- **compact와의 관계.** compact가 대화를 요약해도 아티팩트는 밖에 남는다. 요약에는 아티팩트 ID를 남겨 나중에 다시 발췌할 수 있게 한다.
  이것이 "compact를 보완한다"는 주장의 구체적 형태다.
- 순서: Task 33(encoder probe) → Task 34(guard 개정) 뒤, 실험 3 결과를 보고 이미지 발췌 도구 Task를 연다. 도구 설계는 실험 인터페이스를 따른다.

## 7. 위험

- **모사 compact의 타당성:** 제품 compact의 프롬프트와 시점은 공개돼 있지 않거나 바뀐다. 그래서 공개 규칙으로 모사하고 한계로 적는다. 결론을 "compact 계열 손실 요약 일반"으로 한정한다.
- **도구 호출 변동:** 모델이 도구를 언제 부르는지에 따라 결과가 흔들린다. temperature 0, 고정 지시문, 호출 상한으로 묶고 호출 수를 보고한다.
- **캐싱:** 캐싱 때문에 절감 폭이 작게 나올 수 있다. 그것도 결과로 보고한다.
- **합성 데이터:** 실험 2에 공개 데이터셋 일부(DocVQA, ChartQA, InfographicVQA)를 더하는 계획은 그대로다. 라이선스 확인이 선행한다.
- **범위 확대:** 실험 3이 커지면 일정이 늘어난다. 실험 3은 세션 수를 작게 시작하고(계획 문서 §6), 결과를 보고 늘린다.
