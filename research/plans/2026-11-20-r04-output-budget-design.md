# R04 출력 예산 통제 실험 설계 프로토콜

작성일 2026-11-20 · 기준 main 01a19b521d126bcea4bb469d732be852fe940782
2026-11-20 사용자 결정으로 이번 원고에서는 R05를 실행하지 않는다. RQ3는 기존 모델·하네스·호출 상한에서 관측된 늦은 회상 성능 차이로 한정한다. 출력 예산 또는 검색 도구가 그 차이를 단독으로 일으켰다는 인과 주장은 제외한다. 실험 호출 0건, 실험 지출 US$0. 아래 설계는 향후 별도 연구를 위한 참고안이다.

## 1. 질문과 범위

원질문은 도구를 쓰며 대화 요약을 적용한 S3와 도구 없이 요약한 S1의 늦은 회상 차이가, 호출당 출력 상한(cap)에 따라 어떻게 달라지는가이다. 추정은 동일 제공자 안에서만 한다. 범위는 모사 compact, 과거 연구 버전, 두 모델 스냅샷(gpt-4o-2024-11-20, claude-haiku-4-5-20251001)에 한정한다. 근거는 [R01 주장-근거 지도](../../docs/research/r01-claim-evidence-map.md), [R03 오류 감사](../results/r03-error-audit/README.md), [S3 heldout 결과](../results/s3-heldout/README.md)이며, 구현은 [session-harness](../src/session-harness.mjs), [session-anthropic](../src/session-anthropic.mjs), [session-analyze](../src/session-analyze.mjs), [session-score](../src/session-score.mjs)와 대조한다.

## 2. 기존 실험과 후속 설계

| 항목 | 기존 실험(실적) | R05 제안(설계, 미실행) |
|---|---|---|
| GPT-4o 일반·도구 호출 | 60 | 60 또는 512 |
| Haiku S1 / S3 도구 경로 | 60 / 512(강제 최종·원본 재요청도 512, 기존 하네스에서 확인) | 60 또는 512, 일반·도구 경로에 같은 상한 적용 |
| 요약 호출 | 두 제공자 400 | 400 고정 |
| 비교 | cap이 제공자·경로별로 다름 | 같은 세션을 4셀에 반복 |

cap은 생성 상한이며 실제 출력 길이, 도구 호출 횟수, 세션 총량은 달라질 수 있다. 기존 R03의 표본 일치와 종료 정보만으로는 cap의 인과 효과를 추정할 수 없다. 예전 결과 수치는 새 설계의 효과로 해석하지 않는다. R03 기록에서 GPT 요약 96건은 원본 종료 사유가 기록되지 않았고, Haiku에서 종료 사유가 max_tokens였던 요약은 S1 24/48, S3 1/48이다. 이 집계도 새 설계의 효과 근거가 아니다.

## 3. 처치와 순서

처치: A=S1/60, B=S3/60, C=S1/512, D=S3/512. 턴, 도구 인수, 후속, 강제 최종, 원본 재요청에 같은 명목 cap을 적용하고 요약만 400이다.
표본: 신규 독립 합성 세션 24개(템플릿 3 × 레이아웃 2 × 4). 같은 24개를 두 제공자와 네 셀에 반복해 192회의 세션 실행을 계획한다. 두 모델이 같은 24개를 쓰므로 48개 독립 표본이 아니며, 교차 셀도 독립 관측이 아니다. 세션은 8턴이고 3턴과 6턴에서 요약한다.
층: 템플릿×레이아웃 6개, 층당 4세션. 층마다 4개 순서를 한 세션씩 배정한다.

| 행 | 처치 순서 |
|---|---|
| 1 | A B D C |
| 2 | B C A D |
| 3 | C D B A |
| 4 | D A C B |

이 4행은 각 위치에 모든 처치가 한 번씩 오고, 인접 순서쌍 12개가 모두 다르다. 층 안 세션별 행 배정은 입력 동결 전에 공개한 seed/해시로 정하고, 제공자 선후는 층마다 2:2로 교대한다. 처치마다 독립 대화를 쓴다. 선언된 시간과 캐시 방식을 기록하고, 온도, 모델 스냅샷, 기존 도구 정책, 채점, 예산 외 요소는 동결한다.

동결 순서(모든 실험 호출보다 앞선다): 기존 train/dev/cal/heldout과의 중복 점검 → 생성기 버전, 입력, 채점, 실행 순서, 분석 계획 동결. 새 세션 manifest는 현재 만들어져 있지 않다.

## 4. 추정량과 정밀도

late*는 8턴 중 6, 7, 8턴(3/8)의 회상 문항이며, 동결된 결정적 채점과 고정 문항 분모로 정답률을 구한다. 회상 정확도와 문장 완결성은 구분한다. 완결성은 기술 통계로만 보고한다.
세션별 대비 D_i = (S3−S1)₅₁₂ − (S3−S1)₆₀ = (D−C) − (B−A). 제공자별로 따로 계산한다.
- 층별 평균 D̄_h의 동일 가중 평균 θ̂ = Σ_h (1/6) D̄_h.
- v_h = (1/6)² · s_h² / 4, SE = √(Σ v_h).
- ν = (Σ v_h)² / Σ(v_h²/3), 95% 구간 θ̂ ± t(0.975, ν)·SE (Welch–Satterthwaite 근사).
- 일부 층의 s_h²=0이면 v_h=0으로 두고 계산한다. 모든 층에서 0이면 구간을 추정하지 않고 반폭 기준은 미판정이다.
- 반폭=(U−L)/2는 양 끝점을 절단하지 않은 근사 구간에서 계산한다. 세션 내 차이의 차이가 가질 수 있는 범위는 [−2, 2]이다. 층당 n=4와 이산 점수 때문에 근사가 거칠다.

사전 해석 기준은 반폭 10%p 이하이다. 설계 예시로 층 내 SD가 모두 같다면 v_h=σ²/144, Σv_h=σ²/24, ν=18, t=2.1009이다. σ=.25이면 2.1009×.25/√24≈10.7%p, σ=.50이면 21.4%p이다(보장 또는 실측 아님). 반폭이 10%p를 넘으면 '정밀도 부족'으로 보고하며, 유의성, 부호, 폭에 맞춰 추가 수집하지 않는다. 제공자별 구간은 기술적이고 주변적이다. 통합 또는 다중 유의성 주장은 없다. 24개 고정 탐색 설계이다.
보조 기술 통계: 예산별 S3−S1, 요청 cap, 실제 출력, 종료 분류, 도구 인수 파싱 실패, 완결성, 비용.

## 5. 호출 기록과 종료 분류

호출마다 run, 세션, 제공자, 셀, turn, kind, round, attempt, 실제 snapshot, 요청 cap, usage, 가격 시각, cache, 지연, 도구 파싱 결과, 제공자 원본 finish_reason/stop_reason, 표준 분류, 누락/오류를 기록한다. 응답 직후 raw로 저장하고 중복 키로 이중 기록을 막는다. 실패, 중단, 미시작, 비용 미확인은 서로 다른 상태로 둔다.

| 표준 분류 | OpenAI | Anthropic |
|---|---|---|
| normal | stop | end_turn, stop_sequence |
| limit | length | max_tokens |
| tool | tool_calls | tool_use |
| other | content_filter | refusal, pause_turn |
| unknown | 누락 또는 미등재 값 | 누락 또는 미등재 값 |

원본 값은 모두 보존한다. length는 제공자가 기록한 길이 제한 종료로, 요청 cap과 문맥 한도 중 어느 것이 원인이었는지는 별도로 확인해야 한다. unknown은 추론으로 채우지 않는다. 한도 도달과 도구 전환, 자연 종료를 구분하고, 텍스트 절단은 도구 인수 파싱 실패와 별도 항목으로 기록한다. 공식 레퍼런스: [OpenAI Chat Completions create](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [Anthropic stop reason 처리](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons).
재시도: SDK 자동 재시도는 끈다. 알려진 비청구 전송 전 실패에 한해 1회만 허용하고, 비용 또는 응답이 불명이면 재시도하지 않는다.

## 6. 결측과 실패

- 시작한 셀의 영구 실패: 예정된 late* 중 미응답 문항만 0점이고 이미 응답한 값은 보존한다. 이 복합 지표는 별도로 표시한다.
- 미시작(행정 중단 포함) 셀: 전체 주 대비는 산출하지 않고 완료된 블록만 기술한다. 분모를 밝히고, 결측 셀 점수를 [0,1]로 대입한 세션별 D_i의 최악/최선 범위(전부 결측이면 [−2,2])를 부호에 맞춰 별도 표로 전량 보고한다. 임의 대체는 없다.
- Stop 시 원래의 결측 상태를 보존한다.

## 7. 비용 통제(제안)

R05 하드캡은 최대 30 USD로 제안하며 R04는 지출을 허가하지 않는다. 이 금액은 예상 또는 실측 지출이 아니다. 지난 데이터의 단가로 현재 가격을 단정하지 않는다.

| 항목 | 호출 수 상한 |
|---|---|
| S1 세션 | 일반 8 + 요약 2 = 10 |
| S3 세션 | 8 × (턴 경로 최대 4, 강제 최종 포함 + 원본 재요청 1) + 요약 2 = 42 |
| 전체 | 24 × 2제공자 × (2×10 + 2×42) = 4,992 |

시작 전: 192세션 전부의 최악 비용을 별도 예산표에 합산한다. 셀과 호출 유형별 최대 입출력, 이미지/도구/캐시 write 할증, 요약 400, 누적 문맥, 당시 공식 최고 해당 요율, 청구 불명 보류분을 포함한다. 전액 최악값을 계산할 수 없거나 30 USD를 넘으면 첫 요청 전에 중단하며, 축소/증액은 별도 재설계와 승인이 필요하다. 예상값으로 대체하지 않는다.
실행 중: 단일 순차 요청을 보내기 전에 기청구액, 미정산액(타임아웃 포함), 이미 예약한 별도 금액과 다음 요청의 최악 비용을 더한다. 합계가 30 USD 이하면 다음 요청 금액을 한 번만 예약하고 전송한다. 한 요청은 예약, 미정산, 정산 중 한 상태에만 있고 상태가 바뀔 때 이동할 뿐 합산을 중복하지 않는다. 정산은 실제 사용량으로 하되 명확한 영수증이 없으면 예약을 유지한다. 가격 또는 과금 상한 불명, 로그/동결/양 스냅샷 이상, 한도 소진 시 중단한다. 샘플 완료는 보장하지 않으며 신규 지출, 상한 증액, 모델 대체는 별도 결정이다.

## 8. 향후 연구를 재개할 경우의 시작 조건

제출물: 사전등록 문서(동결 해시, seed, 순서표), 중복 점검 결과, 최악 비용 예산표, 가용성·요율 증빙, 호출 로그 스키마, 분석 계획. 향후 연구를 시작하려면 다음 조건을 모두 충족해야 한다.
1. 생성 입력·채점·순서를 포함해 사전등록하고 동결한다.
2. 연구 실행과 최대 지출액에 대한 별도 승인을 받는다.
3. 두 스냅샷, 해당 출력 한도 파라미터명, 도구·요약 요청의 지원을 확인한다.
4. 당시 공식 요율·통화와 예산 증빙을 기록한다.
5. 192회 세션 전체의 최악 비용이 30 USD 이하임을 확인한다.
6. 로그·예약·오류 중단 장치를 오프라인에서 검증한다.

## 9. 이번 원고에 반영할 해석 범위

사용자는 이번 원고에서 R05 비실행을 선택했다. RQ3에서 보고하는 S3와 S1의 늦은 회상 성능 차이는 당시 두 모델, 하네스 및 출력 상한에서 관측한 값이다. 원고에는 다음과 같이 한계를 명시한다.

> 도구 사용 경로의 출력 상한이 제공자와 조건에 따라 달랐다. 관측된 회상 성능 차이에서 출력 예산과 검색 도구 각각의 인과 효과를 분리해 추정할 수 없다.

이 결정은 현재 원고에 적용한다. 후속 설계에서 제시한 예산과 정밀도는 새 연구를 검토할 때 사용할 기준이다.
