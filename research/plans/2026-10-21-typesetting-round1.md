## 1. 변환 규칙

변환 스크립트가 자동으로 적용하는 규칙(R-)과 사람이 고칠 항목(W-)을 나눈다.

### 1.1 자동 규칙

| 규칙 | 원고 | 투고본 | 근거 |

| R-H 장 | `## I. 서론: 문제와 경계` | "Ⅰ. 서론: 문제와 경계"(스타일 "각 장 제목") | 양식 장 번호는 로마 숫자 글자 |

## 3. 실측 (한글 COM 자동화)

### 3.1 1회차

- 방법: 변환 결과를 양식 사본에 넣는다. 양식 견본 본문(Ⅱ장 제목부터 REFERENCES 앞까지)과 견본 참고문헌을 지우고, 요약·Abstract·Keywords·본문·표·그림·설명·참고문헌을 스타일에 맞춰 넣은 뒤 PDF로 저장한다. 면수는 마지막 쪽의 단별 최저 기준선으로 센다.
- 실행 조건: 한글 "파일 접근 허용" 보안 창을 사용자가 눌러야 하므로, 사용자가 화면 앞에 있을 때 실행한다.
- 결과(2026-10-21, 사용자가 보안 창 허용): **7쪽, 마지막 쪽 82 % → 약 6.8면**

  | 쪽 | 내용 |
  |---|---|
  | 1 | 머리 블록, 요약, Abstract, Keywords, Ⅰ장 시작 |
  | 2 | Ⅰ장 끝, Ⅱ장(표 1), Ⅲ장 시작 |
  | 3 | 그림 1(쪽 맨 위 전단), Ⅲ장 끝, Ⅳ장 |
  | 4 | Ⅴ장(표 2, 그림 2), Ⅵ장 시작 |
  | 5 | Ⅵ장(표 3, 그림 3·4) |
  | 6 | Ⅶ장, Ⅷ장, REFERENCES 시작 |
  | 7 | REFERENCES 끝(27개) |

- §2 추정 6.4면보다 0.4면 크다. 표 셀 줄바꿈과 그림·표 주변 간격, 쪽·단 끝 빈칸이 원인으로 보인다.
- 출처 메모 21개가 PDF에서 모두 빠졌음을 확인했다(남은 "출처" 4건은 본문 낱말 "출처와 함께" 등). 2026-10-21 PR #53 Codex 검토로 개수를 18 → 21로 정정했다.
- 1회차에 반영하지 않은 것: 인용 윗첨자(W-4, 본문이 약간 줄어듦), 참고문헌 이탤릭(W-5), 식별자 글꼴(W-3), 그림 1 설명의 전단 배치(지금은 단 안 두 줄). 모두 ±0.05면 안쪽으로 본다.
- 자동화 메모: 다단 바꾸기(`MultiColumn` 실행)는 실패했다. 그림 1은 `InsertPicture` 뒤 속성 `TreatAsChar=False, TextWrap=1, HorzRelTo=1, HorzAlign=1, VertRelTo=1, VertAlign=0`(쪽 기준 위·가운데, 자리차지)로 두 단 모두 글을 밀어냈다. 문단 기준(`VertRelTo` 문단)으로 두면 기준 단의 글만 밀려 왼쪽 단 글이 그림 밑으로 겹쳤다.
- 8면 목표 대비 약 1.2면 여유가 있다. R5(8.2면 허용)는 필요 없어졌다.

### 3.2 2회차 (2026-10-21)

- 원고: main `6c5bed0`(PR #54 merge본). 변환 스크립트의 수동 확인 항목(커밋 해시·내부 작업명)은 0건이다.
- 1회차에 더해 넣은 것
  - W-4 인용 윗첨자: 본문 인용 묶음([n], [n]–[m], [n], [m])을 윗첨자로 넣고 앞 공백을 지웠다(예: "DTOC[1]와"). 표 셀의 인용은 그대로 둔다. PDF에서 인용 글자 크기는 본문 10 pt 대비 약 6.4 pt다.

  - W-3 식별자 글꼴: 백틱 식별자 20곳을 Consolas로 넣었다(Windows 기본 글꼴, PDF에 포함됨). 다른 글꼴을 원하면 바꾼다.
- 결과: **7쪽, 마지막 쪽 80 % → 약 6.8면**. 1회차(6.82면)와 사실상 같다. 윗첨자로 본문이 줄어든 만큼 이탤릭·식별자 글꼴이 상쇄했다.
- 남은 조판 항목: 그림 1 설명의 전단 배치, 장 제목 부제(W-6), 보충 자료 주소(W-7), 저자 정보(게재본).
