## 2. 질문과 해석 한계

#152에서 같은 행 답 후보 유일성만 본 W3는 유일 후보가 다른 필드의 값일 때 답을 잃었다(요청서 요약). 이번 질문은 "**OCR 열 머리글을 질문한 필드명과 연결하면**, 오른쪽으로 넓힌 창 W1에서 W2로 자를 때 **표지·정답 잉크의 기하적 보존**과 **다른 레코드 질문 필드 값의 제외**를 함께 달성할 수 있는가"다.

- **'답 보존'은 기하 지표다.** 엄격 성공 = 창이 부분 페이지이고 표지·정답 잉크를 여유 0으로 완전 포함. 같은 줄에 같은 레코드의 경쟁 값이 남으면 엄격 성공만으로 W4가 맞는 열을 골랐는지 알 수 없다. 그래서 (a) 적용 쪽의 선택 표제·후보를 **예측 동결 뒤** gold 셀·잉크에 귀속하고, (b) 창에 남은 두 머리글과 경쟁 값의 잉크 관계를 따로 잰다(5.4–5.6절).
- **'불필요한 값 제외'는 다른 레코드 질문 필드 값에만 해당한다.** W4가 W2를 고르면 같은 레코드의 경쟁 값은 창에 남을 수 있다(같은 줄 설계). 경쟁 값은 J 사건에 섞지 않고 full/partial/none으로 따로 보고한다.
- 대상은 세로 괘선 없는 왼쪽 정렬 한글 표와 `<기록명>의 <필드명>은/는 몇 시/명/쪽인가요?` 형식의 질문이다. 표에서 얻은 결과를 카드나 자유형 문서의 근거로 쓰지 않는다. 사람이 표를 읽고 답하는 정확도, 토큰·비용 절감은 재지 않는다.
- 자료는 12원본 × 12변형의 짝지은 설계다. 관찰 단위는 쪽이지만 같은 원본의 12쪽은 질문·답·레코드 텍스트를 공유하므로 144개 독립 사례가 아니다. 결과는 이 합성 분포와 고정 O1 OCR 한 번에 대한 **기술 통계**다. 추론 검정·신뢰구간·일반화·상위 그룹 인과 주장을 하지 않는다. 각 셀은 12원본이며 원본 수를 함께 쓴다.
- 양성 결과도 제품 일반화나 기본값 채택이 아니다(사용자 결정). 실험으로 제품을 자동 변경하지 않는다.

## 3. 새 자료

### 3.1 구성 (12원본 × 12변형 = 144쪽, 등록 생성기가 결정)

- 문서 종류 3개: `library` 도서관 자료 이용 예약표, `sports` 생활체육 시설 운영표, `culture` 문화행사 운영 지원표. 종류마다 독립 내용 4개(c0–c3). 원본 ID `<종류>-c<내용>`.
- **3×3 배정(고정):** 종류 행 × 유형 열(시각 time / 인원 count / 분량 pages)의 원본 수 = library (2,1,1), sports (1,2,1), culture (1,1,2). 유형마다 4원본.
- 원본마다 레코드 3개(슬롯 0/1/2 = 위/가운데/아래). **목표 슬롯은 4/4/4**, 유형 안에서 time (2,1,1), count (1,2,1), pages (1,1,2). "질문할 의미 필드"의 균형: 각 원본의 같은 형식 필드 쌍(자연 순서: 방문/반납, 입실/퇴실, …)에서 질문 필드가 앞 이름인 원본 6개, 뒤 이름인 원본 6개. 목표 열의 좌우는 아래 변형으로 모든 원본에서 완전 교차한다.
- **변형 3요인(원본 안 완전 교차, 12개):** (1) `side` = L(질문 필드 열이 왼쪽 값 열) / R(오른쪽 값 열) — 두 값 열의 머리글과 데이터 전체를 함께 교환, 두 열의 폭이 같아 좌우 여백·열 폭·기록 간 간격이 같다. (2) `header` = normal(두 필드명이 다름) / blank(질문 필드 열의 머리글만 텍스트 없음) / dup(두 값 열 머리글이 모두 질문 필드명). 첫 열(기록명 열)의 머리글과 데이터 의미는 유지. (3) `ans` = same(질문 필드 값이 표지 줄 A) / below(한 줄 아래 줄 B). 경쟁 필드의 같은 형식 값은 항상 줄 A, 경쟁 열의 보조 문구는 줄 B. 질문 필드 열 안에서 정답이 다른 형식의 보조 문구와 자리를 맞바꾼다. 모든 레코드가 같은 `ans`를 따른다.
- 셀 이름 `<side>-<header>-<ans>`(12셀, 셀마다 12원본). 내부 키 `<원본 ID>-<셀 이름>`, 일련번호 `serial` 0–143(원본 → side → header → ans 순서).
- **불투명 ID(등록 순열):** `random.Random("ko-header-column|opaque-ids|v1").shuffle(range(144))`의 결과 `order`로 serial i의 ID = `p{order[i]:03d}`, 파일 `p###.png`. 선택기 측 `questions.json`은 ID 순서. 키↔ID 대응 전체가 `registered/design.json`에 있다. 예측 구현은 ID를 읽어 분기하지 않는다(시험: ID 치환 불변). 이미지에는 변형·정답을 드러내는 텍스트·워터마크가 없다.

### 3.2 페이지 문법과 좌표 (원본 픽셀, 반열림 `[x0, y0, x1, y1)`)

- 페이지 1280 × 960, 흰 바탕 L 모드. 글꼴 `NotoSansKR-VF.ttf`(시스템 설치본, SHA-256 `018174e8…8353d0`, 가중치 400, 본문 24, 제목 32). 렌더러 `research/tools/r09/render.py`(main blob `b61cd9b37803d8eb4b6b126a75301570c14ab11d`, SHA-256 `279a5abe…ab663052`)를 **수정 없이** 쓴다. 텍스트는 셀 왼쪽 +12px, 셀 세로 중앙. 렌더러는 항목마다 검은 L 마스크에 텍스트를 그리고 0 초과 픽셀 전체를 Pillow `getbbox()`로 감싼 **반열림 잉크 상자**를 `render.json`에 기록한다. 이 원래 잉크 상자가 모든 잉크 측정의 기준이다. 글꼴은 저장소에 넣지 않는다.

### 3.3 텍스트 규칙 (생성기 `check`, 문제 0이어야 함)

- 값 문법: time `H:MM`/`HH:MM`(9–20시, 10분 단위), count `N명`(8–95), pages `N쪽`(12–240). 한 쪽의 질문 필드 값 3개와 경쟁 필드 값 3개, 6개 텍스트는 서로 다르다.
- 값 외 어떤 항목도 어떤 유형 문법에도 맞지 않고 ASCII 영숫자가 없다. **머리글 외 어떤 항목에도 `시각`·`인원`·`분량`이 들어가지 않는다**(OCR 그룹 오인 방지). 필드명은 `<한글 구분어> <끝말>` 형식이고 두 필드명은 다르다.
- 12개 질문은 서로 다르고 원본마다 12쪽에 같다. 질문에 목표 표지 정확히 1회, ASCII 영숫자 없음(K0 정상 미매치 → 한글 분기). 목표 표지 한글 bigram ≥ 4. 목표 외 어떤 항목도 목표 표지와 bigram 공유 없음. 머리글·제목 외 항목은 질문과 bigram 공유 없음, 머리글·제목은 ≤ 2, 기록명 열 머리글은 0.
- **등록 질문 단위시험(이미지·OCR 없이):** 12개 질문 모두 고정 #152 `questionTypes`가 설계 유형 하나를 돌려주고, 새 파서(4.2절)가 (목표 표지, 질문 필드명, 같은 유형)을 돌려준다.
- 한계(공개): 질문 형식이 하나뿐이고 필드명이 `구분어 + 끝말` 형식에 한정된다. 필드명 사전·별칭·유사 매칭은 쓰지 않는다.

### 3.4 이상적 인식의 기하 예측표 (등록, 기댓값·통과 조건 아님)

**가정:** OCR이 각 셀 텍스트를 정확히 읽고 머리글 줄을 한 줄 3그룹으로 내며, K1이 목표 표지 줄을 고르고, 비고가 별도 줄이라 W1이 넓어져 W2가 실제로 자르며(`cut`), 다른 같은 행 후보가 없다.

| header | ans | 표지 행 같은 형식 후보 | 이상적 W3 | 이상적 W4 | 기대 |
|---|---|---|---|---|---|
| normal | same | 질문 값 + 경쟁 값 | `multiple_candidates` → W1 | 질문 열 후보 1개 → `applied`(W2) | W2와 같은 제외 효과, 손실 없음, 경쟁 값은 남음 |
| normal | below | 경쟁 값(유일) | `applied` → W2, **답 손실** | 경쟁 열에만 배정 → `no_target_candidate`(W1) | W3 손실 예방 |
| blank | 둘 다 | 위와 같음 | 위와 같음 | 머리글 2그룹 → `header_none`(W1) | 이상적 보류 |
| dup | 둘 다 | 위와 같음 | 위와 같음 | 두 표제 모두 일치 → `header_duplicate`(W1) | 이상적 보류 |

- **설계상 예상되는 읽기 근거 악화:** 기준 띠(표지 잉크 한 단어, 패딩 = 그 높이) 계산에서 머리글 잉크는 모든 쪽에서 W2형 띠 밖이다. 목표 슬롯 0 원본(4개)은 표지 줄 위 3줄 높이를 포함하는 W1에 머리글 줄이 들어갈 수 있으므로, normal-same에서 W4가 W2를 고르면 "W1에 보이던 온전한 목표 표제가 사라지고 경쟁 값은 온전히 남는" 새 사건이 생길 수 있다. 이것은 결과에 맞춰 바꾸지 않는 등록 기하의 성질이다.
- 공란·중복에서 적용 0은 설계상 예상된다. 이것은 보존 기전 검증이 아니며, 관찰한 보류 사유(OCR이 표제를 놓침·추가 그룹·줄 분할·K1이 머리글 줄 선택)와 이상적 보류를 구분해 보고한다.

### 3.5 생성·렌더 뒤 OCR 전 검사와 자료 분리

생성 `python research/tools/ko-header-column/design.py --out <G> --font <글꼴>`(출력이 `registered/`와 바이트 동일해야 함) → 렌더 `python research/tools/r09/render.py --design <G>/design.json --font <글꼴> --out <G>` → 배치 `node src/ko-header-column-data.mjs assemble --from <G> --data <data>`(선택기 측 `data/selector/`: `questions.json`, `images/`; 채점 측 `data/scoring/`: `design.json`, `gold.json`, `render.json`, `render-check.json`) → 검사 `node src/ko-header-column-data.mjs check --data <data>` → `data/checks.json`. 생성·사전 검사는 gold를 쓴다(채점과 구분). 전부 통과해야 동결한다.

1. 렌더 유효: `failedImages = 0`, 골드 2개 = (목표 표지, 목표 값), 잉크가 셀·페이지·인쇄 영역 안, 잉크 겹침·괘선 겹침 없음.
2. 배정: 144쪽 격자와 불투명 ID가 `registered/design.json`과 같음, 3×3·슬롯 균형, `selector/questions.json`이 design과 같은 ID 순서·질문.
3. 유일성과 짝: 144개 PNG SHA-256 서로 다름. 정규화 질문 12개가 각 12회이고 같은 원본에만. **독립 짝 검사**(렌더 잉크 기준): 원본 12쪽의 질문·정답·레코드 항목 텍스트·역할·잉크 높이·기록명 열과 비고의 잉크 x가 같고, 값 열 항목의 잉크 x는 side별로 열 이동량(260px)만큼만 다르며, 줄 A/B를 바꾸는 항목(`tval`, `taux`)의 y만 ans별로 다르다. 머리글: normal 3개(`h-target` = 질문 필드, `h-comp` = 경쟁 필드), blank 2개(`h-target` 없음), dup 3개(두 텍스트 = 질문 필드). 좌우 짝(같은 원본·header·ans)의 L/R 쪽은 값 열 잉크 x만 서로 교환된다.
4. 3.2절 측정과 허용치(렌더 잉크로 다시), 3.4절 이상적 같은 행 후보·이상적 머리글 배정(잉크 왼쪽 차 ≤ 머리글 잉크 높이, 다른 열과는 초과)·기준 띠 노출 기록.
5. 유형·문법·끝말 규칙(3.3절).
6. 기존 자료와의 겹침(숫자 보고): R09 heldout·dev(`0fb3053…`), FCP 48쪽(`708d9946…`), #148 96쪽(`2ab9ed14…`)과 #149 코호트 24 ID(`fd7ba06e…`), #150 48쪽(`b108e2f0…`), #151 48쪽(`d75f5455…`), **#152 48쪽**(`6865828f…:research/results/ko-row-gate/data/selector`, `questions.json` blob `3468afb6…`, `images` tree `733f4587…`). PNG SHA-256 겹침 0, 정규화 질문 겹침 0이어야 한다.
7. 결정성: 생성·렌더·배치를 두 새 폴더에서 각각 실행해 모든 파일 바이트가 같다.

- 실패하면 OCR 없이 원인·수정·해시를 인계서에 남긴다. 자료 유효성 결함만 OCR 전에 고친다. OCR이 실패하거나 변별력이 낮아도 문서를 교체·추가하지 않는다. 실험 OCR을 미리 돌리지 않는다.
- **자료 동결 커밋:** `data/` 전체와 파일별 SHA-256 `data/manifest.json`을 첫 OCR 호출 전에 커밋·push한다.

### 4.2 W4 (등록 규칙, `RECOUNT_SPEC.md` 4절이 정의)

요약(순서가 사유 우선순위다):

1. 오류·미매치 → 그대로(`w4 = null`, 사유 `error`/`unmatched`). `w2Reason ≠ "cut"`(W2가 W1을 실제로 좁히지 않음) → `not_applicable`, W4 = W1. 고정 W3의 `qtypes` 길이 0 → `qtype_none`, 2 이상 → `qtype_multiple`, 유효 히트 0 → `no_valid_hit_word`. 이들은 W1.
2. **질문 파싱:** NFKC 후 Unicode White_Space 연속을 공백 하나로 바꾸고 양끝을 자른 문자열 전체가 정규식 `^(?<record>.+)의 (?<field>[가-힣]+(?: [가-힣]+)* ?(?<suffix>시각|인원|분량))(?<josa>은|는) 몇 (?<unit>시|명|쪽)인가요\?$`에 맞고, `"의 "`가 정확히 한 번이며, 끝말과 단위가 시각↔시, 인원↔명, 분량↔쪽으로 같은 유형일 때만 성공. 실패 → `question_unparsed`. 파싱 유형 ≠ 고정 W3 단일 유형 → `question_type_mismatch`(12개 등록 질문 형식에서는 도달 불가, 방어 분기). 예: "가을 수영 강습의 접수 시각은 몇 시인가요?" → 기록명 "가을 수영 강습", 필드 "접수 시각", time.
3. **머리글 줄 탐지:** 표지 기준 y = 고정 W3의 유효 히트 단어(`validHits`)의 원래 상자 위 y 중 최솟값. 전체 OCR의 줄마다(줄을 합치지 않음, K1 줄 번호 제외) 모든 단어가 유효 반열림 상자(4개 수, 폭·높이 > 0)와 비지 않은 `squash` 텍스트를 갖고 모든 단어 아래 y ≤ 기준 y인 줄만 후보다. 단어를 (x0, x1, 원래 인덱스) 순으로 정렬하고, **직전 단어**의 x1에서 다음 단어 x0까지의 간격이 두 단어 높이 중 큰 값의 **2배 초과**일 때만 그룹을 나눈다(정확히 2배·음수는 같은 그룹, 그룹 누적 폭은 쓰지 않음). 그룹 텍스트 = 구성 단어 `squash` 텍스트를 정렬 순서로 이은 것, 그룹 상자 = 반열림 합집합 외접 상자.
4. **자격:** 정확히 3그룹, 첫 그룹 `^[가-힣]+$`, 뒤 두 그룹 각각 `^[가-힣]+<끝말>$`(끝말 = 파싱 유형의 시각/인원/분량, 앞에 한글 1자 이상), 세 그룹 상자끼리 x축에서 양의 폭으로 겹치지 않음. 자격 줄 0개 → `header_none`, 2개 이상 → `header_multiple`(가까운 줄을 임의로 고르지 않음). 정확히 1개면 뒤 두 그룹 텍스트를 `squash(질문 필드명)`과 전체 비교: 둘 다 같음 → `header_duplicate`, 둘 다 다름 → `header_no_match`, 정확히 하나 같음 → 그 그룹이 **목표 머리글**, 다른 하나가 경쟁 머리글.
5. **열 배정:** 고정 W3 `scan.units`의 각 후보 단위(순서 그대로)의 왼쪽 x0(합집합 상자 x0)와 두 머리글 그룹 상자 x0의 거리(절댓값)를 비교해 **더 짧은 쪽에만**, 그 머리글 그룹 높이(y1 − y0)의 **1배 이하**(등호 허용)일 때만 배정한다. 동률은 `tie`(미배정), 가까운 쪽이 1배 초과면 `too_far`(미배정). 목표 열 배정 0개 → `no_target_candidate`, 2개 이상 → `multiple_target_candidates`, 1개지만 그 합집합 상자가 W2에 완전히 들지 않음 → `target_outside_w2`, **1개이고 W2 안 → `applied`, W4 = W2.** 나머지는 모두 W1. W3 후보가 여럿이어도 목표 열 배정이 하나면 적용할 수 있고, 하나뿐인 후보가 경쟁 열이면 W1이다.
- 모든 비교는 동결 OCR JSON의 **원래 수 표기를 정확한 유리수**로 한 것이다(부동소수점 없음, 경계 등호 포함). W2 좌표는 고정 구현이 직렬화한 정수다.
- 출력(`predictions.jsonl`의 W4 필드): 사유, 출처(W1/W2), 창, 잘린 픽셀, 파싱 결과, 기준 y, 후보 줄별 그룹(단어 인덱스·텍스트·좌표)과 자격 실패 이유, 선택 줄·목표/경쟁 그룹, 후보 단위별 거리·배정·이유, 배정 수(목표·경쟁·미배정), 선택 후보. 진단은 적용 대상이 아닌 쪽에서도 입력이 허락하는 데까지 기록하되 판정은 위 순서만 쓴다.
- W4는 항상 W1 또는 W2와 같다. 사후 단언: `W4 ∈ {W1, W2}`, `W2 ⊆ W4 ⊆ W1`, `applied ⇔ W4 = W2`.
- **입력 제한:** W4 함수의 인자는 질문, 동결 OCR 줄(정확 표기), 동결 K1 기록, 고정 W2 결과, 고정 W3 결과뿐이다. ID·변형·정답·렌더·gold는 인자가 아니다(시험: 인자 수, ID 치환 불변).

## 5. 채점과 보고 지표 (`RECOUNT_SPEC.md` 5–7절이 정의)

- 5.1 **엄격 성공**(#147 `scoreKey` 그대로, W1/W2/W3/W4 각각): 정상 매치, `0 < 면적 < 페이지 면적`, 표지·정답 잉크 전체 포함.
- 5.2 **손실·회복:** 전이 W1→W2, W1→W3, W1→W4, W3→W4. **L2, L3, L4** = W1 엄격 성공에서 실패로 바뀐 쪽 / W1 엄격 성공 수(공통 분모), 서로 다른 원본 수와 원본별 손실. L3 중 L4가 피한 손실(`prevented34`, 분모 L3), W3→W4 새 손실(분모 W3 성공)과 회복(분모 W3 실패). 불변식: L4 ⊆ L2.
- 5.3 **다른 레코드 값 제외(J):** 공통 기회 = 매치 ∧ W1 엄격 성공 ∧ W2 `cut` ∧ W1 안에 `otherValueItems` 중 하나 이상 완전 포함. Jk = 기회 중 Wk 엄격 성공 ∧ W1에서 완전했던 그 값 중 하나 이상이 Wk와 교집합 0(맞닿음 포함). k = 2, 3, 4. 쪽 수와 서로 다른 원본 수, 좌우·머리글·답 행 셀별. 불변식 J4 ⊆ J2.
- 5.4 **gold 귀속(예측 동결 뒤, 적용 쪽 전부):** 선택한 목표 머리글 그룹의 원래 OCR 단어(줄·인덱스·상자)와 선택 후보 단위의 단어 각각에 대해, 모든 구성 단어 중심이 같은 단 하나의 렌더 텍스트 항목 셀 안(왼쪽·위쪽 포함, 오른쪽·아래쪽 제외)에 있고 그 단어들의 외접 상자와 그 항목 잉크의 교집합이 양의 면적일 때만 그 항목으로 확정한다. 머리글 분류: `target_header`(`h-target`) / `comp_header`(`h-comp`) / `other_item` / `undetermined`. 후보 분류: `target_value` / `comp_value`(같은 레코드 경쟁 값) / `other_record_value`(다른 레코드 질문 필드 값) / `other_record_comp`(다른 레코드 경쟁 값) / `other_item` / `undetermined`. **정상 머리글 적용 쪽(좌우 각각 분모 표시)에서 머리글·후보 모두 맞음 = 100%이고 오선택 0·미확정 0**이어야 기하 필요조건의 이 항목을 충족한다. 분모 0은 "해당 없음"이며 통과로 보지 않는다. 공란·중복 적용 쪽도 같은 귀속을 공개한다.
- 5.5 **잘린 표에 남은 정보(창 W1–W4 각각, 144쪽 모두):** 의미상 목표 열 머리글(`h-target`; blank는 `source_missing`, 빈 상자를 만들지 않음), 경쟁 열 머리글(`h-comp`; dup에서는 같은 문자열의 별도 물리 셀), 같은 레코드 경쟁 값(`compValueItem`), 목표 값(`valueItem`)의 잉크 관계: 원래 잉크 상자가 창에 완전 포함 → full, 아니면서 양의 면적 교집합 → partial, 나머지(맞닿음 포함) → none.
- 5.6 **읽기 사건(정상 머리글만):** E1 = 목표 표제 none ∧ 경쟁 값 full. E2 = 목표 표제 partial/none ∧ 경쟁 값 partial/full. Wk(k = 2, 3, 4)마다 W1 대비 새로 생김·이미 있음·해소를 쪽과 서로 다른 원본 수로. 별도 표시: W1에서 목표 표제 full이던 쪽이 Wk에서 none이고 경쟁 값 full. 공란·중복은 원본 자체의 의미 단서 부재·중복이므로 같은 사건 집계에 합치지 않고 노출표만 공개한다. **공란·중복의 기하적 정답 보존(엄격 성공)과 "사람이 글자만으로 필드를 식별할 수 있음"(정상 머리글만 참)을 구별해 표시한다.** 모든 크롭에서 역할을 gold가 알려준다는 사실은 사람이 그 역할을 볼 수 있다는 뜻이 아니다.
- 5.7 **면적:** 감소 %p = 100 × (W1 면적 − Wk 면적) / 페이지 면적을 유리수로 계산해 분모(매치 쪽, W4 적용 쪽)의 산술 평균을 먼저 낸다. 기계 파일은 분자·분모를 보존한다. 공개 표에서만 양수 기준 0.005면 올리는 일반 반올림으로 소수 둘째 자리.
- 5.8 **분리 표:** 전체, 오류·미매치, W2 `cut`, W4 사유별, side, header, ans, **교차 12셀**, 문서 종류, 유형, 목표 슬롯, **12원본 × 12변형 표**(원본별 손실·적용), 상위 원본 집중(J4·적용·L4의 원본별 최대 비중), **좌우 불일치**(같은 원본·header·ans에서 L/R의 W4 사유·적용·엄격 성공이 다른 짝). 차이가 없는 경우와 분모 0을 그대로 둔다.

### 5.9 측정 전 판정 기준 (요청서 그대로, 등록)

- 입력 무결성과 A/B 일치가 전제다. OCR 오류가 있으면 그 수와 분모 144를 표시하고 해석을 관찰 가능한 쪽으로 한정한다.
- **기하 필요조건(모두 충족해야 통과):** (G1) 전체 L4 = 0. (G2) 물리적 공란·중복 쪽의 실제 W4 적용 0. (G3) 정상 머리글의 **각 좌우 순서**(L, R)에서 J4 사건이 서로 다른 원본 2개 이상. (G4) 정상 머리글 적용 쪽의 gold 귀속 정답 100%, 오선택 0, 미확정 0(분모 0이면 미충족). 하나라도 미달이면 그 사유를 기록한다. 적용 0은 보존 기전 검증으로 해석하지 않는다.
- **읽기 근거 악화:** 정상 머리글에서 W4가 W1 대비 새로 만든 E1 사건이 1건 이상. 정상 머리글의 비교 쪽(W1·W4가 모두 있는 매치 쪽)이 0이면 **평가 불가**이며 악화가 없다는 근거로 세지 않는다.
- **최종 2×2 판정표(공개):**

| | 새 읽기 근거 손실 0 | 새 읽기 근거 손실 있음 |
|---|---|---|
| 기하 필요조건 통과 | 이 조건에서만 후속 검토 가능 | 기하는 충족했지만 읽기 근거 악화로 권고 보류 |
| 기하 필요조건 미통과 | 기하 성과 미충족 | 둘 모두 불리 |

  읽기 판정이 평가 불가면 표의 해당 칸 대신 "기하 (통과/미통과) · 읽기 평가 불가"로 기록한다. 판정 코드는 `RECOUNT_SPEC.md` 7절 규칙으로 기계적으로 만든다. 연구 판정과 제품 채택은 별개다.
