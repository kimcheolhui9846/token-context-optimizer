## 2. 분량 추정 (한글 실측 보정)

### 2.1 계산 방법과 보정

- 줄 수: 241.9 mm ÷ (10 pt × 160 % = 5.64 mm) → **단당 42줄, 면당 84줄**
- **줄당 글자 수 30.4자(실측).** 2026-10-20 한글 프로그램으로 직접 쟀다.
  - 양식 사본의 서론 "본문" 문단에 원고 I장을 넣고 PDF로 저장했다. 한글 COM 자동화(`HWPFrame.HwpObject`)를 썼다. 저장한 PDF에서 글자 기준선을 세었다.
  - I장 25문단(2,166자) → **82줄**이다. 같은 글을 문단 사이에 공백 한 칸을 넣어 한 문단으로 합치면 2,190자(공백 24개 추가)이고 72줄이다. 줄당 2,190 ÷ 72 = **30.4자**(공백 포함)다. 끝 줄이 덜 찼을 수 있으므로 하한이고, 상한은 2,190 ÷ 71 = 30.8자다. 기준선 간격은 16 pt로 양식 값과 같다.
  - 양식 수치로 계산한 첫 추정은 35.8자였다(반각 = 전각 절반 가정). 실측이 15 % 적다. 아래 값은 모두 실측 30.4자로 다시 계산했다.
  - 검증: 줄당 30.4자와 "문단 끝 줄을 한 줄로 셈" 규칙을 쓰면 I장 25문단 예측이 82줄로 실측과 같다(30.0자면 83줄, 30.8자면 80줄). 하한값 30.4자를 쓰므로 분량 추정은 보수적인 쪽이다.
- 연속 문장 기준 **면당 약 2,550자**다.
- 문단·목록: Markdown의 문단과 목록 항목마다 마지막 줄을 한 줄로 센다. 위 실측도 목록을 그대로 둔 상태다. 논문체 문단으로 합치면 I장 기준 약 12 % 줄어든다(82 → 72줄).
- 제목: 장·절 제목은 각 2줄로 센다. 표는 행당 1.5줄에 설명·간격 3줄을 더한다(표·제목은 아직 실측하지 않음).

- 남은 오차: 본문·요약·참고문헌은 실측으로 맞췄다(요약·참고문헌은 §2.2). 표·그림·제목·키워드는 양식 수치로 계산한 값이다. 학회 게재 폰트가 양식 기본 폰트와 다를 수 있다(양식의 "폰트문제" 안내).

## 3. hwp 조판 체크리스트 (투고 직전)

### 3.1 구조와 번호

- [ ] 장 번호는 로마 숫자 글자 "Ⅰ."이고, 장 제목은 양식처럼 글자 사이를 띄운다("서  론"). 원고의 "I. 서론: 문제와 경계" 같은 부제는 유지할지 정한다.
- [ ] **절 번호 "6.1" → "1."**: 양식은 장마다 절을 1부터 매긴다. 원고의 "2.1"–"6.3"을 모두 바꾼다. 항은 "가.", 그 아래는 "(1)"이다.
- [ ] 구성 순서: 국문요약 → Abstract(하단 Keywords) → 본문 → 부록 → REFERENCES
- [ ] Keywords 5개 이하, 각 keyword의 첫 문자만 대문자

### 3.2 심사용 원고

- [ ] **저자명·소속·교신저자·Acknowledgment 각주를 지운다.** 양식에 "심사용 논문에서는 삭제"가 세 곳 있다. 저자를 가리는 심사로 보인다.
  - 형식 메모 §3의 미결 문제와 연결된다. 공개 GitHub 저장소에 같은 초안과 저자 이름이 있으면 익명성이 깨질 수 있다. 교수님께 문의할 때 이 점을 함께 묻는다.
- [ ] 머리말의 "20**년 **월 전자공학회논문지 제**권 제**호"와 "논문 20**-**-*-*"는 수정하지 않는다(양식 안내).

### 3.3 그림·표·수식

- [ ] 그림 설명은 그림 아래, 표 설명은 표 위에 둔다. 국문 줄 다음에 영문 줄을 두고, 끝 마침표는 지운다.
- [ ] 그림 폭은 반단 7 cm, 전단 14 cm다(현재 PDF와 같다). 최소 글자 6 pt는 PR #36 M-1에서 맞췄다.
- [ ] 수식 번호는 줄 끝 "(1)"이다.
- [ ] Markdown 표는 hwp 표로 다시 만든다. 셀 글자 크기는 양식에 지정이 없다. 9 pt를 권장한다(그림 설명 9.5 pt보다 작게, 확인 필요).

### 3.4 본문 표기

- [ ] 인용 번호는 윗첨자 [n]이다(작성요령 "인용문 우측 상단").
- [ ] 백틱으로 쓴 식별자(`query_artifact` 등)의 글꼴을 정한다. 양식에는 규정이 없다. 고정폭 글꼴 하나로 통일할 것을 권장한다.
- [ ] 본문의 URL·저장소 경로는 참고문헌이나 부록으로 옮긴다. 저장소 경로는 심사용 익명성(§3.2)과도 관련된다.
- [ ] Markdown 목록은 논문체 문단으로 바꾼다. 분량도 줄어든다(§2.1).
- [ ] 영문(제목·Abstract·그림 설명)은 sentence case다(투고규정 6, 양식 예시).

- **결정 R5(2026-10-20 사용자 승인: (다)): 참고문헌 초과 0.25면 처리**
  - (가) 8면 목표 안에서 본문을 0.18면(약 460자) 더 줄인다.
  - (나) 웹 문서 [14]–[24]를 공급자별로 묶는다(예: OpenAI 3건 → 1건). 인용 위치가 달라 묶으면 근거가 흐려진다.
  - (다) 8.2면을 허용한다. 9면 미만이라 게재료 구간은 같다(형식 메모 L25).
  - 결정: (다). 조판 1회차 실측 뒤 다시 본다. 이 값은 아직 추정이고, Task 38 진행 중에 상한을 바꾸면 Codex 작업이 흔들린다.
- 표·그림·제목·키워드는 아직 실측하지 않았다. Task 38 뒤 조판 1회차에서 전체를 양식에 옮긴 다음, 실제 면수와 §2.3을 대조한다.
- 자동화 메모: 2026-10-20 2차 시도는 화면에 보이지 않는 대화상자에서 멈췄다. 3차는 창을 띄워(`Visible`) 성공했다. 4차(표 실측)는 한글의 "파일 접근 허용" 보안 창에서 멈췄다. 보안 창을 대신 누르지 않고, 직접 띄운 인스턴스만 종료했다. 표 실측은 보안 모듈 등록 문제를 해결한 뒤 하거나 사용자가 직접 조판할 때 한다.
