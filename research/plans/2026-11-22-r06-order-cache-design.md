# R06 조건 순서·prefix 캐시·시간 효과 설계 프로토콜

작성일 2026-11-22 · 기준 main 459a509caeb16b3a3b2559bf94cadde1dc942437
2026-11-22 사용자 결정(A안)으로 이번 원고에서는 R07을 실행하지 않는다. D01에서 원고에 순서·캐시 관련 관측 사실과, 순서·캐시가 결과에 준 인과 효과의 방향과 크기를 식별할 수 없다는 한계를 기록한다. R06 실험 호출 0건, 실험 지출 US$0. 아래 후속 설계는 향후 별도 연구를 위한 참고안이며 실행을 허가하지 않는다.

## 1. 질문과 범위

기존 실험 3은 세션마다 조건을 S0, S1, S2, S3, S4 순서로 고정해 실행했다. 질문은 두 가지다. 첫째, 이 고정 순서에서 순서, 제공자 prefix 캐시, 시간 효과를 얼마나 구분할 수 있는가. 둘째, 구분하려면 어떤 후속 설계가 필요한가.

추정은 같은 제공자 안에서만 한다. 범위는 두 모델 스냅샷 gpt-4o-2024-11-20과 claude-haiku-4-5-20251001이다. 근거는 [R01 주장-근거 지도](../../docs/research/r01-claim-evidence-map.md), [S3 heldout 결과](../results/s3-heldout/README.md), [GPT-4o 호출 기록](../results/s3-heldout/gpt4o/calls.jsonl), [Haiku 호출 기록](../results/s3-heldout/haiku/calls.jsonl)이다. 구현은 [session-harness](../src/session-harness.mjs), [session-anthropic](../src/session-anthropic.mjs), [sessions](../src/sessions.mjs), [session-analyze](../src/session-analyze.mjs)와 대조한다. 형식은 [R04 설계](./2026-11-20-r04-output-budget-design.md)를 따른다.

### 2.1 조건 간 캐시 이월(새 관측, 기술 통계)

- Haiku: 판정 기준은 호출의 캐시 읽기가 같은 시도에서 그 전까지 쓴 캐시 토큰 누계보다 많은지다. 넘는 양을 "초과 읽기"라 한다. 이 기준에 걸린 시도는 S1 24/24(초과 읽기 409,666토큰. S1의 캐시 읽기 합과 같고, S1 자체 쓰기는 1,128토큰), S3 5/24(초과 읽기 168,859토큰, 같은 5개 시도의 읽기 합 169,492토큰)다. S0·S2·S4는 0이었다. 기록과 prefix 구조로 보아 S1은 직전 S0가 쓴 prefix를, S3 일부는 직전 S2가 쓴 prefix를 읽은 것으로 판단된다.
- GPT-4o: S1 2턴 호출의 14/24가 캐시를 읽었다. 14건 모두 읽은 캐시 토큰이 같은 시도의 1턴 프롬프트 전체보다 많다. 그러므로 읽은 prefix는 그 시도가 앞서 보낸 요청에서 만들어질 수 없다. 결과에 포함되지 않은 이전 시도 호출 7건은 모두 heldout-document-review-4의 S2 시도이고, S2는 다른 시스템 프롬프트와 도구 정의를 쓴다. 기록상 S1과 같은 앞부분을 먼저 보낸 요청은 같은 세션의 S0뿐이다. S0 2턴과 S4 2턴의 캐시 읽기는 각각 0/24였다. Haiku S1도 2턴에서 캐시를 읽은 16건 모두 같은 판정이다.
- S2·S3에는 2턴 비교를 쓰지 않는다. 1턴 안의 도구 라운드에서 prefix가 이미 길어지기 때문이다.
- 해석 제한: 이월은 비용과 캐시 비율에 영향을 준 관측 사실이다. 다른 순서였다면 얼마였을지는 반사실 자료가 없어 크기를 추정할 수 없다.

Anthropic prompt caching 문서(2026-11-22 조회, https://platform.claude.com/docs/en/build-with-claude/prompt-caching)에서 다음 문장을 확인했다.

## 3. 구분 가능한 것과 불가능한 것

구분할 수 없는 것은 다음과 같다.

- 기존 고정 순서에서는 조건과 위치가 완전히 겹친다. S1은 항상 두 번째, S3은 항상 네 번째다. 그래서 조건 효과, 순서 효과, 캐시 상태, 시간 효과를 나눌 수 없다.
- 호출 단위 요청 시각이 없어 호출 간 실제 간격과 TTL 경과를 알 수 없다.
- 제공자는 어느 요청이 쓴 캐시를 읽었는지 반환하지 않는다. 2.1절의 출처는 기록과 prefix 구조에서 추론한 것이다.
- 다른 순서였다면 비용과 캐시 비율이 얼마였을지 추정할 수 없다.

구분할 수 있는 것은 다음과 같다.

- 고정 순서 S0→S4에서 관측한 정확도, 비용, 캐시 읽기 비율의 기술 통계.
- 같은 시도에서 만들 수 없는 캐시를 읽은 사례가 있었다는 관측 사실(2.1절: Haiku S1 24/24·S3 5/24, GPT-4o S1 2턴 14/24). 그 출처를 직전 조건으로 특정하는 것(S1은 S0, 일부 Haiku S3은 S2)은 제공자가 출처를 반환하지 않으므로 기록과 prefix 구조에서 추론한 것이다.
- Haiku 경로에 한해, 2026-11-22 조회한 Anthropic 문서는 캐시가 출력 생성에 영향이 없다고 밝힌다. GPT-4o 경로는 OpenAI 문서를 확인하지 않아 확인 불가다. 어느 경우에도 순서·시간 효과가 정확도에 없다는 뜻은 아니다.

## 4. 후속 설계(참고안, 이번 원고에서 미실행)

### 4.1 단위

- 제공자별 신규 독립 합성 세션 40개를 쓴다.
- 사전 고정 seed 20261122로 입력, 템플릿·레이아웃 배정, 순서 배정표를 실행 전에 동결하고 해시를 공개한다.
- 기존 dev/calibration/heldout 세션과의 중복, 비밀·개인정보 포함 여부를 점검한다.
- 생성기는 기존 [sessions](../src/sessions.mjs) 방식을 쓴다. 기존 split의 seed base(5000·6000·7000)와 겹치지 않는 새 base는 동결 시 정한다. 값은 R07 사전등록에서 확정하며 지금은 정하지 않는다.

- 같은 조건끼리의 자기쌍은 0이다.
- 첫 위치에 각 조건이 2회씩 온다.
- S1이 S3보다 먼저 오는 순서는 5/10이다.
- S1과 S3이 인접한 순서는 4/10이다.

### 4.3 블록

- 10개 세션이 한 시간 블록이다. 각 블록에 10개 순서를 한 번씩 seed로 섞어 배정한다.
- 4블록 × 10 = 40세션이다.
- 제공자별로 따로 실행하고 따로 평가한다.
- 블록 사이와 제공자 사이의 순서도 seed로 동결한다.

### 4.4 prefix 정책과 캐시 처리

- 모든 조건은 독립 대화(새 messages)로 실행한다. 독립 대화는 캐시 초기화가 아니다.
- 같은 의미의 입력과 기존과 같은 공유 prefix 정책(같은 SYSTEM/SYSTEM_PLUGIN과 도구 정의)을 고정한다.
- 내용을 바꾸는 salt 처치는 쓰지 않는다.
- TTL, cache namespace, 강제 초기화를 독립적으로 검증할 수 없으면 캐시 자체의 인과효과는 추정하지 않는다.
- 이 설계가 추정하는 것은 순서 무작위화와 고정 공유 prefix 정책 아래의 조건 평균 차이다.
- 순서 무작위화는 캐시 상태를 조건 간에 평균적으로 균형시킬 뿐, 캐시 효과를 제거하지 않는다.

## 5. 주 결과와 정밀도

주 결과는 제공자별 세션 내 차이 D_i = late_acc(S3) − late_acc(S1)이다. late 문항은 3개(6·7·8턴)이므로 값은 1/3 단위이고 범위는 [−1, 1]이다.

- 층은 10개 순서이고 층당 4세션이다.
- θ̂ = Σ_h (1/10) D̄_h
- v_h = (1/10)² · s_h² / 4
- SE = √(Σ v_h)
- ν = (Σ v_h)² / Σ(v_h² / 3) (Welch–Satterthwaite 근사)
- 두 제공자 주 대비 각각 양측 97.5% 구간(Bonferroni)을 쓴다. 구간은 θ̂ ± t(0.9875, ν)·SE다.
- 일부 층에서 s_h²=0이면 v_h=0으로 두고 계산한다. 모든 층에서 0이면 구간을 추정하지 않고 반폭 기준은 미판정이다.
- 층당 n=4와 이산 점수 때문에 근사가 거칠다.

설계 예시(실측 아님): 모든 층의 SD가 같으면 ν=30, t=2.3596이다.

| σ | 반폭 |
|---|---|
| .25 | 9.3%p |
| .35 | 13.1%p |
| .50 | 18.7%p |

참고로 기존 고정 순서 자료에서 세션별 S3−S1 차이의 SD는 GPT-4o .250, Haiku .423이다(층화하지 않음, 순서가 고정된 자료라 새 설계의 분산 추정이 아님). σ=.423이면 같은 산식의 반폭은 약 15.8%p다.

목표 반폭 10%p는 설계 평가 기준이다. 폭, 부호, 유의성에 맞춰 추가 수집하지 않는다. 원실험과의 차이(예: GPT S1 13.9%·S3 81.9%)는 비인과적 기술 비교다.

## 6. 2차 민감도와 기술 결과

2차 민감도 모형은 세션 절편, 조건(4), 위치(4), 직전 조건으로 구성한다. 첫 위치는 직전 조건이 없으므로 따로 처리한다. 직전 조건은 S0 기준 4대비(S1~S4 지시변수)로 두고, 첫 위치 행과 직전 조건이 S0인 행은 네 대비가 모두 0이다. 첫 위치의 차이는 위치 효과가 흡수한다.

- 직전 조건 5수준을 모두 넣으면 위치와 alias가 생긴다(메인 확인: 200행·53열·rank 52).
- 직전 조건을 S0 기준 4대비로 두면 52열이고 rank 52로 완전히 식별된다.
- 적합 전에 실제 자료의 설계행렬 rank를 확인한다. 결측으로 alias가 생기면 해당 효과는 미판정으로 둔다.

캐시 적중과 시간은 기술 결과로만 보고한다. 조건×위치×직전 조건별 cached 비율과 실제 간격을 낸다. 원래 효과가 성능 timing이 아니라 정확도이므로 A/A timing 게이트는 두지 않는다. 독립 세션의 짝차 분산은 제시한다. 다만 모델 실행 자체의 반복 잡음을 분리하지 못한다는 한계를 함께 쓴다.

## 7. 호출 기록 필드

호출마다 다음을 기록한다.

- run, 블록, 세션, 제공자, 조건, 위치, 직전 조건
- turn, kind, round, attempt
- 요청 직전 UTC, 응답 직후 UTC, 직전 요청과의 실제 간격
- prefix 해시(시스템·도구·메시지 직렬화의 SHA-256)와 prefix 토큰 길이
- 제공자가 반환한 cache read/write 토큰. Anthropic은 cache_creation 5m/1h 세부를 포함하고 OpenAI는 cached_tokens를 쓴다.
- 실제 snapshot, system_fingerprint, 요청 cap, usage
- 가격 기준 시점과 출처, TTL 공식 근거 URL·조회일·버전
- 원본 finish_reason/stop_reason, 지연, 오류

누락된 값은 unknown으로 적고 0으로 채우지 않는다.

## 8. 결측·재시도·중단

- SDK와 하네스의 자동 재시도는 끈다.
- 검증된 미전송·비청구 실패만 1회 재시도한다. 결과나 비용이 불명이면 재시도하지 않는다.
- 잘린 응답은 동결된 채점 규칙대로 두고 원래 종료 사유를 기록한다.
- 결측 수를 조건·순서별로 공개한다.
- 결측 late 점수를 [0,1]로 대입한 보수 경계와 완전 쌍 민감도를 보고한다.
- 절단과 미시작은 분리해 기록한다.
- 설계가 미완료면 전체 주 결론을 보류한다.
- 모델, 가격, 계측 방식이 바뀌었거나 전액 최악 비용이 산정·승인되지 않았으면 첫 요청 전 또는 즉시 중단한다.

## 9. 비용 통제(제안)

R06은 지출을 허가하지 않는다. 총상한 금액은 R07 사용자 결정 항목이다.

| 조건 | 세션당 호출 상한 | 산식 |
|---|---|---|
| S0 | 8 | 8턴 |
| S1 | 10 | 8턴 + 요약 2 |
| S2 | 40 | 8턴 × (턴 1 + 도구 라운드 3 + 원본 재요청 1) |
| S3 | 42 | S2 상한 40 + 요약 2 |
| S4 | 8 | 8턴 |
| 합 | 108 | |

전체 호출 상한은 40세션 × 2제공자 × 108 = 8,640회다.

시작 전에 400회 세션 실행 전부의 최악 비용을 예산표로 합산한다. 최대 입력·출력, 이미지, 캐시 쓰기 할증, 당시 공식 최고 요율을 포함한다. 참고로 관측 비용을 40세션으로 단순 환산하면 약 US$23.3이다. 이 값은 예상값도 최악값도 아니다.

실행 중에는 기청구액, 미정산액, 다음 요청의 최악 비용을 더해 상한 이하일 때만 전송한다. 방식은 [R04 설계](./2026-11-20-r04-output-budget-design.md) 7절과 같다.

## 10. 기존 실험과의 비교 제약

- 새 실험의 순서 무작위화 결과를 기존 고정 순서 결과와 합치거나 인과적으로 비교하지 않는다. 차이는 비인과적 기술 비교다.
- R04 제약이 그대로 남는다. Haiku 도구 경로 출력 상한은 512, 일반 호출은 60, GPT는 60, 요약은 400이다. R05를 실행하지 않았으므로 이 비대칭은 유지된다.
- 기존 가격과 정책은 2026-10-15 당시 값이다. 현재 값과 같다고 단정하지 않는다.
- 제공자별로 따로 추정한다. 두 제공자의 구간을 합치거나 제공자 사이의 효과 차이를 주장하지 않는다.

## 11. 이번 원고(8쪽)에 허용할 관측 주장과 인과 해석 한계(제안)

원고는 이번 작업에서 바꾸지 않는다. 2026-11-22 사용자 결정에 따라 D01에서 아래 관측 사실과 한계를 원고에 기록한다. 문장의 최종 형태는 D01에서 정한다.

허용하는 관측 주장은 고정 순서 S0→S4에서 관측한 정확도와 비용이다. 캐시 반영 비용에는 기록과 prefix 구조로 보아 직전 조건이 만든 것으로 판단되는 캐시 읽기가 포함된다(Haiku S1 캐시 읽기 전부, S3 일부, GPT S1 2턴 14/24). 제공자는 읽은 캐시의 출처를 반환하지 않으므로 이 판단은 추론이다.

인과 해석의 한계는 순서, 캐시 상태, 시간 효과를 조건 효과와 분리할 수 없다는 점이다. 캐시 반영 비용의 조건 간 차이는 순서의 영향을 받았을 수 있으나 그 크기와 방향은 측정하지 않았다. 정확도 비교에서는 Haiku 경로에 한해 2026-11-22 조회한 Anthropic 문서가 캐시가 출력에 영향이 없다고 밝히지만, 순서와 시간 효과는 여전히 분리되지 않는다.

제안 문장은 다음과 같다.

> 조건은 모든 세션에서 S0, S1, S2, S3, S4 순서로 고정해 실행했다. 기록과 프롬프트 접두부 구조로 보아 캐시 반영 비용에는 직전 조건이 만든 캐시의 읽기가 포함된다. 비용의 조건 간 차이는 순서의 영향을 받았을 수 있으나 그 크기와 방향은 측정하지 않았다.

> 조건 순서, 캐시 상태, 시간 효과를 조건 효과와 분리할 수 없으므로 이 결과를 조건의 인과 효과로 해석하지 않는다.

## 12. R07 시작 조건과 사용자 결정

R07을 시작하려면 다음을 모두 충족해야 한다.

1. 입력, 채점, 순서표, seed, base를 사전등록하고 동결 해시를 공개한다.
2. 기존 split와의 중복, 비밀·개인정보 점검 결과를 낸다.
3. 400회 세션 실행 전부의 최악 비용 예산표를 만든다.
4. 두 스냅샷의 가용성과 당시 공식 요율, OpenAI 캐시 문서를 확인한다.
5. 호출 기록 스키마와 예약·중단 장치를 오프라인에서 검증한다.
6. 실행과 총상한 금액에 대한 사용자의 별도 승인을 받는다.

사용자에게 제시한 선택지는 다음과 같았다.

- 선택지 A: 이번 원고에서 R07을 실행하지 않는다. 원고에는 관측과 한계 문장만 반영한다.
- 선택지 B: R07 사전등록과 최악 비용 예산표 작성에 착수한다. 실행과 지출은 그 뒤 별도 승인이 필요하고, 총상한 금액을 정해야 한다.

2026-11-22 사용자는 선택지 A를 승인했다. 이번 원고에서 R07은 실행하지 않는다. D01에서 11절의 관측 사실과 인과 효과의 방향·크기를 식별할 수 없다는 한계를 기록한다. 위 시작 조건은 향후 새 연구로 재개할 때 적용하며, 그때 별도 설계와 비용 승인이 필요하다.
