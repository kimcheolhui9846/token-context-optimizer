## 2. 조판 경로

1. `research/tools/d02/md_to_blocks.py`: 원고를 블록 JSON으로 바꾼다. 내부 출처 메모 29개 제거, 저장소 상대 링크 8개를 보충 자료 인용으로 대체, 참고문헌을 첫 인용 순서로 다시 번호 매김(26개 + 보충 자료 1개 = 27개), 장·절 번호를 규정 형식으로 바꾼다.
2. `research/tools/d02/build_hwpx.py`: 양식 HWP를 한글에서 HWPX로 저장한 사본에 블록을 넣는다. 양식 안내문·예시 본문·저자 칸·약력 쪽을 지우고 짝수 쪽 머리말은 살린다. 문서 요약 정보(제목·작성자·주제·마지막 저장자 등 7개 필드)를 비운다.
3. 한글 자동화(별도 숨김 인스턴스): HWPX 열기 → HWP 저장 → HWP 다시 열기 → PDF 저장. 최종본은 저장한 HWP를 다시 열어 PDF를 두 번 내보냈다.
4. `research/tools/d02/verify_pdf.py`: 전 쪽 렌더, A4·머리말·단 배치·그림 위치·글꼴, 인용 순서·항목 본문 일치, 주장 대응, 수치 토큰 다중집합, 내부 경로 누출, 그림·글 겹침, 캡션 분리를 검사한다.
5. `research/tools/d02/clear_hwp_summary.py`(PM 지적 후 추가): 한글이 HWP를 저장할 때 HWP 요약 정보의 작성자(속성 4)·마지막 저장자(속성 8)에 로컬 계정명을 다시 쓴다. 저장 후보는 로컬에 그대로 두고, 그 사본의 `HwpSummaryInformation` 스트림에서 두 문자열만 길이를 1(종결 문자)로 바꾸고 옛 글자를 0으로 채운다. 스트림 길이·속성 위치·다른 바이트는 그대로다. 값은 출력하거나 기록하지 않고 유형·길이·스트림 해시만 남긴다. 정리한 HWP를 별도 숨김 인스턴스에서 다시 열어 저장 없이 PDF로 내보냈다.

- 프로그램: 한글 2018 `10.0.0.14939`(PDF 변환기 Hancom PDF 1.3.0.550), Python 3.12.10, PyMuPDF 2.1(MuPDF 1.28.6), olefile 0.47.
- 한글 파일 접근 보안 대화상자가 인스턴스마다 한 번 떴다. 사용자가 직접 처리했고 이후 작업에서는 다시 뜨지 않았다. 전역 보안 설정, 모듈 등록, 기존 한글 창은 건드리지 않았다.

## 4. 작업 중 찾아 고친 결함

- 짝수 쪽 머리말 누락(r2–r8): 양식의 짝수 쪽 머리말이 약력 쪽에 있어 함께 지워졌다. 논문 제목을 넣어 첫 본문 문단으로 옮겼다.
- 양식 문서 요약 정보(다른 사람 이름, 2002년 작성일)가 PDF 작성자 필드로 나왔다(r2–r9). 7개 필드를 비웠다.
- 내부 출처 메모 1건 누출(r1–r10): 메모 안의 `[]` 때문에 제거 정규식이 중간에서 끝났다. 한 단계 중첩을 허용하도록 고치고, 검증기에 내부 경로 누출 검사를 넣었다.
- 그림·표 겹침(r13): 자동 검사가 놓쳤다. 검증기에 이미지 영역과 글 줄의 교차 검사를 넣었고, 이후 회차는 이 검사로 판정했다.
- 캡션 분리(r12·r18): 검증기에 "캡션 전체가 한 쪽 한 단 안에 있는가" 검사를 넣었다.
- 검증기 한계(검토 지적): 겹침 검사는 래스터 그림과 글 줄만 보고 벡터 표와 본문의 겹침은 보지 않는다. 캡션의 위·아래 위치, 머리말 판정, 인용의 화면 순서는 렌더를 눈으로 확인했다. 쪽 위 표가 문장 사이에 끼는 경우를 위해 주장 대조는 표 영역을 뺀 단 순서로도 한다.
- `md_to_blocks.py`의 그림 2 국문 캡션 영문 병기 제거 분기는 원고와 문자열이 달라 작동하지 않았다. 병기는 #112 단위 문구 검사 대상이므로 남기고 분기를 지웠다(출력 불변).
