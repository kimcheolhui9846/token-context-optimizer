## 3. 새 자료

### 3.1 구성 (12 원본 × 4배치 = 48쪽, 등록 생성기가 결정)

- 문서 종류 `doctype`(이 순서, 번호 d = 0..2): `venue` 공연장 대관 일정표, `proof` 출판 교정 배정표, `workshop` 공방 수업 편성표.
- 양식 `form`(번호 f = 0/1): `table` 표, `cards` 카드. 내용 `content` c = 0/1. 원본 ID `<doctype>-<form>-c<content>`, 12개.
- 배치 두 축(원본 안에서 완전 교차): 세로 위치 `vert` = `same`(표지와 값이 같은 줄) / `below`(값이 한 줄 아래), 이웃 간격 `space` = `narrow`(좁음) / `wide`(넓음). 페이지 ID `<원본 ID>-<vert>-<space>`, 순서: 문서 종류 → 양식 → 내용 → vert → space. 일련번호 `serial` 0–47.
- 원본마다 레코드 3개(위·중간·아래 슬롯 0/1/2). **목표 슬롯 = (d + f + c) mod 3**. 네 배치에서 바뀌지 않는다.

| 원본 | 목표 슬롯 | 원본 | 목표 슬롯 | 원본 | 목표 슬롯 |
|---|---|---|---|---|---|
| venue-table-c0 | 0 위 | proof-table-c0 | 1 중간 | workshop-table-c0 | 2 아래 |
| venue-table-c1 | 1 중간 | proof-table-c1 | 2 아래 | workshop-table-c1 | 0 위 |
| venue-cards-c0 | 1 중간 | proof-cards-c0 | 2 아래 | workshop-cards-c0 | 0 위 |
| venue-cards-c1 | 2 아래 | proof-cards-c1 | 0 위 | workshop-cards-c1 | 1 중간 |

- 슬롯 0/1/2가 각 4원본(표 2·카드 2씩). 목표와 무관한 이웃 레코드: 위 슬롯은 아래 이웃 1개(슬롯 1)와 그 아래 슬롯 2, 중간은 위·아래 이웃, 아래는 위 이웃 1개(슬롯 1)와 그 위 슬롯 0. `design.json`의 `neighbors`에 인접 이웃을, `otherValueItems`에 다른 값 2개를 적는다.

### 3.2 페이지 문법과 좌표 (원본 픽셀, 반열림 `[x0, y0, x1, y1)`)

- 페이지 1280 × 960, 흰 바탕 L 모드. 글꼴 `NotoSansKR-VF.ttf`(시스템 설치본, SHA-256 `018174e8cdd366aff67c8d366c7dc806a7babbe7f2819fc23b00d59f7b8353d0`, 가중치 400, 본문 24, 제목 32). 렌더러 `research/tools/r09/render.py`(main blob `b61cd9b37803d8eb4b6b126a75301570c14ab11d`)를 **수정 없이** 쓴다. 텍스트는 셀 왼쪽 +12px, 셀 세로 중앙(`anchor="lm"`). 글꼴은 저장소에 넣지 않는다.
- 열(모든 원본·배치 공통): 표지 `[40, 400)`, 값 `[720, 960)`, 비고 `[1000, 1240)`. 본문 셀 높이 40. 제목 셀 `[40, 28, 1000, 84)`. 열 간격·글꼴·크기·배경·페이지 크기·질문은 원본의 4배치에서 같다.
- 레코드 블록: `same` 높이 40(표지·값·비고 셀이 같은 y), `below` 높이 80(표지·비고 셀 `[y, y+40)`, 값 셀 `[y+40, y+80)`: 값 칸 안에서 값의 기준선만 정확히 한 줄 내린다).
- 레코드 사이 빈 간격 S: `narrow` 4px, `wide` 84px. 레코드 s의 블록 위 y = Y0 + s·(블록 높이 + S). Y0 = 표 160, 카드 112.
- `table`: 위 구분선 y [96, 98), 머리글 셀 y [104, 144)(표지 열 "공연명/원고명/수업명", 값 열 = 값 항목명, 비고 열 "비고"), 구분선 [150, 152). 레코드 블록마다 아래 간격 가운데에 구분선 `[y_end + S/2 − 1, y_end + S/2 + 1)`.
- `cards`: 카드 3장을 **단일 열로 세로 적층**한다(상·중·하 = 슬롯 0/1/2). 카드는 레코드 블록 바로 바깥의 2px 테두리 상자(x `[24, 1256)`, y `[블록 위 − 2, 블록 아래 + 2)`). 머리글 줄은 없다. 카드 안에는 레코드 항목만 있다.
- 레코드 항목: 표지(`label`), 값(`value`), 비고(`note`, 표지 줄 오른쪽). 다른 레코드 값 = 목표가 아닌 두 레코드의 `value` 항목(레코드당 정확히 하나).

**렌더 잉크 기준 측정과 허용치(OCR 전 검사, 양식 공통 정의):**

| 항목 | 정의 | 허용 |
|---|---|---|
| 같은 줄 | 목표 표지·값 잉크 세로 범위가 양의 길이로 겹침, 그리고 \|값 잉크 위 − 표지 잉크 위\| | ≤ 4px |
| 한 줄 아래 | 값 잉크 위 ≥ 표지 잉크 아래, 그리고 값 잉크 위 − 표지 잉크 위 | [32, 48]px |
| 이웃 간격 | 인접 두 레코드의 잉크 외곽(표지·값·비고 잉크의 세로 합집합) 사이: 아래 레코드 위 − 위 레코드 아래 | narrow [12, 30]px, wide [90, 115]px, 그리고 narrow 최댓값 < wide 최솟값 |

- 페이지별 실측값(목표 표지·값 잉크, 이웃 간격 2개, 레코드 외곽)을 `checks.json`에 남긴다. 레코드 내부의 줄바꿈(below의 값 줄)은 이웃 간격과 별도로 기록한다.

### 3.3 텍스트와 질문

- 문서 종류별 표지 목록 12개(생성기 상수, 직접 지어낸 한글 이름). 0–3번은 그 종류 원본 4개의 목표 표지(목표 번호 = f·2 + c), 4–11번은 이웃 레코드 풀이다. 이웃 표지·값·비고는 `random.Random("ko-row-height|<원본 ID>")`로 뽑는다(값·비고 원본 안 유일). 네 배치는 같은 원본 레코드를 그대로 쓴다.
- 값 항목과 질문:
  - venue "입장 시각", 값 `HH시 MM분`(10–21시, 00–50분 10분 단위), 질문 `{표지}의 입장 시각은 언제인가요?`
  - proof "교정 분량", 값 `NNN쪽`(120–480), 질문 `{표지}의 교정 분량은 몇 쪽인가요?`
  - workshop "수강 정원", 값 `NN명`(6–24), 질문 `{표지}의 수강 정원은 몇 명인가요?`
- 정답 = 목표 레코드 값 텍스트. 골드 두 상자 = 목표 표지 item과 목표 값 item의 실제 잉크(고정 렌더러, 반열림 `[l, t, r, b)`).
- **정규화 질문(NFC, 양 끝 공백 제거, 내부 연속 공백 하나로)은 원본별 1개, 서로 다른 12개이며 각 4번 나온다.** #150의 "질문 48개 유일" 규칙은 쓰지 않는다. 같은 원본의 4쪽이 같은 질문·답·레코드 텍스트를 공유하는 대응을 실험과 보고에서 유지한다.
- 등록 설계 조건(생성기 `check`): 12원본·48쪽·ID와 순서, 슬롯 4/4/4(표·카드 각각 2/2/2), 짝 일치(원본 4쪽의 질문·답·표지·항목 id·역할·텍스트·x 좌표·셀 높이·슬롯·이웃이 같고 y만 다름), 질문에 목표 표지 정확히 1회, 질문에 ASCII 영숫자 없음(K0 정상 미매치 → 한글 분기), 목표 표지 한글 bigram ≥ 4, 목표 외 어떤 item도 목표 표지와 bigram 공유 없음, 머리글·제목 외 item은 질문과 bigram 공유 없음, 머리글·제목은 질문과 공유 bigram ≤ 2, 표지·값·비고 원본 안 유일, 값 ≠ 비고, 같은 줄/한 줄 아래 셀 조건, 비고가 값 오른쪽·표지 줄, 셀 겹침 없음, 셀·구분선 겹침 없음, (`--font`) 글꼴 측정 상자가 셀 안이고 3.2 허용치 충족.
- 한계(공개): 값 항목명이 표 머리글에 있으므로 K1이 머리글 줄을 고를 수 있다(#150 관찰). 표지 bigram ≥ 4 조건은 그 경쟁을 줄이려는 설계이며 선택 순위 규칙 자체는 바꾸지 않는다. 카드에는 머리글 줄이 없다.

6. 결정성: 생성·렌더·배치를 두 새 폴더에서 각각 실행해 모든 파일 바이트가 같다.

- 실패하면 OCR 없이 원인·수정·해시를 인계서에 남기고, 수정한 생성기를 다시 커밋한 뒤 다시 동결한다. 자료 유효성 결함(화면 밖 상자, 잘림, 의도하지 않은 겹침, 분모 오류)만 OCR 전에 고친다. 인식 성능을 근거로 입력을 바꾸거나 페이지를 교체·추가하지 않는다. 실험 OCR을 미리 돌리지 않는다.
- **자료 동결 커밋:** `data/` 전체와 파일별 SHA-256 `data/manifest.json`을 첫 OCR 호출 전에 커밋·push한다.

### 4.4 W2 (등록 규칙)

`RECOUNT_SPEC.md` 4절이 정의다. 요약:

1. W2는 W1 사유가 `widened`인 페이지에만 적용한다. 다른 정상 분기, 미매치, 오류는 W1 상태를 이어받는다(`w2Reason "inherit"`, W2 = W1 또는 null).
2. 히트 = 선택 줄의 저장된 `K1.hitWords` 전부(표지 위치를 보고 선별하지 않음). 상자 `[x, y, w, h]` → 반열림 `[x, y, x+w, y+h)`(실수). widened인데 히트가 없거나, 히트 상자의 너비·높이가 0 이하이거나, 좌표가 유한하지 않거나, 잘못된 인덱스·중복 히트·줄 텍스트 불일치이면 **입력 검증 실패**(페이지 오류가 아니라 과제 검증 실패).
3. a = 히트 위쪽 y의 최솟값, b = 히트 아래쪽 y의 최댓값, 패딩 h = 히트 높이들의 중앙값(짝수 개면 가운데 두 값의 산술평균).
4. 히트 하나라도 `top < W1.top` 또는 `bottom > W1.bottom`이면 W2 = W1, `w2Reason "hit_outside_w1"`. 변과 같으면 안쪽이다.
5. 아니면 새 위 = max(W1.top, floor(a − h)), 새 아래(배타 끝) = min(W1.bottom, ceil(b + h)). 계산은 실수, 마지막 양 끝에서만 내림·올림(하단 배타 끝 올림은 양의 합집합을 보존한다). 좌우는 W1과 같다. 위·아래가 W1과 같으면 `"no_cut"`, 다르면 `"cut"`.
6. 사후 단언: 새 top < bottom, W2 ⊆ W1, 좌우 동일, 모든 히트가 W2 안에 세로로 완전히 들어감. 어긋나면 검증 실패.
7. 수평·수직 규칙을 조합해 후보나 줄을 다시 고르지 않는다. 여러 히트를 포함한 줄, 경계에 맞닿은 상자, 글자 크기가 다른 히트도 위 규칙으로 처리한다. 패딩 탐색·사후 예외·골드를 이용한 복원은 없다.
- 페이지별로 W1 사유, W2 사유, a, b, h, W2, 잘라낸 픽셀 `cutPixels = W1 면적 − W2 면적`을 남긴다.

### 4.5 재생과 예측 동결

- 재생기 `node src/ko-row-height-replay.mjs --ocr <ocr dir> --out <replay dir>`: OCR `freeze.json` 해시 확인 → 각 페이지 원시 OCR로 고정 `keyResults`를 다시 실행해 저장 K1과 같은지 확인 → 고정 W1 → W2 → `predictions.jsonl` 48행, `freeze.json`, `inputs.json`(실제로 연 입력의 상대 이름과 SHA-256). 재생기의 자료 입력은 **허용 목록 리더**(선택기 측 `selector/questions.json`, `selector/images/*.png`)를 거친다. `scoring/`·`gold`·`design`·`render`·`score` 경로를 열려는 시도는 거부(예외)되며 시험으로 확인한다.
- 재생 A의 `predictions.jsonl`을 커밋·push(예측 동결: 커밋·SHA-256을 결과에 적음)한 **뒤에만** 채점기가 `scoring/`을 연다. 채점기는 예측 파일이 HEAD에 커밋된 blob과 같은지 기록한다.
- 재생 B: 별도 프로세스에서 같은 동결 OCR로 다시 재생·채점해 결정적 파일을 바이트·행 단위로 비교한다. OCR을 두 번 수행한 독립 실험이 아니다.

### 4.6 오류와 검증 실패

- 통상 OCR/선택기 기술 오류·타임아웃은 48쪽 분모에 남기고 모든 창에서 실패로 센다. 미매치도 48쪽 분모에 둔다. 표기: 등록 48쪽 = 기술 오류 + 정상 처리(미매치 포함).
- 원본 해시·인덱스·키 손상·누락, 사전등록 위반, 결정적 재생 불일치는 **과제 검증 실패**다. 그 실행을 불완전으로 기록하고 손상 페이지를 선택적으로 빼지 않는다. 같은 조건으로 복구·재실행하면 이전 시도와의 차이를 남긴다.

## 5. 채점과 보고 지표

`RECOUNT_SPEC.md` 5–7절이 정의다.

- **엄격 성공**(#147 `scoreKey` 그대로): 정상 매치, `0 < 면적 < 페이지 면적`, 표지·값 두 잉크 전체 포함(여유 0). 창이 전체 페이지면 두 잉크를 담아도 실패. W0/W1/W2 각각 판정한다.
- **전이**: W1→W2(일차) 회복·손실·유지·둘 다 실패, W0→W1(참고). W1이 전체 페이지였고 W2가 부분 창인 경우(`fullPageToPartial`)와 그중 회복을 따로 센다. 손실 페이지는 잘린 근거(표지/값/둘 다)를 남긴다. W2 ⊆ W1이므로 W2에서 새로 완전히 포함되는 근거·다른 값은 기하상 0이며 검사한다.
- **다른 레코드 값 노출**(렌더 잉크 기준, 목표 외 레코드의 값 2개): 각 창에서 완전(잉크 ⊆ 창) / 일부(양의 교집합, 완전 아님) / 전혀(교집합 면적 0, 맞닿음 포함). W1에서 완전했던 값의 W2 상태(완전/일부/전혀)를 센다. 항목 수와 페이지 수를 구분한다. 일부만 보이는 텍스트의 의미나 답변 정확도는 추정하지 않는다. 목표 레코드의 표지·비고, 머리글, 제목은 이 지표에서 제외한다.
- **일차 지표 (L)**: W1 엄격 성공에서 W2 실패로 바뀐 쪽수, 분모 = W1 엄격 성공 수.
- **일차 지표 (J)**: W1·W2 모두 엄격 성공을 유지하면서, W1에서 완전 포함된 다른 레코드 값 하나 이상이 W2에서 전혀 보이지 않게 된(교집합 0) 쪽수. **기회 분모** = W1 엄격 성공 ∧ 실제로 세로를 자름(`cut`) ∧ W1에서 완전히 보이는 다른 값 ≥ 1인 쪽수. J·기회 분모·L 각각 해당 서로 다른 원본 수(최대 12)를 같이 쓴다. full→partial만 있는 쪽, full→none이 하나 이상인 쪽, 둘 다인 쪽을 나눠 배타/중첩을 표시한다. 일부가 잘려 완전 포함이 줄어든 사례는 J와 별개로 제시한다.
- **면적(부수 지표)**: 같은 유효 매치에서 `W1 면적 − W2 면적`. 픽셀 합과 페이지 면적 대비 평균·중앙값·최대 %p를 유효 쌍 전체와 실제 세로를 자른 쪽 각각에 대해. 0분모는 해당 없음(`null`).
- **분리 표**: 전체 48쪽, W1 widened, 실제 세로 제한(`cut`), W2 사유별, 배치 4조건, vert, space, 양식, 문서 종류, **12개 원본 × 4조건 표**(원본별 4쪽 결과). 단계별 분모와 전이표, 면적·다른 값의 집계 대상을 표마다 명시한다.

### 5.1 측정 전 해석 기준 (요청서 그대로, 등록)

- 입력 무결성과 A/B 일치가 전제다. 통상 OCR 오류가 하나라도 있으면 그 수와 분모 48을 표시하고 해석은 관찰 가능한 정상 쪽으로 한정한다. 입력을 다시 채우지 않는다.
- L > 0: 이 자료에서 "기존 성공을 잃지 않는다"는 조건을 충족하지 못했다. J > 0이면 두 현상이 함께 있었음을 숫자로 병기한다.
- L = 0, 기회 분모 > 0, J ≥ 1: 이 자료에서 안전하게 다른 값을 완전히 제외한 사례가 관찰됐다. J가 한 원본에만 있으면 한 원본의 사례로, 서로 다른 2개 이상이면 반복 관찰된 원본 수로 적는다. 통계적 지지나 채택 문턱이 아니다.
- L = 0, 기회 분모 > 0, J = 0: 그런 사례가 관찰되지 않았다.
- widened = 0, 또는 실제 세로 제한 = 0, 또는 기회 분모 = 0: 다른 값 제거에 대한 판단 기회가 없었다. L은 계산한다.
- 같은 분자·분모 원칙을 배치 4조건에도 적용한다. 원본·조건 수가 적은 결과에 일반화·상위그룹 인과 주장을 붙이지 않는다. 판정 코드(`verdict`)는 `RECOUNT_SPEC.md` 6절의 규칙으로 기계적으로 만든다. 채택 판정은 별도(사용자 결정)다.
