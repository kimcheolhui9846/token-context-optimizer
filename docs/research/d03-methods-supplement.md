## 1. `selectWindow` 규칙

### 1.1 원고 의사코드 전문

원고 `docs/research/image-first-paper-draft.ko.md` 75–88행의 코드 블록을 글자 그대로 옮긴다. 원고 73행은 "실험 2의 C·D와 실험 3의 S2·S3은 같은 `selectWindow` 규칙을 쓴다. 요약하면 다음과 같다(좌표는 원본 픽셀, h는 줄 높이)"로 소개한다.

```text
selectWindow(OCR 줄 목록, 질문, W, H)
  K ← 질문 토큰 중 길이 3 이상, 불용어·yes·off 제외
  각 줄의 점수 ← 줄 단어와 일치하는 K의 개수 (4자 이상은 앞부분 일치도 허용)
  best ← 점수가 가장 높은 줄. 점수가 같으면 OCR confidence가 높은 줄
  모든 점수가 0이면 → 미발견 반환
  anchor ← best 줄에서 키워드와 일치한 단어들의 경계 상자 (없으면 줄 전체)
  h ← max(8, best 줄 높이)
  축 행(단어 8개 이상, 평균 길이 4 이하, anchor 폭 < 줄 폭의 25%)이면
      열 창: 가로 anchor 중심 ± max(1.5 × anchor 폭, 3h), 세로 anchor 위 0.75H ~ anchor 아래 6h
  그렇지 않으면
      행 창: 가로 줄 왼쪽 − 4h ~ 줄 오른쪽 + 8h, 세로 줄 위 − 3h ~ 줄 아래 + 6h
  창을 가운데 기준으로 최소 256 × 128까지 넓힌 뒤 이미지 경계로 자른다
```

### 1.2 코드와 대조한 세부 규칙

기준 코드는 `research/src/selector.mjs`의 `keywords`(35–36행), `score`(38–41행), `selectWindow`(81–112행)다. 원고 90행의 출처 표기는 `research/src/selector.mjs:13,35-41,79-112`다.

| 항목 | 코드의 규칙 | 근거 |
|---|---|---|
| 토큰화 | 소문자로 바꾸고 `a-z`, `0-9`, `-`, 공백이 아닌 문자를 공백으로 바꾼 뒤 공백으로 나눈다 | `selector.mjs:35` |
| 키워드 | 토큰 중 길이 3 이상이고 STOP 목록에 없는 것, 중복 제거. `selectWindow`는 여기서 `off`, `yes`를 다시 뺀다 | `selector.mjs:13,36,79,82` |
| 점수 | 줄의 각 키워드가 줄 단어와 같으면 1점씩 센다. 4자 접두 일치는 키워드와 단어가 둘 다 4자 이상이고 어느 쪽이든 다른 쪽의 접두이면 인정한다 | `selector.mjs:38-41` |
| 최고 줄 | 점수가 가장 높은 줄. 동점이면 OCR confidence가 높은 줄. confidence까지 같으면 먼저 나온 줄이 남는다(비교가 `>`) | `selector.mjs:85-88` |

| 열 창(축 행) | 가로: anchor 중심 ± max(1.5 × anchor 폭, 3h). 세로: anchor 위쪽에서 0.75H 위 ~ anchor 아래쪽에서 6h 아래 | `selector.mjs:97-102` |
| 행 창(그 밖) | 가로: min(anchor 왼쪽, 줄 왼쪽) − 4h ~ 줄 오른쪽 + 8h. 세로: 줄 위 − 3h ~ 줄 아래 + 6h | `selector.mjs:103-104` |

| 정수화 | 왼쪽·위쪽은 floor, 오른쪽·아래쪽은 ceil | `selector.mjs:109-110` |

### 1.3 원고 의사코드와 코드의 차이

의사코드의 규칙 자체와 계수는 코드와 어긋나는 곳이 없다. 의사코드가 적지 않은 세부는 다음과 같다. 원고는 이를 "요약"이라고 소개한다(원고 73행).

1. 행 창 왼쪽: 원고는 "줄 왼쪽 − 4h"로 적지만 코드는 min(anchor 왼쪽, 줄 왼쪽) − 4h다(`selector.mjs:103`). anchor가 줄 상자 안에 있으면 같은 값이며, OCR 단어 상자가 줄 상자의 왼쪽을 벗어나는 경우에만 달라진다. 그런 경우가 실험에서 있었는지는 확인 불가다.
2. anchor 단어 일치: 코드는 단어 텍스트의 첫 토큰만 키워드와 비교한다(`selector.mjs:83`). 줄 점수는 줄 전체 토큰으로 센다(`selector.mjs:39`). 의사코드는 둘을 구분하지 않는다.
3. confidence까지 같은 동점은 먼저 나온 줄이 남는다. 의사코드에 없다.
4. 최소 크기 확장 뒤 경계 자르기: 자른 결과가 256 × 128보다 작아질 수 있다. 의사코드는 순서만 적고 결과 크기를 보장하지 않는다.
5. 정수화(floor/ceil)는 의사코드에 없다.

### 1.4 미발견 시 처리

- 실험 2 C·D: 선택 결과가 `matched:false`이면 B와 같은 전체 1536/q75 변환 이미지를 쓴다. 코드의 분기는 `out = sel.matched ? cropTransform(...) : { bytes: armB.bytes, ops: ["select: no match -> full frame", ...armB.ops] }`이고 `file`은 `fileB`다. (`research/src/variants.mjs:85-94`)
- 실험 3: 도구 질의에서 `sel.matched`가 거짓이면 `cropTransform` 대신 `armTransform`으로 전체 이미지를 변환해 돌려준다. 결과 문구는 "No matching region found ... whole image downscaled"다. (`research/src/session-harness.mjs:166-167`) 원고 90행은 이를 "썸네일 없이 전체 arm 변환 이미지"로 적는다. 썸네일의 유무는 위 코드 발췌만으로 확인하지 못했다. 원고 문구를 그대로 인용한다.
- 원고 90행은 이 의사코드가 실험 경로의 규칙 기술이며 일반 crop 알고리즘으로서의 우월성을 뜻하지 않는다고 못 박는다.

### 1.5 OCR과 동결

- OCR은 tesseract.js 5.1.1 `eng`이며 이미지를 긴 변 4096 px로 확대한다(최대 4배). (`research/src/selector.mjs:8,15-22`)
- 실험 2 하네스·분석은 held-out 호출 전에 동결했다. 동결 커밋은 `dbf4f6b`다. (`research/results/exp2-heldout/README.md:5`)
