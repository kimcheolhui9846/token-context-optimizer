## 2. E-1 — predicate decision

All candidates preserve the original start rule: an ASCII letter at an ASCII `\b` boundary; subsequent run characters are ASCII letters/digits/`+.-`. A valid start may occur after `.` or `-` inside a longer run. `_a:` and `1a:` do not start at `a`, whereas `éa:` can. This is a conservative technical-token heuristic, not a standards-compliant URI parser.

| Candidate | Exact definition | Inputs it stops protecting via URI | Remaining false positives / costs |
|---|---|---|---|
| (가) hierarchy only | Eligible run followed immediately by `://` | Opaque `mailto:a@b`, `data:text/plain,hello`, `urn:example:animal`, custom opaque schemes | Arbitrary `Note://text` still matches; opaque URIs can fall through to unknown or semantic depending on payload |
| (나) non-whitespace suffix — **recommended** | Eligible run then `:` and at least one following character not in JavaScript `\s` | Bare `http:`, `mailto:` and colon followed by space/tab/newline/NBSP/FEFF; malformed or line-wrapped technical text no longer receives this guard | `key:value`, `Note:x`, `localhost:8080`, Windows drive prefixes and parts of IPv6 still match; smallest narrowing among these observed candidates |
| (다) known schemes or hierarchy | Any eligible `://`, OR ASCII-case-insensitive known scheme followed by `:`; known empty/whitespace suffixes remain protected | Unlisted opaque schemes such as `custom:payload` | Bare/space-followed `http:` and `mailto:` remain exact; arbitrary `custom://host` remains matched; allowlist maintenance and domain-specific omissions |

For (다), the concrete list measured is: `http`, `https`, `ftp`, `ftps`, `file`, `mailto`, `data`, `urn`, `tel`, `sms`, `ssh`, `sftp`, `postgres`, `postgresql`, `mysql`, `mongodb`, `redis`, `sqlite`. “Known” does not mean an automatically fetched registry. Changing this list or requiring a suffix for its members requires a new measurement/decision. The `://` alternative applies to **any** eligible scheme, not a literal scheme named `any`.

## 3A. E-3 credential-label protection (C-1)

Extend existing tuple **#0** as `original #0 predicate OR hasCredentialLabel(content)`; leave its reason `secret` and its position unchanged. Do not insert a tuple. All 27 tuple indices, including 2/6/7/8/15/18/19/20/21/23, remain unchanged. The secret reason still enters at #0 when the new label matches, before code/path and numeric reasons; duplicate secret labels still collapse. Predicate-level equivalence exceptions are exactly #0 and #3.

The added label vocabulary is finite: `passwd`, `pwd`, `passphrase`, `pass`, `credential`, `credentials`, `private key`, `secret key`, `access key`, `api key`, `client secret`, `recovery code`, `secret answer`. Match ASCII case-insensitively at ASCII word boundaries. Multiword labels allow one or more ASCII spaces/tabs between the two words, not arbitrary intermediate words. After the last word allow JavaScript whitespace then `:` or `=`; no payload is required. Existing underscore/hyphen and Unicode-fold behavior of original #0 stays protected by the original predicate. This deliberately permits a label inside a sentence, including `Login: alice, Pass: hunter2`.

The independent small-input E-3 specification is:

```javascript
/\b(?:passwd|pwd|passphrase|pass|credentials?|(?:private|secret|access|api)[ \t]+key|client[ \t]+secret|recovery[ \t]+code|secret[ \t]+answer)\b\s*[:=]/i
```

Production uses a linear scanner for the addition: scan word starts; compare the fixed finite vocabulary without slicing the entire remaining input; scan separator spans only after a matching fixed word; check the delimiter, then continue. A whitespace span can be visited by only a bounded number of vocabulary alternatives, so time is O(n) and auxiliary space O(1). Do not use an arbitrary `keyword + words*` pattern or recursive matcher. Preserve the original #0 predicate via OR, and stress the combined #0 as well as the addition. If the original #0 fails a large-input case, replace it with an equivalent scanner only after independently proving its old Unicode/case/boundary semantics; do not silently narrow it.

Reproduce all ten review prefixes both alone and with this explicit suffix: ` The team agreed to keep this note for the onboarding review and preserve the original context.` The supplied review abbreviated the prose, so this survey records a concrete comparable suffix rather than claiming byte identity with an unavailable probe.
