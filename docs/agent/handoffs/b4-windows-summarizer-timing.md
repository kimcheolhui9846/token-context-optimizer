# B4 · Windows 요약기 회귀 테스트의 60초 제한

Tier C · Windows, Node v24.18.0, Vitest 4.1.12. 기준 main `976c403d30`. 과거에는 단독·전체에서 각각 시간 초과가 있었고, 이후 단독 통과 기록은 56.83초였다. 이번 판정은 아래의 새 측정에 근거한다.

## Windows 실측

단독은 해당 파일을 워커 1개로, 전체는 저장소 테스트를 워커 4개로 실행했다. 각 행은 새 프로세스에서 순차 실행했다. 비교 테스트는 Vitest JSON의 해당 테스트 시간이며, 프로세스 전체는 시작부터 종료까지의 경과 시간이다.

## 재현

PowerShell의 새 세션에서 `$env:TCO_SUMMARIZER_TIMING='1'`을 설정한 뒤 `node node_modules/vitest/vitest.mjs run tests/summarizer-selection.test.ts --maxWorkers=1`을 실행한다. 전체 조건은 `node node_modules/vitest/vitest.mjs run --maxWorkers=4`다. 기본 모드는 이 변수를 설정하지 않은 새 세션에서 같은 명령을 실행한다.

- `SUMMARIZER_TIMING_PROGRESS`는 마지막으로 끝낸 입력까지의 누적 시간과 비교 수다. `SUMMARIZER_TIMING`은 완료된 실행의 단계별 합계와 잔여 시간을 담고, `SUMMARIZER_DIFFERENTIAL`은 정확성 검증 횟수를 담는다.
- 실제 제품 경로·기준 구현·입력·예산·단언·기존 60초 제한을 보존했다. 이 제한은 테스트 전체에 적용한다. 제품 단일 요청 지연은 측정 대상 밖이다.
- 임시 복사본의 제한은 120ms였고 Vitest는 실제 11.94초 뒤에 시간 초과를 기록했다. 마지막 체크포인트에는 51개 입력이 남았다. 제한 시각과 실제로 처리가 멈추는 시각은 달라질 수 있다. 잘못된 출력값을 넣자 기존 정확성 단언도 실패했다. 환경 변수 값 `true`에서는 계측 출력이 없었다.

## 검토와 검증

- Claude Opus 5.5 · 계획 수정 후 PASS, 독립 마일스톤 PASS. 사전 실행 순서, 기본 경로 무계측, 시간 초과 시 기록을 확인했다. Opus는 공통 구간 비율을 별도로 재계산하지 않았고, 주 세션이 네 실행의 같은 체크포인트 원본으로 재계산했다. GPT-6.2 Sol은 테스트 코드, Claude Sonnet 5.5는 재현 안내 초안을 맡았다.
- Draft 전 npm 빌드·타입 검사·MCP 스모크·패키지 검사·벤치마크 통과. 기본 전체 테스트 결과는 4,640개 통과, 0개 실패, 5개 건너뜀이다. 위 표에는 진단 모드의 실패도 모두 포함했다.
