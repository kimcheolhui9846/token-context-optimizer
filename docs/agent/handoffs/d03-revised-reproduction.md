## 검증 근거

- Python D03 시험 49개 통과. 구 도구는 질의 키 누락·중복 조건을 MATCH, 그림 2의 GPT-4o A 라벨 삭제를 MATCH-WITHIN-TOLERANCE로 잘못 판정했다. 새 도구는 같은 세 입력을 모두 MISMATCH로 판정하고 종료 코드 1을 반환했다.
- 36개 문항별 네 조건을 원래 실험 명세와 대조한다. 두 데이터 반례에서 잘못된 좌표는 각각 2개였다. 그림 반례는 위치 (1024, 256)의 32×32 영역에서 기준을 넘긴 픽셀이 189개였다. 흩어진 미세 변화는 빠질 수 있다.
- 세 판본 및 11월 26일 자료·최신 도구 조합을 각각 새 폴더에 풀어 실행했다. 네 조합 모두 표·그림 7/7 MATCH, 보조 파일 21개 바이트 일치, 원자료 252개 동일, 오프라인 12단계, 차단 기록 0건, 입력 패키지 무변경. 두 교정본 모두 캡션 24/24 일치.
- 예전 두 ZIP의 SHA-256은 보관본과 일치했다. 11월 27일판도 두 번 생성한 ZIP의 바이트가 같았다. 일반 민감 패턴에 대한 파일명·내용 검출은 모두 0건이었다.
- #165의 독립 검산기로 Exp2 조건별 정확도·재요청 건수와 Exp3 정확도 차이의 신뢰구간을 다시 확인했다. 모델 재호출과 추가 실험 없이 기존 원자료를 사용했다.
- Sol이 문항·조건 검사를 구현하고 Sonnet 5.5가 독자 안내를 작성했다. 주 세션이 판본 호환성과 그림 비교를 통합하고 실제 ZIP과 결과를 검산했다.
- Claude Opus 5.5 계획 PASS. 마일스톤 PASS(중대 0, 경미 1). 손상된 판본 선언 파일을 읽는 오류에 회귀시험을 추가하고 정상적인 종료 코드 2를 확인했다.
- Opus 5.5 수정 재검토 PASS. 독립 실행에서 시험 49개와 네 조합의 결과를 확인했다. 주 세션이 데이터·도구 커밋, 반복 ZIP 바이트 및 실제 반례 명령을 직접 검산했다.
- 제품 브랜치 게이트에서 빌드·타입 검사·MCP 스모크·플러그인 검증·벤치마크 통과, Vitest 4,639개 통과·5개 건너뜀.
