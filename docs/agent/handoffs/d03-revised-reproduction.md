# D03 교정본 오프라인 재현

Tier E · #165의 원고를 기존 독자용 재현 패키지에서 검증하는 작업.

## 범위와 판본

- 기존판 데이터 커밋은 `33d68436621b3db90fbed4b4cc6385e76b4961d3`, 교정본은 `5270a65a0eaa8263aaa1e041d5f3a1ec7b7fbe78`이다.
- 교정본의 데이터·원고·분석 스크립트·기준 그림을 데이터 커밋에서 읽고, 실행기와 안내 파일 다섯 개를 도구 커밋에서 읽는다. 패키지 안의 `MANIFEST.json`이 각 출처를 기록한다.
- 유지관리자는 이 브랜치의 빌더에서 교정본 데이터 커밋과 검증한 도구 커밋을 명시한다. 독자는 ZIP을 풀어 `README.ko.md`의 오프라인 명령을 실행한다. [실행 안내](../../research/d03-reproduction-guide.md) · [판정 기준](../../research/d03-reproduction-rules.md)
- 원고와 원자료에는 변경이 없다. 새 모델 실험은 수행하지 않았다. 연구 ZIP은 로컬 검토용이며 PR은 도구·테스트·안내만 제공한다.

## 구현과 검증

- Sol이 F2 캡션 대조와 반례를 구현했다. Sonnet이 두 판본의 독자 안내와 판정 규칙을 갱신했다. 주 세션이 빌더, 판본 식별, 실행기 및 결과 보고를 통합했다.
- RED에서 기존 빌더는 교정본을 거부했다. 캡션 교체·누락·순서, 도구 판본 선택, 원고 해시 불일치 검사를 추가했다. 통합 중 발견한 키워드 인자 오류를 고친 뒤 실제 ZIP 독자 명령을 다시 실행했다.
- 고정한 Python에서 D03 시험 37개가 통과했다. 구판·교정본 모두 Git 작업 사본 밖에서 표 3개와 그림 4개가 `MATCH`였고, 보조 파일 21개도 기준과 바이트 단위로 같았다.
- 교정본 그림 2는 GPT-4o와 Haiku 4.5의 각 여섯 조건에서 평균 총 입력 토큰과 정확도 24/24가 일치했다. 각 점의 계산값·원고값은 `report.json`에 있다.
- 두 판의 원자료 252개 Git blob이 같았다. 판별용 차단 사전 대조 통과, 실제 재생성 12단계에서 차단 기록 0건, 입력 패키지 무변경. 두 ZIP의 파일명·내용 민감패턴 검출 0건.
- 기존 ZIP의 SHA-256은 `e7d3cdfce2b91398957450f01e1eba679d6d5203cf6c9c4289eb4136ed0ad607`로 원본과 같았다. 교정본은 동일 데이터·도구 커밋으로 두 번 빌드한 ZIP의 바이트를 대조했다.
- 제품 게이트에서 빌드, Vitest 4,639개 통과·5개 건너뜀, 타입 검사, MCP 스모크, 플러그인 검증, 벤치마크를 확인했다.
- Claude Code `claude-opus-5-5` 계획 PASS(중대 0, 경미 4), 마일스톤 조건부 PASS(중대 0, 경미 2). 판본 정보 누락을 실행 전에 거부하는 회귀시험과 판본별 증거 출력을 추가했다.
