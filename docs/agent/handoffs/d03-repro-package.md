| 출력 | 내용 |

종료 코드는 다음과 같다.

| 코드 | 뜻 |
|---|---|
| 0 | 합격 |
| 1 | 판정 실패 |
| 2 | 매니페스트·입력 오류. 재생성 전에 멈추며 `regenerate` 단독 실행도 같다 |
| 3 | 사전 차단 음성 대조 실패 |
| 4 | 재생성이 오프라인 조건을 깨뜨림 |

오프라인 조건은 두 가지다.

- 재생성 단계마다 그 단계의 인터프리터가 차단 장치를 시작한 기록이 있어야 한다. 기록은 단계 이름과 인터프리터 종류가 같아야 하고, 실행기가 띄운 프로세스 자신이나 그 직접 자식의 것이어야 한다.
- 차단된 호출이 0건이어야 한다.

## 검토와 구현 오류 기록

- Argon 1차는 REQUEST CHANGES였고, Opus 마일스톤은 PASS WITH NOTES였다. 지적은 `c6be9cc`·`b231708`에서 반영했고, Argon 재확인은 APPROVE였다
- PM 검토는 CHANGES REQUIRED였다. 주요 지적은 세 건이다
  - 읽을 수 있는 표 파일과 출력 기록이 없었다
  - 재생성의 오프라인 증거가 합격 판정과 종료 코드에 들어가지 않았다

- 코드 지적 두 건은 `e2a850b`, `34be166`, `1a8bca2`에서 고쳤다
- 그 뒤 독립 재현이 해시 잠금 venv에서 과학 판정 7/7인데 종료 코드 4로 끝났다. 원인은 Windows venv의 `python.exe`가 실제 인터프리터를 자식 프로세스로 띄워, 가드 기록의 pid가 실행기 기록과 달랐던 것이다. 차단된 호출은 0건이었다

  - 실패 기록은 로컬에 보존했다
- 수정마다 Opus 재확인을 받은 뒤 처음부터 다시 실행했다. PM 지적 반영에 대한 Argon 판정은 두 번 모두 APPROVE다
