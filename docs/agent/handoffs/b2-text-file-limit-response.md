# B2 · 텍스트 색인 파일 크기 한도와 MCP 응답

Tier C. O01 검토 B2에서 README가 내부 파일 크기 오류 이름을 MCP 응답으로 설명하는 문제를 확인했다. [도구 동작 안내](../../../README.md#tool-behavior)에 실제 응답 예시와 분할 방법을 반영했다.

## 파일 경로를 보낸 경우

- 생성한 UTF-8 파일의 경로만 `index_artifact`에 전달했다. 정확히 10,485,760바이트일 때 색인 결과의 `byteLength` 및 SHA-256이 디스크 값과 일치했다.
- 같은 파일이 10,485,761바이트일 때 JSON-RPC 응답의 `result.isError`가 `true`였다. `result.content`의 텍스트는 `File exceeds maxBytes limit: 10485761`이었다. 공개 오류 코드 필드는 없었다. 예시는 패키지 0.1.0과 잠금 파일의 MCP 서버 SDK 2.3.0에서 확인했다.
- 크기가 큰 파일은 문자 경계에서 유효한 UTF-8 파일로 나눠 각각 10 MiB 이하로 색인한다. 클라이언트가 크기 초과를 별도로 구분해야 하면 로컬 파일의 바이트 수를 확인한다.

## 검증과 검토

- 기존 README가 실제 응답과 어긋나는 지점은 코드 필드와 예시였다. 격리 설치본에서 캡처한 도구 결과와 문서의 JSON 예시를 구조 단위로 대조했다.
- [공개 경로 회귀 T7-1](../../../tests/p06-text-contract-audit.test.ts)은 같은 허용 경로의 파일을 `stat`으로 잰 뒤 한도와 한도+1에서 STDIO 응답을 확인한다. 기준 테스트 20개와 추가 후 21개가 통과했다. 원본이 큰 경우에도 도구 호출에 보내는 입력은 경로 한 개다.
- 계획 검토 · Claude Opus 5.5. 관측한 실제 응답, 경계값, 권한 및 검증 범위를 명시한 수정 계획 PASS.
- 분담 · GPT-6.2 Sol은 회귀 테스트를 작성했고 Claude Sonnet 5.5는 README 예시를 검토했다. 주 세션이 문안을 반영하고 독립적으로 번들 응답을 확인했다.
- 마일스톤 검토 · Claude Opus 5.5 PASS. 예시를 버전 0.1.0의 관측값으로 표시하고 진단 문구가 바뀔 수 있음을 설명했다. 재검토에서 원시 번들 해시와 공개 응답 일치를 확인했다. 주 세션은 별도 임시 디렉터리에서 T7-1 종료 후 테스트 파일이 정리됨을 확인했다.
