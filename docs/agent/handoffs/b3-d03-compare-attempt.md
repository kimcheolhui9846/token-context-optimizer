# B3 · D03 최근 재대조와 보조 파일 차이

Tier C. [#168](https://github.com/kimcheolhui9846/token-context-optimizer/pull/168) 독자 실행기를 기준으로 원래 재현과 최신 재대조의 상태를 구분했다. [실행 안내](../../research/d03-reproduction-guide.md) · [판정 규칙](../../research/d03-reproduction-rules.md)

## 결과 읽기

- `report.json`·`report.md`는 원래 `all`의 기록이다. 재대조의 최신 상태는 `compare.json`의 `runId`, UTC 시작·종료 시각과 `status`로 확인한다. Markdown·출력 매니페스트·명령 출력이 같은 완료 ID를 가리킨다.
- `lastSuccess`는 직전 성공 요약이다. 과거 파일에 없는 ID나 시각은 추정하지 않는다. 완료 결과를 쓸 수 없으면 과거 성공으로 돌아가지 않고, 이미 발급된 시도는 미완료로 표시한다.
- 보조 파일 차이는 일치 개수와 경로로 경고한다. 과학·PDF 합격 조건과 각 수치 임계값은 기존 판정 규칙을 따른다. 구문이 손상된 분석 JSON은 이를 읽는 항목에서 검사 불가로 기록한다.

## 검증

- RED · 이전 배포본은 보조 파일 한 개를 바꿔도 콘솔에 경고가 없었다. 이어 분석 JSON을 손상시키자 종료 1과 예외가 발생했지만 최근 JSON은 앞선 합격으로 남았다.
- GREEN · 후보 ZIP에서 정상 → 보조 차이 → JSON 손상 → 복원 → 재생성 기록 손상 → 복원을 실행했다. 종료 코드는 각각 0, 0, 1, 0, 2, 0이었다. 원래 `all`의 보고서 두 파일은 모든 재대조 전후 바이트가 같았다.
- 보조 Markdown 차이에서 과학 7/7·PDF 4/4·보조 20/21과 파일명이 표시됐다. S3 분석 JSON 구문 오류에서는 T3·F3·F4가 `NOT-REPRODUCIBLE`, 나머지 4개와 필수 PDF 4개는 통과했다. 전제조건이 깨졌을 때는 검사 수치가 `null`이었다.
- 새 출력 폴더의 오프라인 `all`은 과학 7/7·PDF 4/4·보조 21/21을 기록했다. 동일 핀으로 만든 두 ZIP의 지문이 같았고, 기존 배포본의 원자료 252개와 원고는 바이트가 같았다.
- D03 전체 unittest 72개 통과. Windows에서 경합하는 작성자와 실제 최종 파일 교체 실패 후 복구를 확인했다. POSIX 잠금 경로는 이 Windows 환경에서 실행하지 않았다.
- 필수 PDF 하나를 빼면 과학 7/7이어도 PDF 3/4로 종료 1이었다. 생성 세션 JSON의 `rows` 자료형 오류는 그림 3·4에 해당 경로로 기록됐다. 각 입력을 복원하면 다시 통과했다.

## 독립 검토와 인계

- Claude Opus 5.5 · 계획 PASS, 수정 후 독립 마일스톤 PASS. 차단·중대 지적 0건. Opus가 후보 ZIP에서 실패·복구를 다시 실행했다.
