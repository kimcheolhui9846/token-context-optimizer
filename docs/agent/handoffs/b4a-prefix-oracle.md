# B4a · 요약기 테스트의 접두사 토큰 계산 재사용

Tier C · [부모 Draft #173](https://github.com/kimcheolhui9846/token-context-optimizer/pull/173), 기준 커밋 `792c5380f3efb4c5fbae38e6f8bafac3e4f3fd5a`. 입력·예산별로 같은 접두사를 다시 계산하던 기준 구현에 입력별 토큰 수 배열을 도입했다. 배열은 빈 접두사부터 시작한다. 완전한 줄을 LF로 이어서 직접 추정하고 기존 순서로 예산을 처음 넘는 줄을 찾는다. 입력 분류와 실제 제품 요약 호출은 예산마다 수행한다.

## 기준 결과 전수 대조

부모의 Git 객체에서 원래 기준 함수와 입력·예산 생성기를 가져왔다. 같은 입력 객체·경로·예산으로 두 기준의 요약문, 출처 범위, 토큰 수, 대체 사유, 순서가 있는 경고를 직접 비교했다. 정규 테스트에서는 별도로 새 기준을 제품 결과와 대조했다.

- 238개 입력, 50,346개 비교에서 차이 0개. 빈 줄 배열 입력 5개, CRLF 포함 입력 119개였다. `NaN`, 양·음의 무한대, -1, 0.5, 20.5는 각각 238개 입력에서 모두 확인했다.
- 기준 구현 내부의 토큰 추정 호출은 797,557회에서 5,750회로 99.28% 감소했다. 새 횟수에는 5,512개 줄 접두사와 입력별 빈 접두사 238개가 포함된다. 계수용 실행과 시간 측정은 분리했다.
- 임시 복사본에서 빈 접두사 다음의 토큰 수를 고의로 손상시키자 입력 4, 예산 1에서 최초 불일치를 검출했다. 전수 대조는 독립 진단에만 여유 시간을 두었고 저장소 테스트의 제한은 60초다.
- 동결 원본 파일 SHA-256 `7d147e711efb42205a8969a7c84fe92ed708db72ea9e590276d86aa19260319f`, 원래 기준 함수 SHA-256 `1b167f81948a172e6921757935ded6d225b680f02cbe6ff9bd3a289ef14dd78e`. 원래 코퍼스 및 예산 생성부도 새 파일과 일치한다.

## 재현과 검토

`node node_modules/vitest/vitest.mjs run tests/summarizer-selection.test.ts --maxWorkers=1`로 단독 실행한다. 전체는 파일 인수를 빼고 `--maxWorkers=4`로 실행한다. PowerShell에서 `$env:TCO_SUMMARIZER_TIMING='1'`을 설정하면 기준 구현·제품·기타 단계별 시간을 볼 수 있다. 기본 모드는 이 변수를 설정하지 않은 새 셸에서 실행한다.

- npm 빌드·타입 검사·MCP 스모크·플러그인 검사·벤치마크 통과. 전체 기본 테스트 4,640개 통과·0개 실패·5개 건너뜀.
