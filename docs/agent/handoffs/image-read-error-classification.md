# 이미지 색인의 Windows 오류 분류 시험

- Tier C. 기준은 `main@0fb3053`이다. #162에서 실패한 시험과 제품 읽기 모듈의 Git blob이 이 기준과 같음을 확인했다.
- 기존 시험은 모의 읽기 콜백 안에서 파일 시각이 달라졌다고 단언했다. #148의 Windows 진단에서는 이 전제가 성립하지 않았다. 콜백에서 발생한 일반 예외를 읽기 계층이 `read_failure`로 변환해 어떤 단언이 실패했는지 외부 로그에 남지 않았다. #162에는 최종 오류 코드만 기록됐다.
- 마지막 시험을 두 사례로 바꿨다. 두 사례 모두 실제 파일 내용은 유지한다. 첫 사례는 읽기 후 변경 시각만 다른 스냅샷에 `source_changed`가 발생하는지, 두 번째는 읽기 자체의 일반 예외에 `read_failure`가 발생하는지 검사한다. 두 사례 모두 지정한 모의 함수 호출과 저장 건수 0을 검사한다.
- 기존 세 통합 시험, 제품 실행 코드, 번들, 의존성은 기준과 일치한다. [사용자 문서](../../image-artifacts.md)에 실제 파일 시험과 고정 입력 시험이 확인하는 범위를 구분했다.
- RED는 기존 Windows 단독·전체 실행 실패 기록, 그리고 새 시험의 두 기댓값을 맞바꿨을 때 발생한 2개 실패다. 기댓값 복구 후 두 사례를 새 프로세스에서 20회씩 실행해 40/40 통과했다. 관련 회귀는 113개 통과·3개 건너뜀이다.
- Claude Code `claude-opus-5-5` 계획·마일스톤 PASS, blocker/major 0. 첫 마일스톤 시도는 허용된 검증 명령에 다른 셸 명령을 덧붙여 차단됐다. 재검토에서 정확한 명령을 실행해 관련 시험과 기존 세 사례 보존을 확인했다. GPT-6.2 Sol이 시험을, Claude Code `claude-sonnet-5-5`가 문서 초안을 담당했다.
- 타입 검사의 scripts 단계는 최초 빌드 전 `dist`가 없어 실패했고, 빌드 뒤 전체 타입 검사가 통과했다. 추가 유료 호출을 승인받지 않아 별도 Argon 검토는 생략했다.
- 저장소 게이트에서 빌드, 제품 시험 4,640개 통과·5개 건너뜀, 타입 검사, MCP 스모크, 플러그인 검증, 벤치마크가 모두 통과했다. 별도 설치는 수행하지 않았다.
