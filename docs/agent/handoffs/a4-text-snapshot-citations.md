# A4 · 편집한 파일의 현재 값을 인용하는 방법

Tier C. 기준 커밋 `976c403d`. [처음 조회와 복구](../../../README.md#first-session-and-recovery) 및 [설치되는 스킬](../../../skills/optimize-context/SKILL.md)의 압축 후 근거 확인 지침을 보완한다.

## 사용자가 확인할 수 있는 결과

- 같은 경로의 2행을 `Bluebird shipped.`에서 `Bluebird pending.`으로 편집하면, 기존 ID의 인용과 행·바이트 위치는 색인 당시 바이트에 속한다.
- 현재 값을 인용할 때는 허가된 원본을 다시 읽거나 같은 경로를 재색인한다. 재색인 경로에서는 전체 SHA-256을 대조하고 반환된 ID로 다시 조회한다.
- 서버 재시작 직후에는 두 ID 모두 조회할 수 없다. 재색인으로 복구되는 내용은 그 시점에 읽을 수 있는 원본에 달려 있다. 원본을 확인할 수 없으면 저장된 인용의 시점과 현재 값의 미확인 상태를 함께 밝힌다.

## 검증 근거

- 기준 버전은 문서 점검 6개 중 1개를 충족했다. 그 버전의 실제 서버에서 편집 전후의 동작을 먼저 재현했다. 변경 후 문서 점검 6개를 충족했다.
- `tests/p06-text-contract-audit.test.ts`의 T1-4는 실제 STDIO 서버에서 변경 전후의 인용, 디스크 바이트의 SHA-256, 행과 바이트 범위, 재시작, 원본 삭제, 한글 행 삽입 전후의 두 ID 위치를 확인한다. T5-2는 요약을 허용하는 별도 입력에서 편집 이후에도 기존 ID의 요약과 해시가 색인 당시 내용과 일치함을 확인한다.
- 격리 설치본에서 해당 파일의 21개 테스트와 `verify:installed`를 통과했다. 별도 STDIO 재현에서 한글 행을 앞에 추가하자 재색인한 인용 위치가 2행에서 3행으로, UTF-8 시작 오프셋이 17에서 29로 바뀌었다.
- 설치본의 스킬과 번들이 작업 사본과 바이트 단위로 일치했다. 검증 전후 기존 호스트 설치·플러그인 캐시·마켓플레이스의 지문이 같았다.
